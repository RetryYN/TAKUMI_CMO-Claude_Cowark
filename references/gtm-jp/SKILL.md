# GTM 操作スキル（ブラウザ操作・安全境界つき）

GTM は Web UI なので Claude in Chrome で操作できる。**指標を読むだけでなく、指標を定義する側に回れる**のがこのスキルの価値。
ただし GTM の公開は**サイト全体の全訪問者に即時配信**される。安全境界を先に読むこと。

## この画面でできること・できないこと（安全境界の一覧）

| 操作 | 可否 | 根拠・条件 |
|---|---|---|
| コンテナ・タグ・トリガー・変数の**閲覧と棚卸し** | ✅ 自律可 | 読み取り専用。ゲート対象外 |
| コンテナの **JSON エクスポート** | ✅ 自律可（推奨） | 読み取り。**Step E（変更前記録）の証跡そのもの**。編集前に必ず取る |
| **ワークスペース内**でのタグ/トリガー/変数の追加・編集 | ⚠️ ゲート下で可 | 公開しなければ本番に出ない。`takumi-start` 経由・変更前記録の後 |
| **プレビュー（Tag Assistant）での検証** | ✅ 自律可 | 自分のブラウザだけに適用。本番に影響しない。**公開前に必ず通す** |
| **公開（バージョンの公開）** | 🚫 **不可逆送出扱い** | pre-send-verifier の監査 + **人間の明示承認**が必須。手順は下記「公開の関所」 |
| **カスタムHTMLタグ / カスタムJavaScript変数**の新規作成・編集 | 🚫 **AI自律禁止** | 任意の JS を本番の全訪問者に注入できる。Magecart 型のカード情報窃取が実際にこの経路で起きている。**下書きの提示までにとどめ、作成・保存は人間が行う** |
| タグ・トリガー・変数の**削除** | 🚫 承認必須 | 削除ではなく**一時停止（Pause）**を提案する。停止なら数秒で戻せるが、削除は作り直しになる |
| コンテナ・アカウントの削除 | 🚫 禁止 | 復旧不能 |
| ユーザー権限の変更・招待 | 🚫 禁止 | 公開権限の付与はセキュリティ事案 |
| サーバーサイドコンテナの作成・課金設定 | 🚫 禁止 | 課金が発生する（ゼロ課金ゲート対象） |

## 公開の関所（この順を飛ばさない）

GTM 側の機能が A〜K ワークフローとそのまま対応する。**この対応を使えば新しいゲート機構は要らない**。

| GTM の機能 | ワークフロー上の役割 |
|---|---|
| コンテナの JSON エクスポート | **Step E: 変更前記録**。`knowledge/sites/<site>/gtm/<日付>-container.json` に保存 |
| ワークスペース | 作業の隔離。他人の変更と混ざらない |
| プレビュー / Tag Assistant | **Step I: 検証**の前倒し。発火するタグを目視で確認 |
| バージョンの公開 | **Step H: 承認**の対象。ここが唯一の不可逆点 |
| 以前のバージョンへの復帰 | 事故時のロールバック。**過去バージョンは無制限に保存され、いつでも再公開できる** |

**手順:**

1. **現在の公開バージョン番号を控える**（ロールバック先。「v47」ではなく何をしたか分かる名前で控える）
2. **コンテナを JSON エクスポート**して knowledge に保存（Step E）
3. ワークスペースで変更を作る（カスタムHTMLは作らない — 上表）
4. **プレビューで検証**。発火すべきタグが発火し、発火すべきでないページで発火しないことを両方確認する。確認できた画面の証跡（スクリーンショット）を残す
5. `memory/.workflow/bulk_send` を立て、**pre-send-verifier に監査させる**（観点: 誤発火の範囲・PII混入・同意設定との整合・ロールバック手段の有無）
6. 監査 VERDICT を添えて**ユーザーに承認を求める**。承認なしに公開しない
7. 公開。バージョン名は「何をしたか」が分かる説明にする
8. **outcome-verifier に着弾を検証させる**（GA4 のリアルタイムでイベントが実際に届いているか）。届いていなければ即ロールバックを提案する
9. プレビューモードを終了する（つけっぱなしは混乱のもと）

## 構造的にカスタムHTMLを禁止する（ユーザーに提案する設定）

「AI に触らせない」を規約ではなくプラットフォーム側で強制できる。サイトの GTM スニペットより前に置く:

```js
window.dataLayer = window.dataLayer || [];
window.dataLayer.push({ 'gtm.blocklist': ['customScripts'] });
```

### 何がブロックされるか（一次情報で確認済み）

`customScripts` クラスは「ユーザーが提供する JavaScript コードの実行が可能」な機能を指し、対象は次の2つ:

- **カスタムHTMLタグ**（ID: `html`）
- **カスタムJavaScript変数**（ID: `jsm`）

> **DOM要素変数は `customScripts` の対象ではない**（`google` クラスに分類される）。
> 「DOM直接アクセスも止まる」は誤り。止めたいなら別途 ID を指定すること。

クラスは他に `google`（Google ホスト済みスクリプト）/ `customPixels` / `nonGoogleScripts` / `nonGooglePixels` /
`nonGoogleIframes` / `sandboxedScripts`（カスタムテンプレート用）がある。

### 適用ルール（一次情報で確認済み。ここを外すと事故る）

- **blocklist は allowlist に優先する。** 「allowlist で特定タグをブロック、blocklist で特定タグを許可」という逆方向はできない
- **クラス間に依存関係がある。** 例: `nonGooglePixels` をブロックすると `nonGoogleScripts` も自動的にブロックされる
- 両リストとも **Array 型・値は String 型**で、**タグが発火する前に**データレイヤーへ push される必要がある

### 併用の罠（テンプレート移行を勧めるなら必ずセットで伝える）

Google 公式は「セキュリティ管理の改善のため、**カスタムテンプレートとテンプレートポリシーへの移行**」を推奨している。
ただし**カスタムテンプレートを使っている状態で任意のタグクラスを blocklist に入れると、
`sandboxedScripts` を明示的に allowlist へ追加しないとテンプレートが動かなくなる**。

つまり「customScripts を封じる」と「カスタムテンプレートへ移行する」は**同時に成立させるのに1手余分に要る**。
移行を提案するなら、この1手を必ず添えること。

### 副作用と伝え方

この設定を入れると、カスタムHTMLに依存している既存タグは動かなくなる。
先にエクスポートした JSON でカスタムHTMLタグの有無を数え、**あるなら移行計画とセットで**提案する。

CSP を運用しているサイトでは、GTM のカスタムHTML/カスタムJSは `unsafe-eval` 相当を要求する。
blocklist を入れることは **CSP を厳しく保てる**ことでもある。この文脈で DevOps に説明すると通りやすい。

## 独自指標を作る（このスキルの本題）

「読了率を測りたい」のような要望を、**GTM の型に落とす**。

| 測りたいこと | トリガー | GA4 へ送るイベント |
|---|---|---|
| 記事の読了 | スクロール深度（縦・75%/90%） | `scroll_depth`（パラメータ: `percent`, `page_path`） |
| 動画の視聴到達 | YouTube 動画（開始/25/50/75/完了） | `video_progress` |
| 資料DL・外部遷移 | クリック（リンクのクリック・ファイル拡張子） | `file_download` / `outbound_click` |
| フォーム到達と離脱 | 要素の表示 / フォーム送信 | `form_view` / `form_submit` |
| 滞在の質 | タイマー（15秒以上滞在） | `engaged_view` |

原則:

- **イベント名は GA4 の推奨イベント名に寄せる**（自動収集・推奨と衝突しない範囲で）。独自名は snake_case
- **1指標 = 1イベント**。パラメータで切る。イベント名を増やしすぎると GA4 側の上限とレポートの見通しを損なう
- 作った指標は**必ず KPIツリーのノードに紐づける**。紐づかない指標は作らない（測るだけで使わないデータは負債）
- 送るパラメータに**個人情報を入れない**（→ `ga4-jp` の PII 節。違反すると GA4 プロパティのデータが全削除されうる）

## 同意管理（日本）

GTM 単体に同意取得の機能はない。**Consent Mode を機能させるには GTM 対応の CMP（同意管理ツール）が別途必要**。

- 日本の改正個人情報保護法（2022）は Cookie・オンライン識別子を「**個人関連情報**」と位置づける。EU のような事前同意の一律義務はないが、**第三者提供で個人の特定につながりうる場合は事前の通知または同意が必要**
- 2026-06-15 以降、GA4 と Google 広告を連携している構成では Google シグナルによるデータ制御が広告側で効かなくなり、**Consent Mode が単一の制御点**になる
- **同意設定の変更は法務判断**。AI は現状を読んで報告し、変更案を提示するところまで。**設定の変更・公開は人間が行う**

## よくある事故と回避

| 事故 | 回避 |
|---|---|
| プレビューで確認せず公開 → 全ページで誤発火 | 手順4を飛ばさない。**「テストせずに公開しない」が GTM の第一原則** |
| タグを削除して戻せなくなった | 削除ではなく**一時停止**。停止なら即復帰できる |
| ロールバック先が分からない | 手順1で現在の公開バージョンを控える。バージョン名は「v47」ではなく内容で |
| プレビューをつけっぱなし | 検証後に終了する |
| PII をパラメータに載せた | メールアドレス・氏名・電話番号・ユーザーIDに使える生の値を送らない（→ `ga4-jp`） |
