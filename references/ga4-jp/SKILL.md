# GA4 操作スキル（ブラウザ操作・安全境界つき）

## この画面でできること・できないこと（安全境界の一覧）

| 操作 | 可否 | 根拠・条件 |
|---|---|---|
| レポート・探索の**閲覧とデータ取得** | ✅ 自律可 | 読み取り専用 |
| **探索（Explorations）の新規作成** | ✅ 自律可 | 既存の探索を**上書きしない**こと。名前に `-takumi` を付けて自分の作ったものと分かるようにする |
| **カスタムチャネルグループの作成** | ⚠️ ゲート下で可 | 過去データに遡って再処理される（既定チャネルグループは変更されない）。作成後にレポートの見え方が変わるのでユーザーに事前説明 |
| **キーイベント（コンバージョン）の設定** | ⚠️ ゲート下で可 | 追加は可。**既存キーイベントの解除は禁止**（レポートと連携先に波及） |
| カスタムディメンション/指標の**追加** | ⚠️ ゲート下で可 | 上限あり（追加のみ・削除は慎重に）。追加前に既存を棚卸しする |
| **データ保持設定の変更** | 🚫 **禁止** | **期限切れで消えたデータは二度と戻らない**。設定を短くすると過去データが失われる。変更提案は人間へ |
| **データフィルター（内部トラフィック除外等）の有効化** | 🚫 承認必須 | 誤設定すると本番の計測が丸ごと欠落する。テストモードで検証してから人間が有効化 |
| プロパティ・データストリームの削除 | 🚫 禁止 | 復旧不能 |
| ユーザー権限の変更・招待 | 🚫 禁止 | |
| Google 広告アカウントとのリンク | 🚫 禁止 | 有料出稿の導線（ゼロ広告費に反する） |
| **PII を含むデータの送信** | 🚫 **絶対禁止** | 下記 |

## PII（個人を特定できる情報）— ここが一番重い

**Google はポリシー違反を検知した場合、そのプロパティのデータを全削除しうる。** アカウント停止の対象でもある。

- 送ってはいけない: **氏名・メールアドレス・電話番号・住所・公的ID番号**。URL のクエリ文字列に混入するケースが最多（`?email=...` がページパスとして記録される）
- 健康・財務状況・政治信条・宗教などの**センシティブ情報**も収集禁止
- ログインユーザーを追いたいときは **User-ID 機能**を使い、**個人を特定できない自前の一意ID**を渡す（メールアドレスやそのハッシュを ID にしない）
- **実装前に必ず確認する**: フォーム送信後の URL、サンクスページのクエリ、GTM で送るパラメータ。
  匠が計測基盤を作るときは、`gtm-jp` のプレビュー段階で**送信されるパラメータの中身を目視で確認**すること

## AI 経由の流入を可視化する（このスキルの本題）

### 前提の変化（2026年）

- GA4 は **2026-05-13 に「AI Assistant」チャネルを既定チャネルグループへ追加**、2026-06-07 頃に広く提供された。ChatGPT・Gemini・Claude 等が自動で分類される
- **ただし Perplexity は既定チャネルに入っておらず、Referral に落ちる**（最も意図の強い流入源のひとつ）
- **AI 参照セッションの 35〜70% は referrer が付かず Direct に落ちる**

### だから作るもの: カスタムチャネルグループ

管理 → データの表示 → チャネルグループ で新規作成し、チャネル「AI Referrals」を作って:

- 条件: **参照元（Source）が正規表現に一致**
- 正規表現: `chatgpt|openai|perplexity|claude|anthropic|gemini|copilot|edgeservices`
- **ルールの順序を Referral より上に置く**。これが最頻の失敗原因 — 正規表現が正しくても、Referral に先に当たると分類されない
- `www.perplexity.ai` のようにサブドメイン付きで来るケースがあるため、`.*` で挟むか部分一致にする
- **四半期ごとに見直す**（AIアシスタントは新ドメイン・新製品を継続的に追加する）

### 指標の置き方（重要な設計判断）

**絶対値を KPI にしない。** Direct 落ちが 35〜70% ある以上、AI 流入は構造的に過小評価される。
「AI経由セッション 120件」を目標にすると、計測の穴を追いかけることになる。

KPIツリーには次を置く:

| ノード | 指標 | 種別 |
|---|---|---|
| AI経由の到達 | **全流入に占める AI経由セッションの構成比**（%） | 先行 |
| AI経由の質 | AI経由セッションのキーイベント率 | 先行 |
| （比較用） | オーガニック検索セッションのキーイベント率 | 先行 |

AI 経由は**転換率が高い**傾向が各所で報告されている（通常オーガニックの数倍という分析がある）。
ただしこれは他社の観測値であって自社の数字ではない。**自社の GA4 で比較して初めて根拠になる。**

## 週次で取るもの（`takumi.db` へ積む）

1. 全セッション / AI経由セッション / オーガニック検索セッション
2. AI経由の構成比（1から算出）
3. AI経由のキーイベント数と率
4. 参照元の内訳（chatgpt / perplexity / gemini / copilot / claude 別）— 新しいドメインが出てきたら正規表現の更新サイン
5. ランディングページ別の AI経由セッション — **どのコンテンツが AI に拾われているか**（`takumi-campaign` のモダリティ設計へ返す）

## よくある事故と回避

| 事故 | 回避 |
|---|---|
| カスタムチャネルを作ったのに AI が Referral のまま | **ルールの順序**を Referral より上に。正規表現より順序を先に疑う |
| 数字が去年と比べられない | データ保持設定は触らない。既定は短い |
| フィルターを有効化したら計測が止まった | まずテストモードで検証。有効化は人間 |
| URL に個人情報が乗っていた | 実装前にサンクスページ・フォーム後のURLを確認。PII は規約違反 |
| AI 流入の絶対値を目標にした | 構成比とトレンドで見る。絶対値は必ず過小評価 |
