# GA4 操作スキル（ブラウザ操作・安全境界つき）

## この画面でできること・できないこと（安全境界の一覧）

| 操作 | 可否 | 根拠・条件 |
|---|---|---|
| レポート・探索の**閲覧とデータ取得** | ✅ 自律可 | 読み取り専用 |
| **探索（Explorations）の新規作成** | ✅ 自律可 | 既存の探索を**上書きしない**こと。名前に `-takumi` を付けて自分の作ったものと分かるようにする |
| **カスタムチャネルグループの作成** | ⚠️ ゲート下で可 | 過去データに遡って再処理される（既定チャネルグループは変更されない）。作成後にレポートの見え方が変わるのでユーザーに事前説明 |
| **キーイベント（コンバージョン）の設定** | ⚠️ ゲート下で可 | 追加は可。**既存キーイベントの解除は禁止**（レポートと連携先に波及） |
| カスタムディメンション/指標の**追加** | ⚠️ ゲート下で可 | 上限あり（追加のみ・削除は慎重に）。追加前に既存を棚卸しする |
| **データ保持設定の変更** | 🚫 **禁止** | **期限切れで消えたデータは二度と戻らない**。設定を短くすると過去データが失われる。変更提案は人間へ |
| **データフィルター（内部トラフィック除外等）の有効化** | 🚫 承認必須 | 誤設定すると本番の計測が丸ごと欠落する。テストモードで検証してから人間が有効化 |
| プロパティ・データストリームの削除 | 🚫 禁止 | 復旧不能 |
| ユーザー権限の変更・招待 | 🚫 禁止 | |
| Google 広告アカウントとのリンク | 🚫 禁止 | 有料出稿の導線（ゼロ広告費に反する） |
| **PII を含むデータの送信** | 🚫 **絶対禁止** | 下記 |

## PII（個人を特定できる情報）— ここが一番重い

### 一次情報で確認済み（Google 公式ヘルプ）

- **Google 契約上の PII の定義**: 「**それ単体で個人の特定、個人への接触、個人の所在地の特定を可能にするもの**」
- **PII に含まれる例**: メールアドレス / 住所 / 電話番号 / **高精度位置情報（GPS座標）** / フルネーム / ユーザー名
- **PII に含まれない例**: **仮名化 Cookie ID / 仮名化広告ID / IPアドレス**、その他の仮名化されたエンドユーザー識別子
  （※「IPアドレスは PII ではない」は Google 契約上の定義の話。日本の個人情報保護法や GDPR での扱いとは別問題なので混同しない。
  なお日本法上、**Cookie 等の端末識別子は「個人情報」ではなく「個人関連情報」** — 日本法の水準は `gtm-jp`「同意管理（日本）」を正とする）
- **URL 経由の混入**: 「URL やタイトルから個人情報が誤って送信されないように、**URL パスとパラメータのいずれにも**個人情報が含まれていないことを確認してください」
- **回避手段（公式が挙げるもの）**: データ除去機能（**メールアドレスの削除・指定クエリパラメータの削除**）／ location・title の書き換え／User-ID 使用時のベストプラクティス／カスタムディメンション使用時の注意
- **デバイス識別子**: 「特定のデバイスを識別するための固定データ（リセットできない端末固有IDなど）」も列挙されている

### 一次情報で確認**できなかった**もの（扱いを下げること）

- 「**違反するとプロパティのデータが全削除される**」— 上記2ページ（PII回避のベストプラクティス／契約とポリシーにおける PII）**どちらにも措置の記載がない**。
  二次情報（解説記事）由来。**「規約違反である」は公式に確認できるが、措置の程度は未確認**として扱う。
  ただし**対策の強度を下げる理由にはならない** — 送らないのが唯一の正解であることは変わらない
- 「健康・財務状況・政治信条・宗教などの**センシティブ情報も収集禁止**」— 上記2ページには記載がない。
  Google アナリティクス利用規約・ポリシー側にある可能性が高いが**未確認**。該当業種を扱うときは**規約本文を当たること**

### 運用

- ログインユーザーを追いたいときは **User-ID 機能**を使い、**個人を特定できない自前の一意ID**を渡す（メールアドレスやそのハッシュを ID にしない）
- **実装前に必ず確認する**: フォーム送信後の URL、サンクスページのクエリ、GTM で送るパラメータ。
  匠が計測基盤を作るときは、`gtm-jp` のプレビュー段階で**送信されるパラメータの中身を目視で確認**すること
- データ除去機能（クエリパラメータ除外）に `email` `mail` `tel` `phone` `name` `uid` `token` 等を登録するのは公式が挙げる手段。**保険として必ず入れる**

## AI 経由の流入を可視化する（このスキルの本題）

### 前提（一次情報で確認できた範囲）

**公式ヘルプの既定チャネルグループ一覧（18種）に「AI Assistant」は含まれていない。**
一覧はアフィリエイト / オーディオ / クロスネットワーク / ノーリファラー / ディスプレイ / メール / モバイルのプッシュ通知 /
オーガニック検索 / オーガニック ショッピング / オーガニック ソーシャル / オーガニック動画 / その他（有料）/
有料検索 / 有料ショッピング / 有料ソーシャル / 有料動画 / 参照 / SMS。

公式定義（そのまま使える）:
- **オーガニック ソーシャル**: 参照元がソーシャルサイトの正規表現リストに一致、またはメディアが該当
- **参照（Referral）**: メディアが `referral` / `app` / `link` のいずれか
- **ノーリファラー（Direct 相当）**: 参照元が完全一致で `(direct)` かつメディアが `(not set)` または `(none)`

> **未確認**: 「2026-05-13 に AI Assistant チャネルが既定へ追加された」は複数の二次情報が報じているが、
> **公式ヘルプの既定チャネル一覧では確認できなかった**（ヘルプの更新遅れ・地域差の可能性はある）。
> したがって**既定チャネルに頼らず、カスタムチャネルグループを前提に設計する**。
> 実機のプロパティで「AI Assistant」が実在するかを最初に確認し、あればカスタム側の役割を縮小してよい。

> **未確認**: 「AI 参照セッションの 35〜70% は referrer が付かず Direct に落ちる」も二次情報のみで、一次情報は確認できていない。
> ただし**アプリ内ブラウザ・DM 転送・コピペ共有で referrer が落ちること自体は仕組み上そうなる**ため、
> **「AI 流入は必ず過小評価される」という設計判断は数値に依存せず成立する**。数値そのものを根拠として引用しないこと。

### 作るもの: カスタムチャネルグループ

管理 → データの表示 → チャネルグループ で新規作成し、チャネル「AI Referrals」を作って:

- 条件: **参照元（Source）が正規表現に一致**（既定の「参照」定義がメディア基準なのに対し、こちらは参照元基準で捕まえる）
- 正規表現: `chatgpt|openai|perplexity|claude|anthropic|gemini|copilot|edgeservices`
- **ルールの順序を Referral より上に置く**。これが最頻の失敗原因 — 正規表現が正しくても、Referral に先に当たると分類されない
- `www.perplexity.ai` のようにサブドメイン付きで来るケースがあるため、`.*` で挟むか部分一致にする
- **四半期ごとに見直す**（AIアシスタントは新ドメイン・新製品を継続的に追加する）

### 指標の置き方（重要な設計判断）

**絶対値を KPI にしない。** Direct 落ちが 35〜70% ある以上、AI 流入は構造的に過小評価される。
「AI経由セッション 120件」を目標にすると、計測の穴を追いかけることになる。

KPIツリーには次を置く:

| ノード | 指標 | 種別 |
|---|---|---|
| AI経由の到達 | **全流入に占める AI経由セッションの構成比**（%） | 先行 |
| AI経由の質 | AI経由セッションのキーイベント率 | 先行 |
| （比較用） | オーガニック検索セッションのキーイベント率 | 先行 |

「AI 経由は転換率が高い」という分析が各所にあるが、**いずれも二次情報で一次情報は確認できていない**。
他社の観測値ですらなく出所の追えない数字も混じる。**引用しないこと。自社の GA4 で比較して初めて根拠になる。**

## 週次で取るもの（`takumi.db` へ積む）

1. 全セッション / AI経由セッション / オーガニック検索セッション
2. AI経由の構成比（1から算出）
3. AI経由のキーイベント数と率
4. 参照元の内訳（chatgpt / perplexity / gemini / copilot / claude 別）— 新しいドメインが出てきたら正規表現の更新サイン
5. ランディングページ別の AI経由セッション — **どのコンテンツが AI に拾われているか**（`takumi-campaign` のモダリティ設計へ返す）

## よくある事故と回避

| 事故 | 回避 |
|---|---|
| カスタムチャネルを作ったのに AI が Referral のまま | **ルールの順序**を Referral より上に。正規表現より順序を先に疑う |
| 数字が去年と比べられない | データ保持設定は触らない。既定は短い |
| フィルターを有効化したら計測が止まった | まずテストモードで検証。有効化は人間 |
| URL に個人情報が乗っていた | 実装前にサンクスページ・フォーム後のURLを確認。PII は規約違反 |
| AI 流入の絶対値を目標にした | 構成比とトレンドで見る。絶対値は必ず過小評価 |
