# メッセージング一貫性の点検（部品）

**発信は放っておくとズレる。** 直近の成果物を並べ、メッセージングハウスの柱に紐づいているかを点検する部品。
四半期に1度、または `/匠計測`・`/匠戦略` から呼ばれる。作法の正本は `skills/messaging-design-jp` §4。

> **スコープ**: アクティブブランドのみ。正本は `knowledge/brands/<slug>/strategy/messaging.md`。
> 無ければ点検できない → **/匠戦略 でメッセージングハウスを先に作る**よう案内して終了する（推測で柱を捏造しない）。

## 手順

1. **正本を読む**: `knowledge/brands/<slug>/strategy/messaging.md`（ポジショニング1文 + 柱1〜3 + 各柱の証拠 + 言わないこと）
2. **直近の発信を集める**（期間は既定で90日。アクティブ区画内から）:
   - 記事: `channels/ownedmedia/`
   - SNS投稿: `channels/*/`（`sns/` 配下の投稿記録）
   - メール配信: `channels/email/`
   - LP・サイト変更: `channels/website/`
3. **1件ずつ、どの柱に紐づくかを判定する**（複数の柱にまたがる場合は主たる1つ）。
   **どの柱にも紐づかないものは「未紐づけ」**とし、**そう判定した理由を1行残す**（あとで柱の見直し材料になる）
4. **4つの数字を出す**:

| 指標 | 出し方 | 判定 |
|---|---|---|
| **ドリフト率** | 未紐づけ件数 ÷ 全件 | **3割超で警告**（柱かオペレーションのどちらかが壊れている） |
| **柱ごとの被覆** | 柱ごとの件数比 | 1つの柱に9割寄っていたら、他は実質存在していない |
| **矛盾** | 別媒体で逆のことを言っている組み合わせ | 1件でもあれば列挙する |
| **語彙のブレ** | 同じものの呼び方が複数ある箇所 | 検索でも別物として扱われる（→ `skills/seo-jp`） |

5. **報告する**: 数字 + 具体例（未紐づけの実物を3件まで引用）+ **2択の提案**
   — 「発信を柱に戻す」か「柱を現実に合わせて更新する」か。**「ズレているが放置」を提案しない**

## 判定の作法

- **母数を必ず書く。** 「未紐づけ 3/12 件（25%）」と書き、「25%」だけを書かない
- **紐づけの判定は主張の骨子で行う。** 語句の一致では判定しない（媒体ごとに表現は変わるのが正常）
- **柱の更新を提案するときは慎重に。** 柱を変えると、それまでの反復の蓄積がゼロに戻る
  （`skills/messaging-design-jp` §5「朝令暮改が最大の敵」）。**単発のズレでは柱を動かさない**
- 発信が少なすぎて判定できない場合は「**件数不足で判定不能**」と書く。少数から比率を出さない

## 接続

- 結果は `knowledge/brands/<slug>/strategy/messaging-audit-<date>.md` に記録
- ドリフト率が高い → `/匠戦略` の再立案フラグとして提示（∞の上り）
- 柱の更新は**顧客の裏付け**が要る → `/匠顧客`（`skills/voc-research-jp`）を先に回す
- ダッシュボード（`/匠計測`）に**ドリフト率を閾値表示**で載せる（達成率ではない＝ガードレール的な扱い）
