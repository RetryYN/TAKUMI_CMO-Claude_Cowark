添付されたコンテンツ/ビジュアルを起点に、メッセージ一致した LP モックアップを生成してください。補足情報: $ARGUMENTS

## 手順

1. **コンテンツの解析**（画像/記事を直接読む）: 起点から以下を抽出して `knowledge/styles/content-<name>.json` に記録
   - コピー: 見出し・サブコピー・CTA文言（一言一句そのまま）
   - ビジュアルトーン: 主要色（可能な限りHEX推定・「目視推定」と明記）・フォントの雰囲気（丸ゴ/角ゴ/明朝・太さ）・写真/イラストの別と被写体
   - 訴求タイプ: ベネフィット型 / 実績型 / 共感型 / オファー型
   - ターゲット推定: 誰向けか（人物・文言から）
2. **メッセージ一致の設計**: コンテンツ→LPの連続性を最優先する
   - LPヒーローの見出しはコンテンツのメインコピーと同一または直接の続きにする（言い換え禁止 — コンテンツから来た人が「同じ話だ」と0.5秒で分かること）
   - コンテンツのCTA文言とLPの主CTA文言を一致させる
   - コンテンツの主要色をLPのアクセント色に採用（skills/web-design の 60-30-10 に配置）
3. **LP構成の組み立て**: skills/web-design/resources/lp-cro.md の標準骨格に、訴求タイプ別の重点を反映
   - 実績型 → 証拠セクションを前倒し / 共感型 → 課題提起を厚く / オファー型 → 条件を明示
   - 本文コピーが必要な箇所は該当ライティングスキル（sales-writing等）を適用。捏造禁止（起点にない実績数値は `[要確認]`）
4. **生成と検証**: design-artisan に委譲（コンテンツ解析JSON・抽出コピー・構成案の絶対パスを渡す）→ design-critic の審査ループ（page-improve 部品（docs/parts/page-improve.md）と同じ、最大2周）→ アーティファクト発行
5. **メッセージ一致チェック**を最後に自己実行: 起点コンテンツとモックアップを並べ、コピー・色・トーンの一致点と意図的な差異を表で報告
6. **法規チェック（必須）**: LP本文の最終稿を skills/ad-compliance-jp/SKILL.md で検査（景表法の優良/有利誤認・薬機法・打消し表示・ステマ表記）。指摘があれば修正してから納品

## 出力

- コンテンツ解析: `knowledge/styles/content-<name>.json`
- モックアップ: `knowledge/mockups/contentlp-<name>-<date>.html` + アーティファクト共有URL
- 一致チェック表つきの簡易レポート（チャット内でよい。フルレポートは求められたら）
- **Claude Design 同期**: 手順の正本は docs/parts/design-sync.md（増分同期・finalize_plan 承認・素材パック規約）。メディア素材入りHTMLは同期を既定ルートとして提案する（2026-07-23 ユーザー決定）

### 動く演出部品（任意）

ヒーローの人物や CTA 横のオブジェクトを動かしたい場合は、docs/media-pipeline.md の「LPの動く人物/オブジェクト」ライン（GB生成→chromakey→アルファWebM→`<video>` 重ね）を使う。演出は本体を侵食しない範囲で。

## 注意

- 添付画像は knowledge/assets/ に保存（implementation.md の画像規範に従う）
- コンテンツ自体をLPに流用する場合は、権利がユーザー側（自ブランド）にあることを確認してから
- 他者のコンテンツを渡された場合は「参考トーン」としてのみ使い、コピーの転用はしない（自ブランドのコンテンツのときだけコピー一致設計を行う）
