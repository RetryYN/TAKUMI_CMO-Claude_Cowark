# 部品: 基礎分析（foundation-analysis）

**タスク型: リサーチ／分析。** 市場・顧客・自社・収益構造を、**意思決定が出る形**で通しで押さえる。
`/リサーチ` の**背骨**であり、`/戦略` の上流インプットになる。

> **前段**: アクティブブランドを確定する（未確定なら /ブランド）。
> 記録は `knowledge/brands/<slug>/knowledge/analysis/` にスコープされる（Brand Isolation Guard 対象）。
>
> **作法の正本はスキル側。着手前に該当スキルを Read する**（相対不達なら Glob）:
> `skills/market-analysis-jp`（環境）／`skills/stp-jp`（誰に）／`skills/business-model-jp`（儲かるか）／
> `skills/customer-analytics-jp`（顧客データ）／`skills/quant-research-jp`（調査の設計と読み）

## なぜこれを通すのか

**マーケティングの失敗の多くは、マーケティングの外で決まっている。**
構造的に儲からないモデルに集客を足せば赤字が速く増え、
現金が回らないモデルで成長を狙えば黒字のまま止まる。
**誰に売るかが決まっていなければ、何を言っても薄まる。**

**「調べもの」の依頼が来たときほど、まずここに合流させる。**
個別の調査（競合1社・キーワード・デザイン）は、この土台の上でしか意味を持たない。

## 実行粒度

| 依頼の型 | やること |
|---|---|
| 「戦略を立てたい」「事業を見直したい」 | **①〜⑤を通しで**（フルセット） |
| 「競合を調べて」「市場を知りたい」 | ①中心（+ 必要なら②） |
| 「誰に売ればいいか」 | ②中心（+ ④） |
| 「儲かるのか」「値付けを決めたい」 | ③中心 |
| 「顧客を分析して」 | ④中心 |
| 「アンケートを取りたい」 | ⑤中心 |

**フルセットは重い。** 依頼の型に合わせて必要な節だけ回してよいが、
**③（儲かるか・現金が回るか）を飛ばした状態で施策の実行に進まない。**

## ① 環境 — 市場・競合・自社（`skills/market-analysis-jp`）

順に当てる。**各段階の出力は「表」ではなく「決めたこと」。**

1. **PEST** → 3年後に効く外部変化を3つ、**日付か時期つきで**（日付の入らない変化は施策にならない）
2. **5フォース** → **参入する/しない**と理由1文
3. **3C** → 顧客・競合・自社の**食い違い（空白）**。重ならないならそれが結論
4. **VRIO** → 4問すべて通った強みを**0〜2個**（0なら「今は無い」と書く）
5. **バリューチェーン** → 集中する工程・捨てる工程
6. **クロスSWOT** → **S×O から着手**。W×T は「やらないことリスト」

**顧客の欄を推測で書いたら「推測」と明記する**（→ `/顧客の声` を先に回す提案）。
**競合はまとめ記事で済ませず実物を見る**（→ `docs/parts/growth-teardown.md`）。

## ② 誰に売るか — STP（`skills/stp-jp`）

1. **S**: 切り口を複数持つ。**「状況」と「用事」の軸を必ず1つ入れる**（属性だけで切らない）
2. **T**: 6基準（規模／**到達可能性**／測定可能性／反応の違い／競合の手薄さ／自社適合）で絞る。
   **ゼロ広告費では「どうやって届くか」を1文で言えないセグメントは狙えない**
3. **P**: ポジショニングマップは**顧客が実際に比較に使っている基準**で軸を取る
   （自社が有利な軸を選ばない・相関する2軸を使わない）

**出力に「狙わないと決めたもの」を2つ以上、理由つきで書く。** 空欄なら絞れていない。

## ③ 儲かるか・現金が回るか（`skills/business-model-jp`）

**ここが従来ワークフローに無かった部分。飛ばさない。**

1. **ビジネスモデル1枚**を埋める（誰が払う／何に／**いつ現金が入るか**／変動費／固定費／収益の型）
2. **損益分岐点**を計算する

```python
from takumi.domain.unit_economics import BreakEven
be = BreakEven(fixed_cost_yen=<固定費>, variable_cost_ratio=<変動費率>)
be.break_even_sales_yen(); be.margin_of_safety_ratio(<現状売上>)
```

**変動費率が1以上なら `ValueError`** — 損益分岐点が存在しない（売るほど赤字）。
**このときやることは集客ではなく、原価・提供方法・価格のどれかを変えること。**

3. **キャッシュフロー（CCC）**を出す

```python
from takumi.domain.unit_economics import CashCycle
cycle = CashCycle(inventory_days=<棚卸>, receivable_days=<売上債権>, payable_days=<仕入債務>)
cycle.ccc_days(); cycle.working_capital_need_yen(daily_sales_yen=<日商>)
```

**CCC が正なら、売上が伸びるほど現金が減る。**
「来月から売上2倍」の計画を立てる前に、**日商 × CCC の運転資金を用意できるか**を確認する。
用意できないなら、**その計画は成功したときに資金が尽きる**。

4. **オーガニックな獲得コスト**を出す（**時間が原価**）

```python
from takumi.domain.unit_economics import OrganicAcquisitionCost
cost = OrganicAcquisitionCost(hours_spent=<時間>, hourly_rate_yen=<時間単価>, customers_acquired=<件数>)
cost.verdict(gross_profit_per_customer_yen=<1件あたり粗利>)
```

**時間単価を0円にしない**（`ValueError`）。0円にすると全施策が「効率的」に見える。
**獲得0件は「判定不能」**であって「コスト0円」でも「効率が良い」でもない。

**ここで出た指標を KPIツリーに載せない**（→ `skills/business-model-jp` §5）。
KPIツリーは「動かすため」の指標で、これは「続けるか・やめるか」の指標。混ぜると
「獲得単価を下げる」が目標になり、**獲得を減らせば達成できてしまう**。

## ④ 顧客データ（`skills/customer-analytics-jp`）

**平均を見ない。分ける。**

- **誰に力を入れるか** → RFM／デシル／ABC（BtoB・低頻度なら RFM を使わない）
- **時期の違い** → コホート（**縦読み**が施策効果を見る実用的な方法）
- **どこで落ちるか** → ファネル（**定義を先に固定**する）
- **なぜ買われたか** → JTBD（**今使っている代替手段**を必ず書く。「何もしない」が最大の競合であることが多い）

**数字で場所を特定し、理由は `/顧客の声` で聞く**（データは「何が起きたか」しか語らない）。
**個人が特定できる情報は取得の時点で落とす**（→ `privacy-auditor`）。

## ⑤ 調査するなら（`skills/quant-research-jp`）

- **判定基準と期間を着手前に固定する**（後から決めると結果に合わせてしまう）
- **n を必ず併記する。** n=100 の「60%」は実際 50〜70% のどこか
- **偏りは n では直らない。** 自社ファンに聞いた結果を市場の意見として書かない
- 「差が確認できなかった」を**「同じ」「効果なし」と書かない**
- 価格は「いくらなら買いますか」と直接聞かない（**小さく売って確かめるのが最も確実**）

## ⑥ 記録して接続する（ここまでやって完了）

1. `knowledge/brands/<slug>/knowledge/analysis/<date>-基礎分析.md` に保存。
   **観測（事実）と推論（そう考えた理由）を節で分ける**
2. 各結論に**出典**を付ける（一次情報／推測の別を明記）
3. `/戦略` へ渡す（勝ち筋・KPIツリー・ロードマップの上流インプットになる）
4. STP の結論は `knowledge/brands/<slug>/strategy/` の
   ポジショニング・`messaging.md` に反映（→ `skills/messaging-design-jp`）
5. **未確認のまま残った前提を一覧にする**（→ `skills/hypothesis-design-jp` の検証待ち行列へ）

## 禁止・注意

- **フレームを埋めて成果物とする**（成果物は意思決定。表ではない）
- **顧客欄を推測で埋めて、推測だと書かない**
- **③を飛ばして施策の実行に進む**（儲からない構造に集客を足す）
- **n の無い数字を書く／他社調査を原典に当たらず引用する**
- **ユニットエコノミクスを KPIツリーのノードにする**
- **分析用に個人情報を持ち込む**
- **分析を止めない**（決めるべきことが決まったら止める → `skills/market-analysis-jp` §7）
