# 部品: 社会文脈 → 人物像（context-to-persona）

**タスク型: リサーチ／分析。** 日本の社会統計から環境を整理し、
**複数条件の交点**で対象を定義し、制約から行動を推論し、心理を状況の言葉で書くまでを1本で回す。

> **作法の正本は `skills/social-insight-jp`。着手前に必ず Read する**（相対不達なら Glob）。
> ここは実行の段取りとシートの型だけを持つ。判断基準と禁止事項は正本側にある。
>
> **前段**: アクティブブランドを確定する（未確定なら /匠設定）。
> 記録は `knowledge/brands/<slug>/knowledge/analysis/` にスコープされる（Brand Isolation Guard 対象）。

## この部品の位置

`docs/parts/foundation-analysis.md` の **①環境 と ②STP の間**に入る。

```
① 環境（market-analysis-jp: PEST/5F/3C/VRIO）
     ↓  市場の構造は分かった。では「そこにいる人」はどう暮らしているのか
★ この部品（social-insight-jp: 社会統計 → 条件の交点 → 制約 → 行動 → 心理）
     ↓  人物像が立った。ではどこを狙い、どこを狙わないのか
② STP（stp-jp: セグメント → ターゲット → ポジショニング）
```

**①だけで②へ飛ぶと、セグメントが属性の切り分けで終わる。**
「30代女性」から先に進めない原因はここにある。

## 実行粒度

| 依頼の型 | やること |
|---|---|
| 「ペルソナを作って」「どんな人が顧客か」 | 1〜6 を通しで |
| 「この層の生活実態を知りたい」 | 1〜4 |
| 「訴求が刺さらない理由を考えたい」 | 3〜5（制約から見る） |
| 「世代論を検証したい」 | 1・3（条件の交点で説明できるか） |

## 1. 構造を取る（統計・読み取りのみ）

`skills/social-insight-jp` §1 の対応表で、**知りたいことに対応する調査**を選ぶ。

| 知りたいこと | 調査 |
|---|---|
| 世帯構造・所得・**生活意識** | 国民生活基礎調査（厚労省） |
| **1日の時間の使い方** | 社会生活基本調査（総務省統計局） |
| 就業形態・共働き | 労働力調査 |
| 支出（品目別・月別） | 家計調査 |
| **メディア接触・SNS利用率** | 情報通信白書／情報通信メディアの利用時間調査（総務省） |
| 人口・年齢・地域 | 国勢調査・人口推計 |

- **入口は e-Stat**（`https://www.e-stat.go.jp/`）
- **定義を確認する**（「世帯」「就業者」の定義は調査ごとに違う）
- **年次を記録する**（統計は更新される。**観測日を必ず書く**）
- **平均値をそのまま使わない** — 年代別・平日休日別・世帯類型別に**分解してから**使う

**`skills/social-insight-jp` §2 に代表的な数値をまとめてあるが、
出所を特定しただけで原文は未取得**（文字化けで直読できず）。
**対外資料に載せる数値は、必ず原典を開いて確認する。**

## 2. 条件の交点を作る（複合条件の整理・ここが本体）

6軸を掛け合わせる。**単一属性で切らない。**

| 軸 | 埋める内容 |
|---|---|
| 世帯・同居者 | 単身／夫婦のみ／未就学児あり／介護あり |
| 就業形態 | 正規／非正規／自営／管理職／交代勤務 |
| **ライフステージの節目** | 入学・転職・引越し・介護開始・退職（→ `skills/demand-timing-jp`） |
| 居住 | 都市/地方・持家/賃貸・**通勤時間** |
| 金銭の余裕感 | 余裕あり／切り詰めている |
| 情報環境 | 主に使う面・時間帯・端末 |

**固定するのは2〜3軸だけ。** 6軸すべて固定すると該当者が数人になる。
**「意思決定が変わる軸」だけを固定し、残りは幅を持たせる。**

**「決定権」を必ず書く**（自分だけ／配偶者と／上司の承認）。
ここを落とすと**説得する相手を間違える**。

## 3. 制約を書き出す（願望より先に）

**時間／注意／金／関係／知識／手続き**の6つ。

- **時間**: まとまった時間はいつ、何分あるか
- **注意**: その時間、他に何をしているか（ながらか）
- **金**: 迷わず出せる額
- **関係**: 誰の合意が要るか
- **知識**: 前提知識をどこまで持っているか
- **手続き**: 面倒だと感じる工程

**時間の制約は訴求で覆せない。** 制約に合わないなら**形式を変える**
（長文→要点／夜のセミナー→録画／30分動画→3分）。

## 4. 行動を推論する（根拠の種別を必ず書く）

```
条件: 〈交点〉
制約: 〈どれが効くか〉
だから起きること: 〈**観測できる形で**。「感度が高い」ではなく「通勤中の10分だけ見て保存する」〉
根拠: 〈統計 / 一次情報 / 推測 の別を明記〉
```

**「推測」と書くことを恐れない。** 推測だと書いてあれば後から確かめられる。
書かなければ、**推測が事実として独り歩きする**。

## 5. 心理を言語化する（状況の言葉で）

**人格ではなく状況を書く。**

- ✗ 「効率重視でコスパにシビア、承認欲求が強い」
- ○ 「**夜9時、子どもを寝かせた後の30分が唯一まとまった時間**。だから**結論が先に無い記事は途中で閉じる**。
  失敗すると次に試す時間が無いので、**『うまくいかなかった例』が書いてあるほうを選ぶ**」

3条件を満たすこと: ①**人格ではなく状況** ②**観測できる行動が入る** ③**理由が制約から出ている**。

**形容詞で人を語らない**（「意識が高い」「保守的」は書き手の評価であって描写ではない）。

**文面に落とすときは `skills/psych-target-jp` の3軸**（不安の核／意思決定スタイル／関係段階）へ渡す。
**心理は不安の解消に使い、増幅に使わない**（session-rules (3)）。

## 6. 反証して記録する（ここまでやって完了）

**1〜5はすべて推論。** 次で裏を取る:

| 確かめ方 | 分かること |
|---|---|
| **`/匠顧客`** | 制約・決定権・**顧客自身の語彙** |
| **GA4 の曜日・時間帯・デバイス** | 「夜9時の30分」が実データと合うか（**最も安く確実**） |
| **GSC の検索クエリ** | 実際に使っている言葉 |
| 問い合わせ・コメント | つまずいている工程（→ `/匠顧客`） |

**実データと合わなければ、人物像のほうを直す。**

記録:

1. `knowledge/brands/<slug>/knowledge/analysis/<date>-人物像-<対象>.md`（型は正本 §8）
2. **観測日と統計の年次を必ず書く**
3. **未確認の前提を一覧にする**（→ `skills/hypothesis-design-jp` の検証待ちへ）
4. **②STP へ渡す**（→ `skills/stp-jp`。この人物像がセグメントの根拠になる）
5. 主張の言語化は `skills/messaging-design-jp`、文面は `skills/psych-target-jp`

## 禁止

- **統計から個人を断定する**（生態学的誤謬。「単独世帯34%」は目の前の人の性質ではない）
- **属性から人格・能力・価値観を決めつける**
- **保護される属性で不利益な推論をする**（国籍・出自・障害・信条・健康状態・性的指向）
- **成果物に「あなたは◯◯タイプ」と書く**（プロファイルは書き手側の内部判断に留める）
- **社会不安を煽る材料に使う**
- **世代論をそのまま使う**（条件の交点で説明できないなら使わない）
- **出典の無い数字を根拠にする**／**原典未確認の数値を対外資料に載せる**
- **推論を反証せずに資料化する**
- **個人が特定できる情報を人物像に混ぜる**（→ `privacy-auditor`）
