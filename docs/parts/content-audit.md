# 部品: コンテンツ監査（content-audit）

**タスク型: 分析／掃き出し。** 既存のコンテンツ資産を棚卸しして4分類し、
**伸ばす／直す／統合する／落とす**を決めて実行に接続する。

> **作法の正本は `skills/content-ops-jp`。着手前に必ず Read する**（相対不達なら Glob）。
>
> **前段**: アクティブブランドを確定する（未確定なら /匠設定）。
> 記録は `knowledge/brands/<slug>/knowledge/analysis/` にスコープされる（Brand Isolation Guard 対象）。
>
> **削除・統合は不可逆。** 実行は `takumi-start` のゲート下 + **人間の承認**を経る。

## 使う場面

- 「記事は増えたのに成果が伸びない」
- 「古い記事をどうするか決めたい」
- 「同じテーマの記事が複数ある」
- 半年〜年1回の定期監査

**新規制作の依頼が来たときも、まずここを確認する**
（→ `skills/content-ops-jp` §0 の3つの問い。**増やす前に、持っているものを直す**）。

## 段取り

### 1. 数字を揃える（読み取りのみ）

各記事について集める（→ `/匠計測`・`skills/search-console-jp`・`skills/ga4-jp`）:

| 項目 | 出所 |
|---|---|
| 表示回数・クリック・掲載順位 | Search Console |
| 流入・滞在・キーイベント | GA4 |
| 公開日・**最終更新日** | CMS |
| 対象クエリ | Search Console |

**GA4 の値は推定値でしきい値により行が消える。** 絶対値ではなく**比率と推移**で読む。

### 2. 鮮度と正しさを見る（数字だけで決めない）

- **情報が古びていないか**（制度・法改正・価格・スペック）
- **事実が変わっていないか**
- **出典と取得日が書かれているか**
- **書き手が明示されているか**（→ `skills/content-ops-jp` §5）

### 3. 4分類する

| 分類 | 条件 | 次にやること |
|---|---|---|
| **伸ばす** | 成果あり・内容も良い | 厚くする／**内部リンクを集める**（ハブ化の候補） |
| **直す** | 成果あり・内容が古い | **最優先でリライト**（→ 4） |
| **統合する** | 成果が弱く・似た記事がある | 1本に寄せる（→ 5） |
| **落とす** | 成果なし・直す価値なし | 統合先が無ければ noindex か削除（→ 5） |

**数字だけで「落とす」を決めない。** 流入が無くても
**営業で使う／信頼の担保になる**記事はある。**用途を確認する。**

### 4. リライトの順番を決める

1. 成果があり、情報が古い（放置は信頼を削る）
2. 表示は多いがクリックされない（タイトル・冒頭）
3. クリックされるが離脱する（中身）
4. あと少しで上位（伸びしろ）

**やること**: 事実と数字の更新（**出典と取得日も**）／結論を前に／**一次情報を1つ足す**／
書き手の明示／内部リンクの張り直し／**更新日の表示**。

**中身を変えずに日付だけ新しくしない。**

### 5. カニバリ・統合・削除

**カニバリの確認は Search Console で**（同じクエリに複数の自社URLが出ていないか）。**推測で判定しない。**

**統合・削除の手順**（不可逆なので順に）:

1. 現状を記録（URL・流入・被リンク・順位）
2. **用途を確認**（営業利用・外部参照）
3. **統合先を決める**（消すのではなく**寄せる**のが第一選択）
4. リダイレクトを設定（**設定できないなら消さない**）
5. 内部リンクを張り替える
6. **段階的にやる**（一度に大量に消さない。影響を測ってから次へ）

**AI は削除を自律実行しない。** 人間の承認を経る。**GSC の削除ツールは使わない。**

### 6. トピッククラスターに整える

**枝が3本たまったテーマから、ハブを作る**（先にハブを作らない）。

- 枝 → ハブへ**必ずリンクを返す**
- ハブ → 主要な枝へリンク
- 枝どうしは**関連するものだけ**
- **アンカーテキストは具体的に**（「こちら」を使わない）

### 7. リパーパスの候補を出す

**「伸ばす」に分類された記事は、別の形で使い切れているか**を確認する
（要点の投稿／図解／短い動画／メール連載／FAQ／プレスリリース）。

**骨子は変えず、形だけ変える。時間差で出す。元記事へ戻す導線を置く。**

### 8. 記録して接続する

1. `knowledge/brands/<slug>/knowledge/analysis/<date>-コンテンツ監査.md` に:
   - 対象範囲と**取得日**
   - 4分類の一覧（各件に**判断理由を1行**）
   - リライト順・統合案・**落とす候補と用途確認の結果**
   - リパーパス候補
2. 実行は **`/匠発信 ▸ takumi-ownedmedia`**（記事）・**`takumi-content`**（画像・動画）へ渡す
3. 公開・更新・削除は `docs/parts/wp-publish.md`（下書き→承認→公開）
4. 工数は `docs/parts/capacity-plan.md` に載せる（**監査は重い。半年〜年1回**）

## 禁止・注意

- **新規制作の前に、既存の確認を飛ばす**
- **中身を変えずに更新日だけ新しくする**
- **カニバリを推測で判定する**（Search Console で確かめる）
- **数字だけで削除を決める**（用途を確認する）
- **一度に大量に削除する**／**リダイレクトを設定せずに消す**
- **AI が自律で削除・統合を実行する**（人間の承認を経る）
- **GSC の削除ツールを使う**（一時的措置にすぎない）
- **枝が無いままハブを作る**（ただの目次になる）
