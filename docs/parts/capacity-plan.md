# 工数配分の計画（部品）

**ゼロ広告費は「金を使わない」だけで、時間は有限。** 7割計画の原則を数字にする部品。
`/戦略`（ロードマップ作成時）・`/キャンペーン`（媒体選定時）・`/レポート`（ダッシュボード）から呼ばれる。

> **スコープ**: アクティブブランドのみ。記録は `knowledge/brands/<slug>/strategy/capacity.md`。

## なぜ要るか

`/キャンペーン` は「媒体を増やすより1つの物語で束ねることを優先」と規定しているが、
**判断材料が無かった**。「これ以上は入らない」が言えないと、計画は必ず消化できない量に膨らむ。

**消化できなかった計画は、失敗ではなく最初から嘘だった計画**であり、
次の計画の信頼も失わせる。

## 手順

### 1. 使える時間を先に置く（施策から積み上げない）

| 項目 | 例 |
|---|---|
| 1週あたりの実働（マーケに使える時間） | 人数 × 時間 |
| **7割を上限とする** | 実働 × 0.7 が**計画に入れてよい量** |
| 残り3割 | 差し込み・修正・危機対応・学習に残す |

**3割を計画で埋めない。** ここを埋めると、差し込みが来た瞬間に全部が遅れる。

### 2. 施策ごとに見積もる（範囲で持つ）

| 施策 | ドライバー（KPIノード） | 見積（時間） | 実績 | 担い手 |
|---|---|---|---|---|

- **範囲で見積もる**（3〜5時間）。1点で見積もると必ず下振れする
- **AI が代行できる部分と人間しかできない部分を分ける**（承認・ログイン・撮影・取材・対外発信）
- **見積もりに「承認待ちの時間」を入れる**（不可逆送出は必ず人間承認を挟む）
- ドライバーが空欄の施策は**そもそも計画に入れない**（→ `skills/kpi-design-jp`）

### 3. 埋まり具合を出す

```
埋まり具合 = 計画に入れた合計時間 ÷ （実働 × 0.7）
```

| 値 | 判定 |
|---|---|
| 〜80% | 余裕あり。1つ足せる |
| 80〜100% | **適正** |
| **100%超** | **入りきらない。足す前に落とす**（何を落とすかを決めてから足す） |

**「頑張れば入る」で 100% を超えない。** 超えた分は必ずどこかで落ちる。

### 4. 実績を戻す

- 完了時に**実績時間を記録する**（見積との差が次回の精度になる）
- 見積が常に下振れするなら、**係数を掛けるのではなく見積の粒度を細かくする**
- 実績は `/レポート` のダッシュボードに反映（**埋まり具合を閾値表示**）

## 落とすときの順序

100% を超えたら、次の順で落とす:

1. **どの柱にも紐づかない発信**（→ `skills/messaging-design-jp`。面を薄くするだけ）
2. **ドライバーが空欄の施策**（動かす指標を言えない）
3. **新媒体の追加**（既存媒体でのモダリティ展開の方が面が濃くなる → `/キャンペーン` 2b）
4. 効果が遅行で、かつ他で代替できるもの

**落とした施策は消さずに「今期は入らなかった」として残す**（次期の候補になる。判断の履歴が残る）。

## 接続

- `/戦略` のロードマップに**見積列**を持たせる（7割計画の実体）
- `/キャンペーン` の媒体選定時に**埋まり具合を先に見る**（増やす前に確認）
- `/レポート` のダッシュボードに**埋まり具合を閾値表示**（達成率ではない＝ガードレール的な扱い）
- 100% 超のまま実行に進もうとしたら**止めて、落とす候補を提示する**
