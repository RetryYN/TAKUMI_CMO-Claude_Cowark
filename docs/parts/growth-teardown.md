# 部品: 伸びているものの分解（growth-teardown）

**タスク型: リサーチ／分析。** 伸びているアカウント・サイトを実際に開いて観測し、
**自社で試せる仮説**に変えるまでを1本の手順にしたもの。

> **作法の正本は `skills/growth-teardown-jp`。着手前に必ず Read する**（相対不達なら Glob）。
> ここは実行の段取りとシートの型だけを持つ。判断基準は正本側にある。
>
> **前段**: アクティブブランドを確定する（未確定なら /ブランド）。記録は
> `knowledge/brands/<slug>/knowledge/teardowns/` にスコープされる（Brand Isolation Guard 対象）。

## 使う場面

- 「伸びてる◯◯を参考にしたい」「あのアカウントはなぜ伸びてるの？」
- 自社メディア・SNS の**型を決める前**の下調べ
- 競合のメディアを分析したいとき（→ /リサーチ から呼ばれる）

## 段取り

### 1. 対象を選ぶ（3〜5件。ここで結果の8割が決まる）

**有名だからで選ばない。** 選定基準は正本 §1。**必ず「伸びていない同業」を1件入れる**
（差分が取れず、生存者バイアスに落ちるため）。

選んだ理由を1行ずつ書き残す。**後から「なぜこれを見たのか」を再現できるようにする。**

### 2. 観測する（読み取りのみ・変更操作なし）

**実物を開く。まとめ記事で代替しない。** ブラウザ操作が要る場合は `takumi-start` のゲート下。
bot 検知・CAPTCHA・レート制限に遭遇したら**即中断して報告**（/リサーチ の共通ルール）。

各対象について、次を**推測を混ぜずに**記録:

| # | 観測項目 | 記録の仕方 |
|---|---|---|
| 1 | 記事・投稿タイトル10本 | **原文のまま。要約しない**（要約すると型が消える） |
| 2 | 連載・カテゴリ・タグの名前 | 一覧をそのまま |
| 3 | 直近5本の公開日 | 日付のまま（→ 更新頻度を出す） |
| 4 | 著者表記 | 実名／肩書き／社員／無記名のどれか |
| 5 | 自社商品への導線の位置 | 本文内／ヘッダ／フッタ／別セクション |
| 6 | コンセプト文 | **そのまま引用**（何のメディアだと名乗っているか） |
| 7 | 商品以外の接点 | アプリ・動画・音声・メール・SNS の一覧 |
| 8 | 運営者自身が出している数字 | プレスリリース・IR・決算資料**のみ**。無ければ「記載なし」 |

**8で二次情報の数字を使わない。** まとめ記事の「月間◯万PV」は、
運営者発表に当たれないなら**書かない**（→ `docs/開発ワークフロー.md` §0b の一次情報規律と同じ）。

### 3. 横断で並べる（1件ずつでは型が出ない）

対象×観測項目の**表**にする。**列で読む**（同じ項目を全対象で見比べる）。

見るのは主に差分:

- **タイトルの型が割れていないか**（検索狙いと記憶狙いは正反対になる）
- **全対象に共通している項目はあるか**（例外の無い共通点は、最も転用しやすい）
- **更新頻度の幅**（自社の工数で入る範囲か）
- **著者の出し方**（何で信じてもらう設計か）

### 4. 仮説に変える（ここまでやって完了）

**観測をそのまま真似しない。** 各案を次の形で書く:

```
観測: 〈どこで・何が見えたか。原文のまま〉
差分: 〈自社と何が違うか〉
推論: 〈なぜ効いていると考えるか。**推論だと明記する**〉
資源: 〈自社の工数で再現できるか〉
仮説: 〈誰が・どんな状況で・だからこうすれば・こう変わるはず〉
外れたと分かる条件: 〈これが起きたら間違いだったと分かる〉
```

- **工数の裏取りは `docs/parts/capacity-plan.md`**（更新頻度と連載は、続けられなければ逆効果）
- **仮説の型は `skills/hypothesis-design-jp`**。反証条件の無い案は出さない
- **優先順は「大きさ ÷ 検証コスト」**

### 5. 記録して接続する（メモで終わらせない）

1. `knowledge/brands/<slug>/knowledge/teardowns/<date>-<対象群>.md` に保存。
   **観測**と**推論**を**別の節**に分ける（混ぜると後から検証できない）
2. **観測日を必ず書く**（サイトは改装される。日付の無い観測は使えない）
3. 採用した仮説は `knowledge/brands/<slug>/hypotheses/backlog.md` へ
4. コンテンツの型に落とすなら **/コンテンツ・/オウンドメディア**（`skills/breakout-content-jp` と接続）
5. 媒体運用の型なら **/SNS運用**、メディア全体の設計なら **/戦略**

## 禁止

- **文章・構成・デザインの複製**（著作権侵害。型を学ぶことと複製は別）
- **競合記事の書き換えによる自社記事の作成**
- **出典の無い数字の引用**（運営者発表に当たれないものは書かない）
- **非公開情報の推測を事実のように書く**（売上・人数・費用）
- **観測と推論を混ぜて書く**
- **ログインが必要な領域への侵入・規約に反する自動収集**（読み取りは公開範囲のみ）
