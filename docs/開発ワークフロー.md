# 開発ワークフロー（正本）

TAKUMI-CMO の改修・拡張はこの規約に従う。目的は **回帰ゼロで無双マーケティングエンジンを育てる**こと。
Cowork の実行仕様は [cowork-runtime.md](cowork-runtime.md)、ドメインの言葉は [domain-model.md](domain-model.md) が正本。

## 0. 原則

1. **技術負債を作らない** — 中途半端なリネーム・孤児参照・スタブ・stale docs を残さない。不変条件は機械（lint/テスト）に落とす。
2. **日本語を原則とする（コードを除く）** — ドキュメント・手順書・コミットメッセージ・PR・報告は日本語。コード（識別子）は英語でよいが、集約・値オブジェクトの命名は [domain-model.md](domain-model.md) のユビキタス言語と1対1で対応させる。
3. **Cowork 前提** — 安全ゲートが機械強制されるのは cloud セッションのみ。設計・検証は常に cloud 実機を前提に置く。

## 1. 原子的ブランチ & マージ戦略（回帰防止）

- `main` は常に緑（CI 全通過）。**`main` へ直接コミットしない。**
- 作業単位（フェーズ／独立した1つの変更）ごとに feature ブランチを切る: `phase/<名>` または `fix/<名>`（ブランチ名は ASCII）。
- ブランチを push → **PR を作成**（`pull_request` トリガで CI が回る）→ **CI 全緑を確認** → `main` へマージ（`gh pr merge --merge`）。
- 1 PR = 1 つの意味的にまとまった変更（原子的）。lint / テスト / test-hooks / shellcheck が赤いまま PR をマージしない。
- マージ後に feature ブランチは削除。次フェーズは `main` から新ブランチ。

## 2. TDD（テストファースト）

**テストを先に書き、赤を確認してから実装し、緑にする。**

- **ドメインコード**（`takumi/` Python パッケージ）: `tests/` に unittest（stdlib・依存追加なし）を先に書く → `python3 -m unittest discover -s tests` で red → 実装 → green。
- **hook（bash）**: 新ゲートは `scripts/test-hooks.sh` に「denyされるべき入力」「素通しすべき入力」のケースを**先に**追加 → red → hook 実装 → `bash scripts/test-hooks.sh` で ALL PASS。
- **Cowork 統合**（hook 配線・コマンド経路・エージェント起動・ブランド分離など機械テスト不能な項目）: 実行可能な仕様＝**検証項目（V番号）を先に** `procedures/takumi-verify.md` と `templates/verify-task.yaml` に追加してから機能を作る。これが Tier 2 の TDD。

## 3. オブジェクト型 DDD

- ドメインを**集約（Aggregate）・エンティティ・値オブジェクト**でモデル化する（[domain-model.md](domain-model.md)）。中心は **Brand 集約**（マルチブランドの分離単位＝`knowledge/brands/<slug>/`）。
- **ランタイム（Cowork が読むもの）とドメインモデル（dev-side コード）を分ける**:
  - ランタイム = markdown（commands/procedures）+ bash（hooks）+ templates。Cowork 上で人＝AI が読んで実行する。
  - ドメインモデル = `takumi/domain/` の Python。集約の不変条件（ブランド slug の一意性・KPIツリーの整合・区画パスの正当性）をコードで表現し、`scripts/lint.py` がワークスペースの `knowledge/brands/**` を検証するときに使う。
- 集約の境界＝**Brand Isolation Guard（hook）の境界**。「別ブランド区画への書き込み禁止」はドメインの不変条件であり、hook で機械強制する。

## 4. 二層検証（Tier 1 / Tier 2）

| 層 | いつ | どこで | 何を | 手段 |
|---|---|---|---|---|
| **Tier 1** | 毎コミット | ローカル / CI | 参照整合・ドメイン不変条件・hookロジック・シェル健全性 | `lint.py` / `python3 -m unittest` / `test-hooks.sh` / shellcheck |
| **Tier 2** | フェーズ節目 | **cloud Cowork** | hook実配線・コマンド経路・エージェント起動・ブランド分離・ブラウザ実操作 | `/検証`（takumi-verify）を実タスク形式で実行 → PASS/FAIL を貼り戻す |

- **各検証項目は Tier を明示する**（`procedures/takumi-verify.md`）。Tier 1 で緑でも、hook 配線・経路・分離は Tier 2 でしか確証できない — 「Tier 1 が緑＝Cowork で動く」と誤認しない。
- Tier 2 が要るのは hook / コマンド / エージェント / ブランド境界が変わったフェーズ（[cowork-runtime.md](cowork-runtime.md) §6）。docのみの変更は Tier 1 で足りる。

## 5. CI（GitHub Actions・push[main] と全 PR で発火）

`.github/workflows/ci.yml` が回す（強化していく）:

1. `lint`: `python3 scripts/lint.py` → `lint: OK`（参照整合・frontmatter・JSON・台帳・version・delve-残骸禁止・ブランド区画スキーマ）
2. `tests`: `python3 -m unittest discover -s tests -v` → ドメインモデル（DDD 集約）の単体テスト全緑
3. `hooks`: `shellcheck --severity=error hooks/scripts/*.sh scripts/*.sh` + `bash scripts/test-hooks.sh` → `ALL PASS`

CI が赤い PR はマージ不可。**新しい機械チェックを足したら、それが守る不変条件をこの表に1行追記する。**

## 6. フェーズ完了の定義（Definition of Done）

- [ ] Tier 1 全緑（lint / unittest / test-hooks / shellcheck）
- [ ] 変更した不変条件に対するテスト（TDD で先に書いたもの）が存在し緑
- [ ] 台帳（`docs/command-registry.md`）と実体が双方向一致（lint が保証）
- [ ] PR の CI 全緑 → `main` にマージ
- [ ] hook/コマンド/エージェント/ブランド境界を変えたフェーズは、対応する Tier 2 検証項目（V番号）を追加済み（実機実行はユーザーに依頼）
