# /メール — メール配信の運営（takumi-email）

オーガニック媒体の1つ（`ChannelKind.EMAIL`）。**唯一、プラットフォームのアルゴリズムに露出を左右されない接点**であり、
指名検索・再訪・キーイベントに直結する。ゼロ広告費のブランドにとって最も安定した資産。

> **前段**: アクティブブランドを確定する（未確定なら /ブランド）。記憶は `knowledge/brands/<slug>/channels/email/` にスコープされる（Brand Isolation Guard 対象・原則4）。
> **役割分担**: 本文の執筆は `skills/sales-writing`（訴求）/ `skills/business-writing`（お知らせ・事務連絡）、件名は `skills/copywriting`（13字）。このパックは**媒体としての配信運営**を担う。

## 最重要: 配信は不可逆送出

**送ったメールは取り消せない。** このパックの手順の大半は、その1点のために存在する。

1. **配信は takumi-start のゲート下**。`bulk_send` を立てる
2. **`pre-send-verifier` の敵対的監査**を通す（下記チェックを機械的に見る）
3. **ユーザーの承認**を得る（承認前に送らない）
4. 送出後は **`outcome-verifier`** が証跡のある確定数だけを成果に数える
5. ログイン・配信ツールの操作認証は**人間が行う**（Credential Guard）

## 要望の振り分け（タスク4型）

| 要望の型 | やること | 参照 |
|---|---|---|
| 「メルマガ書いて」「お知らせ送りたい」 | 設計 → 執筆 → 監査 → 承認 → 配信 | `skills/sales-writing` / `business-writing` / `copywriting` |
| 「配信リストを整理して」 | オプトアウト・バウンス・重複の除去 | 下記「リストの衛生」 |
| 「件名のABテストしたい」 | 1要素だけ変えて半分に割る | `skills/cro-jp`（配信文面のABテスト） |
| 「開封率は？」「効果を見て」 | 実測 → KPIツリーへ返す | `/計測`（takumi-analytics）・`outcome-verifier` |

## 配信設計

**送る前に「なぜ今これを送るのか」に答える。** 答えられないなら送らない。配信頻度そのものがガードレール指標。

- **1通1目的。** 詰め込むと何も伝わらず、解除率だけ上がる
- **CTA は1つ**（複数のCTAは迷いを生む → `skills/cro-jp`）
- **セグメント**: 全員に同じものを送らない。少なくとも「既存顧客／見込み客」は分ける
- **フレームの選択**: 締切のある単発行動は損失フレーム、**継続関係（メルマガ）は利得フレーム**が基調（`skills/psych-nudge-jp`）
- **配信計画は `docs/parts/content-calendar.md`** で他媒体と横断して組む。表で終わらせずキューと定常タスクへ接続する

## リストの衛生（送る前に必ず）

| 項目 | 内容 |
|---|---|
| **オプトアウト済みの除外** | 解除した相手に送るのは最も重い事故。**除外はリストの正本側で行う** |
| バウンスの除去 | 継続的に不達のアドレスは到達率そのものを下げる |
| 重複の除去 | 同一人物に複数通が届く |
| **テンプレ変数の置換確認** | `[名前]` `{{company}}` が生で残っていないか。**1件でも残っていたら配信しない** |
| 配信解除リンク | 全通に必ず入れる |
| 送信者情報 | 事業者名・連絡先を明記する |

**リストの本体（宛先ファイル）は人間が管理する。** AI は除外・整形の提案までを行い、リストそのものの書き換えは承認を経る。

## 執筆

- **件名**: `skills/copywriting` の13字ルール。**機械で文字数を数える**（目視禁止）。開封されなければ本文は存在しない
- **本文**: 結論ファースト（PREP）。1文60字以内。相手の行動と期限を1箇所にまとめる（`skills/business-writing`）
- **実績・数値は実測値のみ。** 創作は1件でも致命（`skills/sales-writing`）
- **公開前チェック**: 最上級表現・保証表現・体験談があれば **`skills/ad-compliance-jp` を必ず通す**（メールも「表示」であり景表法・ステマ規制の対象）
- **煽らない**: 偽の希少性・恐怖訴求は禁止（session-rules (3)）

## テスト送信

**本配信の前に必ず自分宛てに1通送る。** 見るのは4点:

1. 件名と差出人名が意図どおりか
2. **テンプレ変数がすべて置換されているか**
3. リンクが正しく開くか（**UTM パラメータが付いているか** → `/計測` で流入を分解するため）
4. スマートフォンでの折り返しと文字サイズ（本文16px相当 → `skills/design-evidence-jp`）

## 効果測定（∞の上り）

配信して終わりにしない。取る数字と返し方:

| 指標 | 種別 | 注意 |
|---|---|---|
| 開封率 | 先行 | **画像ブロックとプライバシー保護で過小・過大に振れる。**絶対値を信用せず推移で見る |
| クリック率 | 先行 | 開封を分母にするか配信数を分母にするかを**先に決めて固定**する |
| 配信からのキーイベント | 遅行 | UTM をつけて `/計測`（GA4）のセッションスコープで分解する |
| **解除率** | **ガードレール** | 達成率ではなく**閾値を割っていないか**で見る。配信数を追うと必ずここが犠牲になる |

1. `knowledge/brands/<slug>/channels/email/<date>-配信.md` に**母数・期間つき**で記録
2. **KPIツリーの該当ノードに紐づける**（ツリーに無い指標は返さない）
3. 勝ちパターンはテンプレの正本に反映して初めて完了（メモだけ残さない）

## 禁止・注意

- **購入リスト・許諾のない宛先には送らない**（同意の有無が最初の関門）。
  **これは作法ではなく法規** — 特定商取引法は「消費者があらかじめ承諾しない限り、電子メール広告の送信を原則禁止」とし、
  **承諾記録は3年間保存**が必要（同趣旨のオプトイン規制は特定電子メール法にもある → `skills/ad-compliance-jp` §5）。
  **リストの出所と承諾記録の所在を言えないなら送らない。**「たぶん名刺交換した人」は承諾記録ではない
- **有料の配信オプション・従量課金プランへの変更は行わない**（ゼロ課金ゲート対象）
- 開封率の上下だけで施策を止めない（計測方法自体が不安定なため。移動平均で見る）
- 一斉配信の**宛先を BCC/個別送信のどちらにするかを必ず確認**する。宛先の相互露出は取り返しがつかない
