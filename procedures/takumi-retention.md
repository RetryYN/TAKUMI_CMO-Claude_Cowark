# /リテンション — 既存顧客の維持とファン化（takumi-retention）

**ゼロ広告費では、既存顧客が最大の獲得チャネルになる。** 新規を金で買えない以上、
**再訪・継続・紹介・口コミ**が成長の主動力になる。ここが空いていると、集めた分だけ漏れる桶に水を注ぐことになる。

> **前段**: アクティブブランドを確定する（未確定なら /ブランド）。記憶は `knowledge/brands/<slug>/retention/` にスコープされる（Brand Isolation Guard 対象・原則4）。
> **役割分担**: このパックは**誰に・いつ・何を届けるかの設計**を担う。実際の配信は **/メール**、コンテンツは **/コンテンツ・/オウンドメディア**、数字の取得は **/計測**、離脱理由の聞き取りは **/顧客の声**。

## 大原則

1. **獲得のファネルは「認知 → 流入 → 転換」で終わらない。** その後に**定着 → 継続 → 推奨**がある。他パックは前半、ここは後半を担う。
2. **去った理由は推測しない。** 解約・離脱の理由は `/顧客の声` で聞く（**生存者バイアス**: 残っている人だけに聞いても分からない）。
3. **接触を増やすことは施策ではない。** 頻度を上げれば必ず解除率が上がる。**解除率はガードレール指標**。
4. **LTV・CAC・ROAS は KPIツリーに置けない**（有料指標として `KpiNode` が `ValueError` で拒否する）。継続率・再訪率・紹介経由の比率など**オーガニックな指標で組む**。
5. **紹介に対価を渡すなら表示規制の対象**（ステマ規制。→ `skills/ad-compliance-jp`）。

## 要望の振り分け（タスク5型）

| 要望の型 | やること | 接続先 |
|---|---|---|
| 「継続率を見たい」「コホートを出して」 | 測る（下記①） | `/計測`（GA4）・`outcome-verifier` |
| 「解約理由を知りたい」「なぜ離れる？」 | **去った人に聞く**（推測しない） | `/顧客の声`（takumi-voc） |
| 「オンボーディングを設計して」 | 最初の体験の設計（下記②） | `/コンテンツ`・`/メール` |
| 「定期接点を作りたい」 | 届ける内容と頻度の設計（下記③） | `/メール`・`/SNS運用`・`/オウンドメディア` |
| 「紹介・口コミを増やしたい」 | 推奨の導線設計（下記④） | `/メール`・`skills/ad-compliance-jp` |

## ① 測る — コホートで見る

**「今月の継続率」は単体では読めない。** 入ってきた時期ごと（コホート）に分けて、経過月数で並べる。
そうしないと、新規が増えた月に継続率が下がったように見える。

| 指標 | 種別 | 定義の注意 |
|---|---|---|
| **継続率**（コホート別・n ヶ月後） | 遅行 | 分母は「その月に入った人」。**期間と母数を必ず併記** |
| **再訪率** | 先行 | GA4 の指標は推定値。絶対値ではなく推移で見る |
| **定着の節目に到達した割合** | **先行** | ②で決めた「ここを超えると残る」行動の到達率。**最も打ち手に近い** |
| 紹介・口コミ経由の流入比率 | 遅行 | 参照元が落ちることがあるため比率で持つ |
| **解除率・離脱率** | **ガードレール** | 達成率ではなく**閾値を割っていないか**で見る |

**数字を取ったら KPIツリーのノードに紐づける**（∞の上り）。ツリーに無い指標は返さない。
指標の新設は合議を通す（`docs/parts/pre-setup-council.md`）。

## ② オンボーディング — 「ここを超えると残る」を1つ見つける

継続率を動かす最短経路は、**最初の体験のどこで脱落しているか**を特定すること。

1. 入ってから離れるまでの経路を並べる（登録 → 初回利用 → …）
2. **各段階の到達率を測る**（`/計測`）。最も落ちている1箇所を特定する
3. その段階を越えた人と越えなかった人で、**その後の継続率が明確に分かれるか**を見る
4. 分かれるなら、そこが**定着の節目**。**先行指標としてKPIツリーに置く**
5. 節目までの導線を短くする（案内・初回コンテンツ・つまずきの除去）

**節目は自分で決めない。データで見つける。** 「たぶんここ」で施策を打つと、動かない指標が増えるだけ。
分かれ目が見つからないなら「未特定」と明示する（`skills/logical-writing`: 相関と因果を混同しない）。

## ③ 定期接点 — 頻度ではなく理由で設計する

**「毎週送る」は設計ではない。** 送る理由が無い回は、送らない方が継続率が上がる。

- **セグメントを分ける**: 最低限「定着済み／まだ／離れかけ」の3つ。全員に同じものを送らない
- **フレームは利得基調**: 継続関係では損失フレーム（失われます・終了します）は心理負担を残す（→ `skills/psych-nudge-jp`）
- **接点は複数チャネルに散らす**: メールだけに頼らない。SNS・記事・更新情報。ただし**同じ主張を形を変えて**届ける（同一文面の一斉配信はしない）
- **頻度の上限を決めて守る**。上限は解除率で調整する（ガードレール）

## ④ 紹介・口コミ — 頼む前に、頼める状態を作る

> **設計の正本は `skills/referral-advocacy-jp`。着手前に必ず Read する。**相対不達なら Glob。
> **紹介はゼロ広告費で唯一「複利で増える」獲得経路** — 顧客が増えるほど紹介の母数も増える。
> ここを偶然に任せているのは、一番強い武器を使っていないのと同じ。

1. **語る理由があるか先に確かめる**（満足していない顧客に頼むと不満を増幅させる → `/顧客の声`）
2. **満足している瞬間を特定する**（②の節目通過直後・成果が出た直後）
3. その瞬間に**頼む導線を1つ置く**（レビュー・紹介・事例掲載の依頼）
4. **語る言葉を渡す**（顧客自身の語彙・名前のついた概念・自社の実測値）。
   **定型文やハッシュタグを配らない** — 同じ文が並んだ時点で推奨としての価値が消える
5. **依頼は具体的に**（「何を・どこに・どのくらいの分量で」。`skills/business-writing` の依頼メール）
6. **掲載には必ず許諾を取る**（実名・所属・写真すべて）+ `privacy-auditor` の監査
7. **来た口コミには返信する**（→ `/エンゲージメント`）。返信は書いた本人より、**それを読む第三者**に効く
8. **掲載後、結果を相手に返す**（どれだけ読まれたか）。返す人は、次も応じてくれる

**頼んではいけないとき**: 不具合対応の直後／問い合わせが未解決／契約更新の交渉中
（**断りにくい状況で頼まない**）。

### 特典を出す場合（金額の上限は計算できる）

**対価（割引・特典・報酬）を渡す場合は、その旨の表示が必要**になる（ステマ規制）。
`skills/ad-compliance-jp` を必ず通す。**対価を伏せた口コミ依頼は行わない。**

さらに、**特典には景品表示法の景品規制による上限がある**（総付景品なら取引価額の10分の2 等）。
上限は計算できるので、**文章の注意書きで済ませず機械で確かめる**:

```python
from takumi.domain.premium import PremiumKind, PremiumOffer
PremiumOffer(PremiumKind.TOTSUKE, transaction_value_yen=5000, premium_value_yen=1500).assert_lawful()
```

**種別（総付景品／一般懸賞／共同懸賞）と、そもそも景品類に当たるか（値引きは当たらない）の判断は人間が行う。**
AI が自動分類しない — 過剰検知も過小検知も法的判断を誤らせる。限度額と根拠は `skills/referral-advocacy-jp` §5。

## ⑤ 離脱の兆候（できる範囲で）

**「解約してから知る」を減らす。** ただし予測モデルは作らない（データ量が足りず、外すと誤った接触を生む）。

観測できる単純な兆候だけを見る: 利用が途切れた／定期接点への反応が止まった／問い合わせの内容が変わった。
兆候を見つけたら**一斉配信ではなく個別に当たる**（`/メール` の個別接触。`skills/psych-target-jp`）。

## 記録と接続（ここまでやって完了）

1. `knowledge/brands/<slug>/retention/<date>-<種別>.md` に**期間・母数つき**で記録
2. **KPIツリーのノードに紐づける**（継続率・定着の節目・解除率）
3. 解約理由は `/顧客の声` の記録と突き合わせ、**推測で埋めた前提が覆ったら `/戦略` の再立案フラグ**として提示
4. `/レポート` のダッシュボードに反映（**解除率は閾値表示**）

## 禁止・注意

- **解約導線を隠さない・分かりにくくしない**（ダークパターン。景表法リスク → `skills/cro-jp`）
- **引き止めのための虚偽・誇張をしない**（「今なら」「あなただけ」が事実でないなら書かない）
- **有料の引き止め施策（値引き原資・広告リターゲティング）は扱わない**（ゼロ広告費・ゼロ課金ゲート）
- **個人の行動履歴を本人が想定しない形で使わない**（個人データを扱う設計は `docs/parts/pre-setup-council.md` の合議に privacy-auditor を呼ぶ）
- 一斉配信は不可逆送出（`pre-send-verifier` + 人間承認）
