# /計測 — 計測基盤の構築とデータ取得（takumi-analytics）

匠CMO の「**体**」＝データを取り、仮説を裏付ける柱。**指標を読むだけでなく、計測基盤そのものを組む。**
GA4・GTM・Search Console / Bing WMT を扱い、取った数字を **KPIツリーへ返す**（∞の上り）ところまでを1本で担う。

> **前段**: アクティブブランドを確定する（未確定なら /ブランド）。記憶は `knowledge/brands/<slug>/analytics/` にスコープされる（Brand Isolation Guard 対象・原則4）。
> **役割分担**: 「**何を測るか**」の設計は `skills/kpi-design-jp`（正本）と **/戦略**。このパックは「**どう測れるようにするか**」と「**取ってきて返すか**」を担う。指標の新設そのものは合議を通す（下記）。

## 大原則

1. **測る前に「この数字が動いたとき、我々は何を変えるのか」に答える。** 答えられない計測は作らない（`skills/kpi-design-jp` §0）。
2. **作った指標は必ず KPIツリーのノードに紐づける。** 測るだけで使わないデータを増やさない。紐づけ先は `knowledge/brands/<slug>/strategy/kpi-tree.yaml`。
3. **スキルを Read してから画面を触る。** `skills/gtm-jp` / `ga4-jp` / `search-console-jp` の冒頭に安全境界表がある（session-rules (3d)）。相対不達なら Glob。
4. **ゼロ広告費**: Google 広告アカウントとのリンク、有料出稿の計測設定は行わない（URL Guard / ゼロ課金ゲート対象）。
5. **PII を送らない。** メールアドレス・氏名・電話番号を GA4 へ送るのは Google 契約上の違反で、**送ってしまうと取り消せない**。

## 要望の振り分け（タスク4型）

| 要望の型 | やること | 参照する正本 |
|---|---|---|
| 「この指標を新しく測りたい」「KPIを足したい」 | **①合議 → ②設計 → ③実装** の順（下記「関所」） | `skills/kpi-design-jp` → `docs/parts/pre-setup-council.md` → `skills/ga4-jp` |
| 「イベントを飛ばしたい」「スクロール率/読了率を取りたい」 | GTM でトリガーとタグを組む（合議は**不要**） | `skills/gtm-jp` |
| 「数字を出して」「先月どうだった？」 | データ取得 → 解釈 → KPIツリーへ反映 | `skills/ga4-jp`（分析編）/ `skills/search-console-jp` |
| 「AI検索で引用されてる？」「検索順位は？」 | GSC / Bing WMT から一次情報で取得 | `skills/search-console-jp` |

## 関所: 合議を通すもの / 通さないもの

**判定基準は「後から直すのが高くつくか」**（`docs/parts/pre-setup-council.md` が正本）。

| 依頼 | 合議 | 理由 |
|---|---|---|
| **指標の新設・KPIツリーへのノード追加** | **通す** | 定義を後から変えると過去と比較できない |
| **カスタムディメンションの設計** | **通す** | 上限があり、削除しても48時間は同名で作り直せない |
| **カスタムチャネルグループの定義** | **通す** | 過去データに遡って再処理され、レポートの見え方が変わる |
| GTM のタグ・トリガー・変数の設定と**公開** | **通さない** | バージョンでロールバックできる。戻せる作業に関所を置くと、関所自体が軽く扱われる |
| 既存レポートの閲覧・データ取得 | 通さない | 読み取り |

合議は**常設2体（risk-forecaster / strategy-advisor）を1ターンで並列委譲**。**個人データを扱う依頼のときだけ privacy-auditor を足す**（GTM が扱うのは UTM・パス・イベント名・クリックIDで、通常は個人情報を含まない）。返答をそのまま貼らず、争点・兆候・最も安い保険＋**呼ばなかった相手とその理由**を統合して提示し、承認を待つ。

## GA4（設定と分析）

**設定**: キーイベントの追加は自律可。**カスタムディメンション/指標の追加は上限に注意**し、追加前に既存を棚卸しする。**データ保持設定の変更は禁止**（期限切れで消えたデータは戻らない）。データフィルターの有効化は承認必須。プロパティ/データストリームの削除・権限変更・**Google 広告とのリンクは禁止**。

**分析**: 探索の新規作成は自律可（既存を上書きせず、名前に `-takumi` を付ける）。レポートを読むときは以下を必ず添える:

- **推定値であることを明記する**（セッション数は HLL++ による推定。しきい値で行が消える）
- **ラストクリックとデータドリブンの両方を並べる。** ラストクリックでは認知を担うモダリティ（動画・SNS）が構造的に評価されない
- 新設したディメンションは**反映に24〜48時間**かかる。当日の依頼に「明日出せます」と答えない

## GTM（実装）

1. 変更前に**必ずコンテナをエクスポート**（JSON）して `knowledge/brands/<slug>/analytics/` に保存する
2. ワークスペース内でタグ・トリガー・変数を組む（公開しなければ本番に出ない）
3. **プレビュー（Tag Assistant）で発火を確認**し、**パラメータの中身を目視する**（PII 混入の唯一の実効的な防止策）
4. **公開は人間の承認**を得てから。ロールバックは「バージョン → アクション → 最新バージョンに設定」で可能

**カスタムHTMLタグ / カスタムJavaScript変数は AI 自律禁止。** 下書きの提示までにとどめ、作成・保存は人間が行う。削除ではなく**一時停止（Pause）**を提案する。

## Search Console / Bing WMT（検索とAIでの露出）

生成AIパフォーマンスレポート・検索クエリ・掲載順位・インデックス状況・sitemap 送信を扱う。
**削除ツール（Removals）は AI 自律禁止**、所有権・ユーザー設定の変更は禁止。

**ゼロ広告費における意味**: 広告で反復露出を買えない以上、**認知の伸びは検索側にしか現れない**。
指名検索の推移は `skills/kpi-design-jp` のシェア・オブ・サーチに接続する。

## ∞の上り（このパックの締め）

取ってきた数字は、必ずここまで通して初めて完了する（メモだけ残さない）:

1. `knowledge/brands/<slug>/analytics/<date>-<種別>.md` に**出所・集計期間・母数つき**で記録する
2. **KPIツリーの該当ノードに紐づける**。ツリーに無い指標は返さない（`DownstreamLoop.hand_up` が拒否する構造と同じ）
3. **停滞ノード**（前回比の伸びが閾値未満）を洗い出し、**/戦略 の再立案フラグ**として提示する
4. **ガードレール指標は達成率ではなく「閾値を割っていないか」**で見る
5. `/レポート` のダッシュボードに反映する

## 検証（`scripts/lint.py --workspace .`）

KPIツリーとキャンペーンの整合は機械で確認できる（V49）。指標を足したら回す:

```bash
python3 <プラグインルート>/scripts/lint.py --workspace .
```

## 禁止・注意

- **ブラウザ操作は takumi-start のゲート下**（変更操作は変更前記録が要る）。ログインは人間が行う（Credential Guard）
- 数字の解釈で**相関と因果を混同しない**（「変えた週に増えた」だけなら**要因未特定と明記**する）
- **虚栄の指標を KPI にしない**（累計値・母数が変われば崩れる値・打ち手と結び付かない値 → `skills/kpi-design-jp`）
- レポート化は `skills/logical-writing` + `docs/conventions.md`（`templates/report-template.html` の骨格）に従う
