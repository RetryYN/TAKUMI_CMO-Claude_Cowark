## 生成スキルの規約チェック（Agent Skills 公式規約準拠 — 2026-07-23 導入）

生成する SKILL.md は保存前に以下を自己チェックする（公式 skill-creator の思想を翻案）:

- [ ] **name**: 英語ケバブケース・ディレクトリ名と一致
- [ ] **description に「Use when / Not for」**: 発火判定はメタデータだけで行われる — いつ使うか・いつ使わないかを日本語の言い方で書き切る
- [ ] **段階的開示**: SKILL.md 本体は要点のみ（目安5,000語以内）。長い参照資料・スクリプトは同ディレクトリの別ファイルに分け、本体からリンクする
- [ ] **重複チェック**: 既存の skills/（42本）・docs/parts/ と役割が被らないか。被るなら新設せず既存を更新する（乖離防止）
- [ ] **golden タスク**: プラグイン同梱の skills/ に新設する場合は `docs/evals.md` に評価タスクを1つ書く（**`scripts/lint.py` が要求する** — 無いと CI が落ちる）。腕落ちを測る手段のないスキルを増やさないため。ワークスペース側の `.claude/skills/` は対象外
- [ ] **`## 接続`（前段／後段／併用／正本が別）を書く** — 正本は `docs/skill-map.md`。**他スキルへ2本以上つなぐ**（行き止まりを作らない）
- [ ] **既存スキル側に張り返す** — **新設スキルは外向きのリンクを自然に書くが、既存側からの張り返しは必ず忘れる**（2026-07-26 の実測で孤島2本・行き止まり3本を検出した原因がこれ）。最低限「前段になるスキルの `## 接続` の後段」に自分を足す。**`scripts/lint.py` が「どのスキルからも参照されていない」を落とす**
- [ ] **`docs/skill-map.md` の層の表に追加**（これも lint が要求する）
- [ ] **`## 出典` を書く（その数字はどこから来たのか）** — **外部出典がゼロでも省略しない。【社内基準】と明記する**（空欄は書き忘れと区別がつかない）。ラベルは【一次情報・確認済み】【一次情報・出所は特定済み／原文は未取得（要確認）】【二次情報・原典未取得】【未確認】【社内基準】の5種（→ `docs/開発ワークフロー.md` §0b-2）。**`scripts/lint.py` が節の存在とラベルを要求する**。**配下に `resources/` を作るならそこにも書く** — 本文が「必読」で開く以上、正本と同じ強さで読まれる
- [ ] **数値を書いたら出所を必ず添える** — 出所を辿れない数値は**書かないか、「成果物に引用しない」と明記する**。2026-07-26 の実測で、**出典なしの利用率が1年古いまま気づかれず**、「数値根拠」と題したファイルの改善率5件が**すべて出所不明**だった

## 3種の定着先（振り分け基準）

| 種類 | 判定 | 保存先 |
|---|---|---|
| **手順（スキル）** | 「同じやり方で再実行できる方法」— ユーザーが教えた手順、2回以上繰り返した作業パターン、試行錯誤の末に確立したやり方 | ワークスペースの `.claude/skills/<name>/SKILL.md` |
| **暗黙知（ナレッジ）** | 「調べても出てこない事実」— 業界事情、社内ルール、取引先の癖、この人しか知らない背景・判断基準 | `knowledge/tacit/<topic>.md` |
| **好み（既存）** | 成果物への OK/NG | `knowledge/feedback/lessons.md`（/メモリ保存 の管轄） |

## スキル化の手順

1. 手順を再実行可能な形に整理する（前提 → ステップ → 検証方法 → 失敗時の対処）
2. `.claude/skills/<kebab-name>/SKILL.md` として書く。frontmatter 必須:
   - `name`: ケバブケース
   - `description`: **「Use when + ユーザーの言い方の例」形式**（自動発火の生命線。本プラグインのコマンド群と同じ作法）。**言い方の例は必ず日本語で書く**（ユーザーは日本語で話しかけるため。英語の例だけだと発火しない）
3. 具体値（URL・ID・数値）は本文に残してよい（ワークスペース内に閉じるため）。ただし認証情報は絶対に書かない
4. 既存スキル（プラグイン同梱+ワークスペース）と重複しないか確認。重複するなら新規作成せず既存を更新
5. 作成後「スキル化しました: <name> — 次からは『◯◯して』で発火します」と1行報告

## ナレッジ化の手順

1. `knowledge/tacit/` 配下にトピック単位で記録（1ファイル1トピック、150行超えたら分割）
2. 形式: 事実 → 出所（誰から/いつ）→ 適用場面。推測と事実を混ぜない
3. 既存ファイルがあれば追記・更新（矛盾したら新しい方を正とし、古い記述に取り消し線）
4. 記録後「ナレッジ化しました: <topic>」と1行報告

## 自動発火の合図（この状況を見たら提案ではなく実行する）

- ユーザーが手順を口頭で説明した（「うちではこうやってる」「この順でやって」）
- 同じ種類のタスクで前回と同じ手直しをした（2回目=パターン）
- 業界・社内・媒体固有の事実が会話に出た（「この媒体は金曜に審査が止まる」等）
- 明示指示（「覚えて」「スキルにして」「次からこれで」）

## 注意

- スキル・ナレッジはワークスペース産物（フォルダ接続していないと消える — 未接続なら記録前にその旨を警告する）
- 記録は静かに素早く（長い確認をユーザーに求めない。1行報告のみ）
- 個人情報（候補者名等）はナレッジに書かない。役割・属性に抽象化する
