# /キャンペーン — 複数媒体の統括（takumi-campaign）

匠の∞ループの**打ち手（統括）**。戦略（上流）が流した「計画」を受け、**複数のオーガニック媒体を1つの目標の下に束ねて**オーケストレーションする。すべて**ゼロ広告費**（有料出稿は組み込まない）。

> **前段**: アクティブブランドを確定する（未確定なら /ブランド）。計画は `knowledge/brands/<slug>/strategy/campaigns/` にスコープされる（Brand Isolation Guard 対象）。

## 手順

1. **目標の確定**: このキャンペーンで動かす **KPIツリーのノード**を1つ選ぶ（`knowledge/brands/<slug>/strategy/kpi-tree.yaml` から。無ければ /戦略 を先に）。期間と達成水準（仮でも根拠つき）を決める。
2. **参加媒体の選定**（オーガニックのみ）: SNS運用 / コンテンツ / Webサイト / オウンドメディア / メール から、目標に効く媒体を選ぶ。各媒体の役割（認知/流入/転換/信頼）を割り当てる。
2b. **モダリティの面を張る（包囲網の形成）**: 媒体だけでなく**テキスト／画像／動画**の3モダリティで露出面を設計する。1本の主張を、記事（`/オウンドメディア`）・投稿（`/SNS運用`）・画像/バナー・動画（`/コンテンツ`）へ**同じ骨子のまま形を変えて**展開する。テキスト1本は点にすぎず、モダリティを横断して初めて面になる — **これが「AI に届く」の実体**（複数モダリティ・複数露出面から反復して現れるものを AI は認知し推奨する）。キャンペーン YAML に `modalities:` として、どのモダリティを誰がいつ担うかを明記する。**媒体を増やす前に、いま持っている主張のモダリティ展開が埋まっているかを先に見る**（1記事を動画・画像に展開するほうが、新媒体を1つ足すより面が濃くなる）。
3. **計画化**: docs/parts/content-calendar.md（計画部品）で、媒体横断のカレンダー・配信計画を作る。**表で終わらせず** queue.md 反映と定常タスク化（/カスタマイズ）まで接続する。
4. **統括ファイルの保存**（アクティブ区画内）: `knowledge/brands/<slug>/strategy/campaigns/<name>.yaml` に「目標KPI・参加媒体と役割・スケジュール・成果の測り方」を記録。**`goal_kpi:`（KPIツリーに実在するノード名）と `channels:`（オーガニック媒体）の2キーは機械検証の対象**なのでこの名前で書く（他は自由記述。形は docs/domain-model.md「ワークスペース検証」。`scripts/lint.py --workspace .` で検証）。
5. **実行は下流の各パックへ**: 実際の制作・投稿は /SNS運用・/コンテンツ・/Webサイト が担う（変更操作は takumi-start のゲート下・不可逆送出は pre-send-verifier + 承認）。キャンペーンは司令塔として進捗を束ねるだけで、手順を複製しない。
6. **計測を上流へ返す（∞の上り）**: 各媒体の実測を outcome-verifier が集計 → 目標KPIノードの進捗を更新 → /戦略 の再立案インプットにする。
7. **ダッシュボード**: /レポート のトップ（ダッシュボード）でキャンペーン進捗・KPIツリーの動きを可視化する。

## 原則

- 1キャンペーン=1目標（KPIツリーの1ノード）。媒体を増やすより、1つの物語で束ねることを優先。
- **主張は1つ、形は複数**。モダリティごとに言うことを変えない（面がぼやけて包囲網にならない）。骨子は共通、表現だけを媒体・モダリティに最適化する。
- 費用は使わない。ブースト・出稿・課金導線は組み込まない（ゼロ課金ゲートが遮断）。
- 複数ブランドを運用している場合も、キャンペーンは常にアクティブブランドの区画に閉じる。
