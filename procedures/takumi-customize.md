# /カスタマイズ — 仕組みを育てる統合入口（takumi-customize）

## 0. 何をカスタマイズ？（曖昧なときだけ聞く）

要望から読み取れなければ質問ツールで確認する:

1. **タスクをまとめる**（繰り返す仕事の登録） → procedures/takumi-task.md
2. **スキルを作る**（手順・やり方を覚えさせる） → procedures/takumi-skillify.md（ルール？方法？判断基準？の分類つき）
3. **好み・NGを記憶**（成果物への評価を次に活かす） → procedures/takumi-feedback.md
4. **機能のON/OFF**（使う媒体・パックの変更） → procedures/takumi-config.md（媒体の増減は /セットアップ でも可）

## 判定のヒント

- 「毎朝/毎週◯◯して」「定常化して」 → 1
- 「このやり方覚えて」「同じ作業2回目」 → 2（スキル化条件は session-rules (3c)）
- 「ここはNG」「次からこうして」 → 3
- 「◯◯機能いらない」「TikTokやめる」 → 4

複合依頼（「これ覚えて毎朝やって」）は 2→1 の順に両方実行する。完了時は「登録した内容 + 次からの呼び出し方（『<タスク名>やって』）」を1行で報告。

## 壁打ちを通す条件（① 構える — 2026-07-26 に穴として検出）

**ここで作るのは「これから毎回走るもの」であり、後から直すのが高い。**
にもかかわらず、このパックは長らく**エージェントを1体も通していなかった**
（コマンド→手順書→部品→エージェントの到達を機械で数えて判明）。

| 作るもの | ① 構える で通すもの |
|---|---|
| **定常タスクの新規設計**（1. タスクをまとめる） | **`strategy-advisor`**（session-rules (11)(12)。VERDICT を得てから YAML を書く） |
| **計測・指標に関わる設定**（GA4/GTM/GSC の値、指標の新設） | **`docs/parts/pre-setup-council.md` の並列合議**（risk-forecaster + strategy-advisor。個人データが射程なら privacy-auditor を追加） |
| スキル化・好み記憶・機能ON/OFF | 通さない（**可逆で影響範囲が閉じている**ため） |

**壁打ちを飛ばしてよいのは「すぐ消せるもの」だけ。** 毎朝走る設定は、間違っていても
毎朝走り続ける — 気づくのは数週間後になる（→ `docs/parts/task-loop.md` ①）。

**③ 咎める は「破壊的ステップの人間承認」が担う**（`destructive: true/auto` は Step H で必ず承認を取る）。
**④ 確かめる は初回実行**: 登録して終わりにせず、1回走らせて動くことを確認するまでが完了
（動かない定常タスクは、動かないまま放置される）。
