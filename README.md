# TAKUMI-CMO（匠CMO）

> *金は1円も使わない。コンテンツとブランディングで、ブランドを無双させる。*

## コンセプト — AI時代、広告先行はひっくり返る

**運用スキルは凡庸化した。**

かつて広告運用は虎の子だった。入札を刻み、クリエイティブを差し替え、配信面を切る。その職人技が差を生んだ。
いまは AI に財布を握らせれば、勝手に回し、勝手に改善し続ける。出稿は増え、スキルは平準化し、
残った差は**いくら出せるか**だけになった。広告先行のモデルは資本の殴り合いへ収束する。
そこでは「うまくやる」ことに意味がない。

**同時に、伝わり方が変わった。**

人は検索結果を上から舐めない。AI に聞いて、答えを受け取る。そこで選ばれるのは、
**オーガニックに厚く露出し、AI に認知され、推奨されるもの**だ。
マーケティングは「人に直接伝える」から、**AI を介して人に伝える**モデルへ移った。
広告枠を買う競争の隣で、露出の総量と一貫性という別の競争が始まっている。

**では人間の仕事は何か。**

市場を探り、まだ誰も気づいていない可能性を見つけ、それを戦略へ返すこと。
そして提案書で終わらせず、**公開された成果物として世に出しきること**だ。

TAKUMI-CMO はこの考えを製品にした。**広告予算という変数を 0 に固定**し、
残りすべて — 戦略・企画・制作・運用・計測 — の質と回転数で成果を出す。
ゼロ広告費は努力目標ではない。**機械的な制約**だ。広告マネージャや課金ページへの遷移は安全ゲートが遮断し、
KPIツリー自体が CAC/ROAS/広告費といった有料指標を受け付けない。「つい出稿してしまう」経路が存在しない。

**匠CMO は実務主義だ。分析でも提案でもない。成果を納品するための仕組みである。**

## 匠の三徳 — 心・技・体

マーケティングのプロは、**仮説づくりのプロ**であるべきだ。背景情報を読み取り、数字を読み取り、市場を読み切る。

データドリブンは正しい。ただし**データは背景を読み解かない**。数字は「何が起きたか」しか語らず、
「なぜ起きたか」「次に何が起こりうるか」は語らない。だからプロはリサーチで背景を掘り、そこから推論する。
匠CMO は、この仮説づくりを支える三つを徹底的に磨いた。

**心 — ユーザー行動を心理学から読み解き、市場を開拓する**

「たぶんこう感じるはず」で書かない。**心理プロファイリング**で読み手の意思決定スタイル・不安・関係段階を3軸で確定し、
**認知行動療法（CBT）の「認知の歪み」**を使って、購買や応募を妨げている思考パターンを特定する。
全か無か思考、破局視、べき思考 — ブレーキの正体が分かれば、文面で先回りして外せる。
訴求フレームの選択も、デザインの視線設計も、配色も、実証データから決める。感覚では決めない。

ただし**線は引いてある**。心理学は**不安の解消に使い、増幅には使わない**。恐怖訴求も偽の希少性も却下される。
読み手を「あなたは◯◯タイプなので」と**診断しない** — プロファイルは書き手側の内部判断に留める。
判定基準は1つ、**「事実を分かりやすく伝えた結果か、事実を歪めて作った感情か」**。後者は通らない。

**技 — ユーザーにも AI にも届く形に磨き上げ、伝わることを実現する**

*ユーザーに届く*は品質の話だ。検索意図、転換率、可読性、コントラスト。感覚ではなく実証基準の数値で決める。
生成したビジュアルは審査エージェントの PASS を得るまで人前に出ない。作りっぱなしを構造的に禁じている。

*AI に届く*は**面の話**だ。テキスト1本では点にしかならない。記事・SNS投稿・画像・動画を横断して出し、
**マルチメディアで包囲網を形成する**。同じ主張が複数のモダリティと複数の露出面から立ち上がるとき、
AI はそれを認知し、推奨する。だから匠CMO は最初からテキスト・画像・動画を扱い、
複数媒体を1目標で束ねる司令塔（`/キャンペーン`）を持っている。

**体 — データを取り、仮説を裏付け、AI の実行力で加速する**

実ブラウザで計測し、公開し、証跡を残す。送出後は成果を検証し、**証跡のある数だけ**を成果として数える。
一度攻略したサイトの構造は地図として残り、次の実行が速くなる。

**そして、この三つをつなぐのがデータだ。**

心が立てた仮説を、技が形にし、体が実測する。実測は KPIツリーへ返り、次の仮説の材料になる。
データは目的ではない。三徳をつなぐ血流である。この循環を回す機能を、このプラグインに封入した。

## 達成するもの — 匠の∞（無限）ループ

三徳を「どう回すか」の答えがこれだ。戦略だけ立てて実行が伴わない。実行だけ回して学びが戻らない。
この断絶を消すために、**上流（戦略）ループ**と**下流（実行）ループ**を、**計画**と**計測**で結んだ ∞ 字の学習系にした。

- **上流ループ（戦略）**：リサーチ→仮説→戦略→計画→改善。市場・競合・自社を読み、KPIツリーと施策ロードマップを組む
- **下流ループ（実行）**：計画→リサーチ→企画→実行→計測→改善。オーガニック媒体で実行し、実測を上流へ返す
- **∞ の交差点**：下りは *計画*、上りは *計測・改善*。両ループが共有する背骨が **KPIツリー**

回すほど賢くなる。効いた訴求も外した仮説もナレッジに積み上がり、停滞した KPI ノードは
「戦略の再立案が要る」と自動的に上流へ差し戻される。
これを **1インストールで複数ブランド**ぶん、記憶を混ぜずに並行して回す。

## なぜ Claude Cowork なのか — 「Claude Code でよくない？」への答え

**よくない。**

Claude Code はエンジニアの開発環境だ。ターミナルがあり、リポジトリがあり、成果物はコード。
一方、**CMO の成果物は「公開された記事」「投稿されたポスト」「改善されたLP」**であって、
コードでも分析レポートでもない。**超実務主義のCMOは Cowork を選ぶ。**

- **提案書で終わらない** — Claude in Chrome があなたのログイン済みセッションで実ブラウザを操る。
  API を公開していない媒体でも、管理画面でも、WordPress でも、**実際に公開するところまで**行く。
  「こう改善すべきです」で止まるツールとの差はここに出る
- **暴走を仕組みで止める** — 実務を任せるなら、止める力が要る。Cowork のプラグイン機構（hooks）で
  「承認前に送信させない」「課金ページへ行かせない」「別ブランドの記憶に書かせない」を、
  **AIの善意ではなく機械的な制約として**強制する。ゼロ広告費の保証もこの上に載っている
- **明日も同じ仕事をする** — ナレッジ・ログ・タスク定義がワークスペースに永続し、定常タスクは無人で回る。
  毎回チャットで説明し直す運用は、実務ではない
- **コードを書かなくていい** — 設定も指示も日本語。CLI もリポジトリも要らない

> すまない。これで7割のマーケターの仕事は要らなくなる。本当に申し訳ない。
> ただ、**残り3割** — 何に賭けるかを決めること — は、まだ人間のものだ。

## セットアップ（3ステップ）

1. Cowork の **設定 → プラグイン** でこのリポジトリを marketplace として追加する:
   `https://github.com/RetryYN/TAKUMI_CMO-Claude_Cowark`
2. **takumi-cmo** を有効化する
3. 最初に `/セットアップ` を実行 — 運用するSNS・生成AIアカウント・素材サイトをチェックリストで回答する（1回だけ。あとから変更可）

ブラウザ操作は **Claude in Chrome**（あなたの実ブラウザ）で行うため、ログイン済みのサイトがそのまま使える。
チャットの「+」→ コネクタで Claude in Chrome を ON にしておくこと。

## 使い方 — コマンドを覚える必要はない

普通に日本語で頼めばいい。Claude が適切な機能を自動で選ぶ。コマンドは**業務ジャンルごとのまとまり（「パック」）**で、
やってほしいことは引数に自由に書ける。

| カテゴリー（パック） | 言い方の例 |
|---|---|
| /戦略 | 「戦略を立てて」「KPIツリー作って」「3C分析して」（上流ループ＝軍師が立案。ゼロ広告費で統合戦略） |
| /キャンペーン | 「キャンペーン組んで」「複数媒体を連動させて」（複数オーガニック媒体を1目標で統括） |
| /ブランド | 「ブランドを追加」「acme に切り替え」「ブランド一覧」（マルチブランドの登録・切替・一覧） |
| /Webサイト | 「表示速度を測って」「デザイン調べて」「このLPを改善して」「徹底的に洗い出して」 |
| /コンテンツ | 「記事のアイキャッチ作って」「サムネ作って」「Geminiで画像/動画作って」「バナーにして」（オウンド/オーガニック制作） |
| /SNS運用 | 「Xの投稿ストック埋めて」「noteを書いて」（X/Instagram/Threads/TikTok/note/YouTube/LINE対応） |
| /リサーチ | 「競合を分析して」「トレンド調べて」（SNS/サイト/市場 — 対象に合わせて最適な調査へ振り分け） |
| /オウンドメディア | 「ブログ記事を公開して」「WordPressを更新」「記事のSEO見直し」（**WordPress 既定**） |
| /ワーク追加 | 「dodaを追加して」— 登録 + 管理画面を初期マッピング + 専用コマンドを自動生成 |
| /セットアップ | 導入直後に1回 — 運用媒体・アカウント・素材サイト等をチェックリストで回答 |
| /カスタマイズ | 「毎朝これやって」「このやり方覚えて」— タスク登録・スキル化・好み記憶・機能ON/OFF |
| /レポート | 「今どうなってる？」「今日の作業まとめて」— 全体サマリー + 作業ログ/運用レポート |

はじめてなら「何ができるの？」と聞けばガイドツアーが始まる。

執筆・生成・審査・戦略立案は専任エージェントが分業し、**生成→審査→修正**を通ってから成果物が出る。
調査・診断・作業報告は統一デザインの HTML レポートで届く。

各ブランドの記憶は `knowledge/brands/<slug>/` に**区画分離**され、戦略・KPI・媒体状態・ナレッジ・ログが
1ブランドに閉じる。すべてのタスクは、まずアクティブブランドを確定してから走る。

## フォルダの接続（推奨）

「フォルダを追加」で業務用フォルダを接続する。未接続でも動くが、こうなる:

- ナレッジとログがセッション終了で消える
- 専門AIがプラグイン同梱の執筆規範に到達できず、デザイン審査や法規チェックの精度が落ちる

**メディア制作（背景除去・WebM化・バナー合成）を使うなら必須。** 生成物をフル解像度で取り込むために
**専用ダウンロードフォルダ**を用意する:

1. PC に専用フォルダを作る（例: `CoworkDrop`）
2. Chrome の設定 → ダウンロード → 保存先をそのフォルダに変更（または「保存場所を確認」を ON）
3. Cowork の「フォルダを追加」で **そのフォルダだけ** を接続する

**Downloads フォルダ本体は絶対に接続しないこと**（個人書類が丸ごと AI から見える）。

## 安全設計

- 認証情報は扱わない。ログインは人間が行う。**Credential Guard** がパスワード・認証コード欄へのAI入力をブロックする
- 変更操作はワークフローゲート（フェーズ判定・変更前記録）を通過しないと実行されない
- 送信・投稿など不可逆な送出の前は、敵対的監査 ＋ 人間承認の二段ゲート。金銭・契約系の画面は **Money Watch** が検知して変更操作を止める
- **ゼロ広告費は二重に守る** — 安全ゲートが広告マネージャ・課金URLを遮断し、加えて KPIツリー自体が
  CAC/LTV/ROAS/CPA/広告費 等の有料指標を受け付けない。ゲートが沈黙しても有料前提が設計に混入しない
- **削除も守る** — フォルダ一括削除・`rm -r` は人間の承認なしに実行されない

**既知の限界**（多層防御の前提。ゲートを唯一の防御にせず、自己規律と人間承認を併用している）:

- **安全ゲートが効くかは環境に依存する。** Cowork のバージョン・構成によっては hooks が発火せず、
  その場合は全ゲートがフェイルオープンになる。一括送出・金銭近傍・無人運用は、ゲートの発火を確認できた環境で行うこと
- ゲートの対象は MCP ブラウザツール。**Bash 経由の直接送信（node/curl 等）は対象外**
- ゲートの実体は `memory/.workflow/` のフラグファイルで、Bash から直接触れば技術的に迂回できる。
  「うっかり・手順飛ばし」への防御であって、意図的な迂回への防御ではない
- Credential Guard 等はキーワード検知の best-effort

### 誤ブロックの開放・抑制リスト（あなたが手で編集するファイル）

ガードが安全側に倒しすぎたときは、業務フォルダの `knowledge/config/` にテキストファイルを置いて調整する
（1行1パターン・`#` はコメント・正規表現可）:

| ファイル | 効果 |
|---|---|
| `url-allowlist.txt` | URL Guard の誤ブロックを開放。**AIは代筆しない**（あなた本人が編集する） |
| `money-suppress.txt` | Money Watch が平常画面に反応しすぎるときの抑制 |
| `critic-suppress.txt` | デザイン審査ゲートを通さなくてよいファイルのパターン |
