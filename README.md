# TAKUMI-CMO（匠CMO）

> *金は1円も使わない。コンテンツとブランディングで、ブランドを無双させる。*

## コンセプト — AI時代、広告先行はひっくり返る

**運用スキルは凡庸化しました。** かつて広告運用は虎の子でした。入札を刻み、クリエイティブを差し替え、
配信面を切る。その職人技が差を生んだ。いまは AI に財布を握らせれば、勝手に回し、勝手に改善し続けます。
出稿は増え、スキルは平準化し、残った差は**いくら出せるか**だけ。広告先行のモデルは資本の殴り合いに収束し、
そこでは「うまくやる」ことに意味がなくなります。

**同時に、伝わり方が変わりました。** 人は検索結果を上から舐める代わりに、AI に聞いて答えを受け取ります。
そのとき選ばれるのは、**オーガニックに厚く露出し、AI に認知され、推奨されるもの**です。
マーケティングは「人に直接伝える」から、**AI を介して人に伝える**モデルへ移りました。
広告枠を買う競争の隣で、露出の総量と一貫性という別の競争が始まっています。

**では人間の仕事は何か。** 市場を探り、まだ誰も気づいていない可能性を見つけ、それを戦略へ返すこと。
そして提案書で終わらせず、**公開された成果物として世に出しきること**です。

TAKUMI-CMO は、この考えを製品にしたものです。**広告予算という変数を 0 に固定**し、
残りすべて — 戦略・企画・制作・運用・計測 — の質と回転数で成果を出します。
ゼロ広告費は努力目標ではなく**機械的な制約**です。広告マネージャや課金ページへの遷移は安全ゲートが遮断し、
KPIツリー自体が CAC/ROAS/広告費といった有料指標を受け付けません。「つい出稿してしまう」経路が存在しません。

**匠CMO は実務主義です。分析でも提案でもなく、成果を納品するための仕組みです。**

## 達成するもの — 匠の∞（無限）ループ

戦略だけ立てて実行が伴わない、あるいは実行だけ回して学びが戻らない。この断絶をなくすため、
**上流（戦略）ループ**と**下流（実行）ループ**を、**計画**と**計測**で結んだ ∞ 字の学習系にしています。

- **上流ループ（戦略）**：リサーチ→仮説→戦略→計画→改善。市場・競合・自社を読み、KPIツリーと施策ロードマップを組む
- **下流ループ（実行）**：計画→リサーチ→企画→実行→計測→改善。オーガニック媒体で実行し、実測を上流へ返す
- **∞ の交差点**：下りは *計画*、上りは *計測・改善*。両ループが共有する背骨が **KPIツリー**

回すほど賢くなります。攻略したサイトの構造・効いた訴求・外した仮説がナレッジに蓄積され、
停滞している KPI ノードは自動的に「戦略の再立案が要る」と上流へ差し戻されます。
これを **1インストールで複数ブランド**ぶん、記憶を混ぜずに並行して回せます。

## なぜ Claude Cowork なのか — 「Claude Code でよくない？」への答え

**よくありません。** Claude Code はエンジニアの開発環境です。ターミナルがあり、リポジトリがあり、
成果物はコードです。一方、**CMO の成果物は「公開された記事」「投稿されたポスト」「改善されたLP」**であって、
コードでも分析レポートでもありません。**超実務主義のCMOは Cowork を選びます。**

- **提案書で終わらない** — Claude in Chrome があなたのログイン済みセッションで実ブラウザを操ります。
  API を公開していない媒体でも、管理画面でも、WordPress でも、**実際に公開するところまで**行きます。
  「こう改善すべきです」で止まるツールとの決定的な差はここです
- **暴走を仕組みで止められる** — 実務を任せるなら、止める力が要ります。Cowork のプラグイン機構（hooks）で
  「承認前に送信させない」「課金ページへ行かせない」「別ブランドの記憶に書かせない」を、
  **AIの善意ではなく機械的な制約として**強制できます。ゼロ広告費の保証もこの上に載っています
- **明日も同じ仕事をする** — ナレッジ・ログ・タスク定義がワークスペースに永続し、定常タスクは無人で回ります。
  毎回チャットで説明し直す運用は、実務ではありません
- **コードを書かなくていい** — 設定も指示も日本語です。CLI もリポジトリも要りません

> すみません、これで7割のマーケターの仕事は要らなくなります。本当にごめんなさい。
> ただ、**残り3割の仕事** — 何を賭けるか決めること — は、まだ人間のものです。

## セットアップ（3ステップ）

1. Cowork の **設定 → プラグイン** でこのリポジトリを marketplace として追加:
   `https://github.com/RetryYN/TAKUMI_CMO-Claude_Cowark`
2. **takumi-cmo** を有効化
3. 最初に `/セットアップ` — 運用するSNS・生成AIアカウント・素材サイトをチェックリストで回答（1回だけ。あとから変更可）

ブラウザ操作は **Claude in Chrome**（あなたの実ブラウザ）で行うため、ログイン済みのサイトがそのまま使えます。
チャットの「+」→ コネクタで Claude in Chrome を ON にしてください。

## 使い方 — コマンドを覚える必要はありません

普通に日本語で頼めば、Claude が適切な機能を自動で使います。コマンドは**業務ジャンルごとのまとまり（「パック」）**で、
やってほしいことは引数に自由に書けます。

| カテゴリー（パック） | 言い方の例 |
|---|---|
| /戦略 | 「戦略を立てて」「KPIツリー作って」「3C分析して」（上流ループ＝軍師が立案。ゼロ広告費で統合戦略） |
| /キャンペーン | 「キャンペーン組んで」「複数媒体を連動させて」（複数オーガニック媒体を1目標で統括） |
| /ブランド | 「ブランドを追加」「acme に切り替え」「ブランド一覧」（マルチブランドの登録・切替・一覧） |
| /Webサイト | 「表示速度を測って」「デザイン調べて」「このLPを改善して」「徹底的に洗い出して」 |
| /コンテンツ | 「記事のアイキャッチ作って」「サムネ作って」「Geminiで画像/動画作って」「バナーにして」（オウンド/オーガニック制作） |
| /SNS運用 | 「Xの投稿ストック埋めて」「noteを書いて」（X/Instagram/Threads/TikTok/note/YouTube/LINE対応） |
| /リサーチ | 「競合を分析して」「トレンド調べて」（SNS/サイト/市場 — 対象に合わせて最適な調査へ振り分け） |
| /オウンドメディア | 「ブログ記事を公開して」「WordPressを更新」「記事のSEO見直し」（**WordPress 既定**） |
| /ワーク追加 | 「dodaを追加して」— 登録 + 管理画面を初期マッピング + 専用コマンドを自動生成 |
| /セットアップ | 導入直後に1回 — 運用媒体・アカウント・素材サイト等をチェックリストで回答 |
| /カスタマイズ | 「毎朝これやって」「このやり方覚えて」— タスク登録・スキル化・好み記憶・機能ON/OFF |
| /レポート | 「今どうなってる？」「今日の作業まとめて」— 全体サマリー + 作業ログ/運用レポート |

はじめての方は「何ができるの？」と聞けばガイドツアーが始まります。

執筆・生成・審査・戦略立案は専任エージェントが分業し、**生成→審査→修正**を通してから成果物が出ます。
調査・診断・作業報告は統一デザインの HTML レポートで届きます。

各ブランドの記憶は `knowledge/brands/<slug>/` に**区画分離**され、戦略・KPI・媒体状態・ナレッジ・ログが
1ブランドに閉じます。すべてのタスクは、まずアクティブブランドを確定してから実行されます。

## フォルダの接続（推奨）

「フォルダを追加」で業務用フォルダを接続してください。未接続でも動きますが、以下が起きます:

- ナレッジとログがセッション終了で消える
- 専門AIがプラグイン同梱の執筆規範に到達できず、デザイン審査や法規チェックの精度が落ちる

**メディア制作（背景除去・WebM化・バナー合成）を使う場合は必須**です。生成物をフル解像度で取り込むために
**専用ダウンロードフォルダ**を用意してください:

1. PC に専用フォルダを作る（例: `CoworkDrop`）
2. Chrome の設定 → ダウンロード → 保存先をそのフォルダに変更（または「保存場所を確認」を ON）
3. Cowork の「フォルダを追加」で **そのフォルダだけ** を接続する

**Downloads フォルダ本体は絶対に接続しない**でください（個人書類が丸ごと AI から見えてしまいます）。

## 安全設計

- 認証情報は扱いません。ログインは人間が行います。**Credential Guard** がパスワード・認証コード欄へのAI入力をブロック
- 変更操作はワークフローゲート（フェーズ判定・変更前記録）を通過しないと実行されません
- 送信・投稿など不可逆な送出の前は、敵対的監査 ＋ 人間承認の二段ゲート。金銭・契約系画面は **Money Watch** が検知して変更操作を停止します
- **ゼロ広告費は二重に守られます**: 安全ゲートが広告マネージャ・課金URLを遮断し、加えて KPIツリー自体が
  CAC/LTV/ROAS/CPA/広告費 等の有料指標を受け付けません。ゲートが沈黙しても有料前提が設計に混入しません
- **削除も守られます**: フォルダ一括削除・`rm -r` は人間の承認なしに実行されません

**既知の限界**（多層防御の前提 — ゲートを唯一の防御にせず、自己規律と人間承認を併用しています）:

- **安全ゲートが効くかは環境に依存します**。Cowork のバージョン・構成によっては hooks が発火しないことがあり、
  その場合は全ゲートがフェイルオープンになります。一括送出・金銭近傍・無人運用は、ゲートの発火を確認できた環境で行ってください
- ゲートは MCP ブラウザツールが対象です。**Bash 経由の直接送信（node/curl 等）は対象外**
- ゲートの実体は `memory/.workflow/` のフラグファイルで、Bash から直接操作すれば技術的に迂回できます。
  「うっかり・手順飛ばし」への防御であり、意図的な迂回への防御ではありません
- Credential Guard 等はキーワード検知の best-effort です

### 誤ブロックの開放・抑制リスト（あなたが手で編集するファイル）

ガードが安全のために止めすぎたときは、業務フォルダの `knowledge/config/` にテキストファイルを置いて調整できます
（1行1パターン・`#` はコメント・正規表現可）:

| ファイル | 効果 |
|---|---|
| `url-allowlist.txt` | URL Guard の誤ブロックを開放。**AIは代筆しません**（あなた本人が編集） |
| `money-suppress.txt` | Money Watch が平常画面に反応しすぎるときの抑制 |
| `critic-suppress.txt` | デザイン審査ゲートを通さなくてよいファイルのパターン |
