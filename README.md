# TAKUMI-CMO（匠CMO）

> *金は1円も使わない。コンテンツとブランディングで、ブランドを無双させる。*

**TAKUMI-CMO** は Claude Cowork 上で動く、**ゼロ広告費のコンテンツドリブン**なマーケティングエンジン。
1インストールで**複数ブランド**を扱い（記憶はブランドごとに分離）、1ブランドに**統合的な施策戦略**を打つ、匠のCMO。

> ✅ **v2.0.0 — 匠CMO 到達**。堅牢に検証された「Browser Worker for Claude Cowork」基盤を土台に、
> ゼロ広告費・マルチブランドのマーケティングエンジンへ作り替えました。設計の正本は [docs/command-registry.md](docs/command-registry.md)。
> **cloud Cowork 実機での `/検証 full`（FAIL 0）が配布の最終ゲート**です（[docs/開発ワークフロー.md §7](docs/開発ワークフロー.md)）。

## 世界観 — 匠の∞（無限）ループ

戦略も実行も、匠の技で磨き続ける。**上流（戦略）ループ**と**下流（実行）ループ**が、**計画**と**計測**で結ばれた ∞ 字の学習系です。

- **上流ループ（戦略・トップダウン）**：リサーチ→仮説→戦略→計画→改善。市場・競合・自社を読み、KPIツリーと施策ロードマップを組む。
- **下流ループ（実行・ボトムアップ）**：計画→リサーチ→企画→実行→計測→改善。オーガニック媒体で実行し、実測を上流へ返す。
- **∞ の交差点**：下りは *計画*（戦略→実行ブリーフ）、上りは *計測・改善*（実測KPI＋学び→再戦略）。両ループが共有する背骨が **KPIツリー**。
- 掘る（探索・収集）と鍛える（実証基準での成果物化）は、下流ループの内部動作として効きます。

**無双の芯 = ゼロ広告費**。有料出稿・課金は安全ゲートが機械的に遮断（cloud セッション時）。金を使わずに集客とブランディングを成立させます。

## セットアップ（3ステップ）

1. Cowork の **設定 → プラグイン** でこのリポジトリを marketplace として追加:
   `https://github.com/RetryYN/TAKUMI_CMO-Claude_Cowark`
2. **takumi-cmo** を有効化
3. 最初に `/セットアップ` — 運用するSNS・生成AIアカウント・素材サイトをチェックリストで回答（1回だけ。あとから変更可）

ブラウザ操作は **Claude in Chrome**（あなたの実ブラウザ）で行うため、ログイン済みのサイトがそのまま使えます。
チャットの「+」→ コネクタで Claude in Chrome を ON にしてください。

> **推奨は cloud セッション**。安全ゲート（hooks）が機械的に効くのは cloud のみです（[検証と安全設計](#検証と安全設計)）。

## 使い方 — コマンドを覚える必要はありません

普通に日本語で頼めば、Claude が適切な機能を自動で使います。コマンドは**業務ジャンルごとのまとまり（「パック」）**で、
やってほしいことは引数に自由に書けます。パック内では要望を「計画 / リサーチ / 収集 / クリエイティブ / 分析 / 掃き出し」に
振り分け、単発・一連の流れ・まるごと運用の3粒度で実行します。

| カテゴリー（パック） | 言い方の例 |
|---|---|
| /戦略 | 「戦略を立てて」「KPIツリー作って」「3C分析して」（上流ループ＝軍師 cmo-strategist が立案。ゼロ広告費で統合戦略） |
| /キャンペーン | 「キャンペーン組んで」「複数媒体を連動させて」（複数オーガニック媒体を1目標で統括） |
| /ブランド | 「ブランドを追加」「acme に切り替え」「ブランド一覧」（マルチブランドの登録・切替・一覧。記憶は区画分離） |
| /Webサイト | 「表示速度を測って」「デザイン調べて」「このLPを改善して」「徹底的に洗い出して」 |
| /コンテンツ | 「記事のアイキャッチ作って」「サムネ作って」「Geminiで画像/動画作って」「バナーにして」「WebMにして」「このビジュアルからLP」（オウンド/オーガニック制作。**有料出稿は行いません＝ゼロ広告費**） |
| /SNS運用 | 「Xの投稿ストック埋めて」「noteを書いて」（X/Instagram/Threads/TikTok/note/YouTube/LINE対応。単一媒体は /X運用 等が第一入口） |
| /リサーチ | 「競合を分析して」「トレンド調べて」（SNS/サイト/市場 — 対象に合わせて最適な調査へ振り分け） |
| /オウンドメディア | 「ブログ記事を公開して」「WordPressを更新」「記事のSEO見直し」（自社ブログ運営。**WordPress 既定**） |
| /ワーク追加 | 「dodaを追加して」— 登録 + 管理画面を初期マッピング + 専用コマンドを自動生成 |
| /セットアップ | 導入直後に1回 — 運用媒体・アカウント・素材サイト等をチェックリストで回答。済んだ質問は聞かれない |
| /カスタマイズ | 「毎朝これやって」「このやり方覚えて」— タスク登録・スキル化・好み記憶・機能ON/OFF |
| /レポート | 「今どうなってる？」「今日の作業まとめて」— 全体サマリー + 作業ログ/運用レポート（効果測定） |

はじめての方は「何ができるの？」と聞けばガイドツアー（デモ）が始まります。

> **匠CMOの中核コマンド**: **/戦略**（上流ループ＝3C→KPIツリー→施策ロードマップ）・**/キャンペーン**（複数媒体を1目標で統括）・**/ブランド**（登録・切替・一覧＝マルチブランド）。

## マルチブランド（記憶の分離）

1インストールで複数ブランドを無双させます。各ブランドの記憶は `knowledge/brands/<slug>/` に**区画分離**され、
戦略・KPI・媒体状態・ナレッジ・ログが1ブランドに閉じます。**Brand Isolation Guard**（安全ゲート）が
別ブランド区画への書き込みを機械的に遮断し、相互汚染を防ぎます（cloud セッション時）。
すべてのタスクは、まずアクティブブランドを確定してから実行されます。

> マルチブランド（`/ブランド`・区画分離・Brand Isolation Guard）と戦略層（/戦略・/キャンペーン・cmo-strategist・KPIツリー）は実装済み。設計は [docs/domain-model.md](docs/domain-model.md)。

## 何が起きるか

1. **変更操作は勝手に実行されません** — サイトへの入力・クリック等は、タスク開始手続きと「変更前状態の記録」を済ませるまでゲートがブロックします。
2. **地図が残ります** — 訪れたサイトの構造・手順は `knowledge/` に蓄積され、次回同じ業務が速くなります。
3. **成果はHTMLレポート** — 調査・診断・作業報告は統一デザインのレポートで出力（デジタル庁ダッシュボードガイドブック準拠）。
4. **成果物ごとに専門AIが分業** — レポート執筆・モックアップ生成・デザイン審査・戦略立案を専任エージェントが担当し、生成→審査→修正で品質を確保。

## 継続利用する場合（推奨）

「フォルダを追加」で業務用フォルダを接続してください。ナレッジとログがフォルダに永続化され、セッションを跨いで
引き継がれます。未接続でも動きますが、蓄積がセッション終了で消えます。

## メディア制作を使う場合（必須セットアップ）

画像・動画の生成物をフル解像度で取り込んで加工（背景除去・WebM化・バナー合成）するには**専用ダウンロードフォルダ**の
接続が必要です（2026-07-23 実機検証: Downloads→手動アップロード経由はレンダリングに失敗する）:

1. PC に専用フォルダを作る（例: `CoworkDrop`）
2. Chrome の設定 → ダウンロード → 保存先をそのフォルダに変更（または「保存場所を確認」を ON）
3. Cowork の「フォルダを追加」で **そのフォルダだけ** を接続する

**Downloads フォルダ本体は絶対に接続しない**でください（個人書類が丸ごと AI から見えてしまいます）。

## 自社カスタマイズ

執筆リファレンスは業界を問わず使えます。自社のトーン・NG表現・定型フォーマットに合わせたい場合は
`references/` 配下の該当ファイルを編集してください。コマンド / フック / テンプレートはそのまま使えます。

### 誤ブロックの開放・抑制リスト（あなたが手で編集するファイル）

ガードが安全のために止めすぎたときは、業務フォルダの `knowledge/config/` にテキストファイルを置いて調整できます
（1行1パターン・`#` はコメント・正規表現可）:

| ファイル | 効果 |
|---|---|
| `url-allowlist.txt` | URL Guard の誤ブロックを開放。**AIは代筆しません**（あなた本人が編集） |
| `money-suppress.txt` | Money Watch が平常画面に反応しすぎるときの抑制 |
| `critic-suppress.txt` | デザイン審査ゲートを通さなくてよいファイルのパターン |

## 検証と安全設計

**二層で検証します**（[docs/開発ワークフロー.md](docs/開発ワークフロー.md)）:

- **Tier 1（機械・毎コミット・CI）**: `scripts/lint.py`（参照整合）/ `python3 -m unittest`（ドメインモデル）/ `scripts/test-hooks.sh`（hookロジック）/ shellcheck。GitHub Actions が push[main] と全 PR で実行。
- **Tier 2（実機・節目・cloud Cowork）**: `/検証`（takumi-verify）を cloud セッションで実行し、hook の実配線・コマンド経路・エージェント起動・ブランド分離を実測。ユーザーが実行 → PASS/FAIL を開発側へ貼り戻す往復で確定。

安全設計:

- 認証情報は扱いません。ログインは人間が行います。**Credential Guard**: パスワード・認証コード欄へのAI入力を hook がブロック。
- 変更操作はワークフローゲート（フェーズ判定・変更前記録）を通過しないと実行されません。
- 送信・投稿など不可逆な送出の前は pre-send-verifier（敵対的監査）＋ 人間承認の二段ゲート。金銭・契約系画面は **Money Watch** が検知して変更操作を停止します。
- **ゼロ広告費は二重に守られます**: hook（**ゼロ課金ゲート**が広告マネージャ・課金URLを deny）に加え、ドメイン層でも
  KPIツリーが CAC/LTV/ROAS/CPA/広告費 等の有料指標を受け付けません（`takumi/domain/kpi_tree.py`）。hook が沈黙しても有料前提が設計に混入しません。
- **ブランドの混線も二重**: hook（**Brand Isolation Guard** が非アクティブ区画への書き込みを deny）＋ 区画パスの境界判定（`BrandPartition`）。
- **既知の限界（多層防御の前提）**:
  - **安全ゲートが機械強制されるのは cloud セッションのみ。ローカル Cowork では hooks が未配線（フェイルオープン。escalations E4）**。さらに Cowork のバージョン・構成によって plugin hooks が発火しない上流報告もあるため、**hooks を唯一の防御にせず、自己規律＋人間承認と併用**します。ゲート依存の運用（一括送出・金銭近傍・無人運用・ブランド分離）は cloud で行い、Tier 2 検証で実際の発火を確認してください。
  - ゲートは MCP ブラウザツールが対象。**Bash 経由の直接送信（node/curl 等）はゲート対象外**。
  - ゲートの実体は `memory/.workflow/` のフラグファイルで、Bash から直接操作すれば技術的に迂回可能。「うっかり・手順飛ばし」への防御であり、意図的迂回への防御ではありません。
  - Credential Guard 等はキーワード検知の best-effort。硬い防御は Money Watch・URL Guard・人間承認が担います。
- Cowork の実行仕様と上流の既知課題は [docs/cowork-runtime.md](docs/cowork-runtime.md) / [docs/escalations.md](docs/escalations.md)、検証状況は [TESTING.md](TESTING.md) を参照。
