# 指標設計スキル

**計測は目的ではない。** 指標は意思決定を変えるために置く。
このスキルは「何を測るか」を決めるためのもので、「どう測るか」は `gtm-jp` / `ga4-jp` / `search-console-jp` が担う。

## 0. 最初の関門 — この数字は誰の、どの判断を変えるか

新しい指標を提案されたら、実装より前にこれを聞く。

> **この数字が動いたとき、我々は何を変えるのか。**

答えられないなら**その指標は作らない。** 測れることは作る理由にならない。
使われない指標はダッシュボードを埋め、上限を消費し、レビューの時間を奪い、**「見ている」という誤った安心を生む**。

---

## 1. 設計の順序 — 目標 → 兆候 → 指標

**取れるデータから指標を決めるのが、最も多い失敗である。**
GA4 に何があるかを見てから KPI を決めると、計測できるものだけが目標になる。順序は逆にする。

1. **目標（Goal）** — 何を達成したいのか。広い言葉でよい（「読者が自分ごととして受け取る」）
2. **兆候（Signal）** — 目標に近づいたとき、ユーザーの行動として何が観測されるか（「最後まで読む」「共有する」「指名で再訪する」）
3. **指標（Metric）** — その兆候を数える具体的な定義（「読了率（90%スクロール到達 ÷ セッション）」）

Google の HEART フレームワーク（Rodden, Hutchinson, Fu / CHI 2010）は、
「**製品の目標を指標へ対応づけるプロセス**」を伴う点が本体である。カテゴリ名だけ借りても意味がない。

HEART の5カテゴリ: **Happiness / Engagement / Adoption / Retention / Task Success**。
**全部を使おうとしない。** 施策ごとに1〜2カテゴリへ絞る。

匠CMO の文脈での対応:

| カテゴリ | オーガニック施策での兆候の例 |
|---|---|
| Happiness | 好意的な言及・返信の質・NPS 的な直接の声 |
| Engagement | 読了率・視聴維持・保存/共有・回遊 |
| Adoption | 新規の初回接触（新規セッション・新規フォロー） |
| Retention | 再訪率・**指名検索の継続**・購読の継続 |
| Task Success | 目標到達プロセスの完了率・フォームの離脱率 |

---

## 2. 北極星指標は「短期に測れて、長期を予測する」もの

実験科学の側では **OEC（Overall Evaluation Criterion）** と呼ばれる。要件は2つ:

- **短期に測れる**（週次で動く）
- **長期の目標を予測する**（それが上がれば、半年後の成果も上がっている）

**片方だけでは失格。** 長期の成果そのもの（売上）は測れるが遅すぎて舵が切れない。
短期に動く数字（PV）は測れるが、長期を予測しない。

OEC の考え方では、**複数の目的を1つに重み付けして統合する**ことが望ましいとされる。
トレードオフが明示的になり、組織の判断が揃い、一貫した意思決定ができるため。
（例: メール施策なら「期待収益 － 配信停止による損失」）

**根に置く指標は1つ。** 2つ置くと、対立したときに誰も決められない。

> ゼロ広告費の制約により、根に **CAC / LTV / ROAS / CPA / 広告費**は置けない。
> `takumi/domain/kpi_tree.py` がこれを機械強制しており、該当語を含むノード名は `ValueError` になる。

## 3. 先行指標と遅行指標

| | 性質 | 使い道 |
|---|---|---|
| **遅行指標（LAGGING）** | 成果に近い。遅れて動く。打ち手から遠い | 成否の判定。振り返り |
| **先行指標（LEADING）** | 打ち手に近い。早く動く。介入できる | **日々の舵取り。** ここを動かしに行く |

**遅行指標だけの KPIツリーは運転できない。** バックミラーだけで運転するのと同じ。
逆に**先行指標だけだと、成果につながっているかが永久に分からない**。両方を親子で繋ぐ。

繋ぎ方は「**この先行指標が上がると、この遅行指標が上がると考える理由**」を1文で書けること。
書けないなら、それは親子ではなく**ただ並んでいるだけ**である。

`takumi/domain/kpi_tree.py` の `KpiKind` が `LEADING` / `LAGGING` を表す。ノードには必ずどちらかを付ける。

## 4. ガードレール指標 — 最適化の巻き添えを検知する

**一つの指標を最適化すると、必ず何かが犠牲になる。**
OEC の運用では、これを防ぐために**ガードレール指標**を別に置く。目標にはせず、**閾値を割ったら止める**ために監視する。

匠CMO で置くべきガードレール:

| 最適化するもの | 犠牲になりうるもの（＝ガードレール） |
|---|---|
| 投稿数・公開本数 | 1本あたりの読了率・エンゲージメント率（薄い量産の検知） |
| 流入数 | 直帰的な行動の増加・キーエベント率の低下（釣りタイトルの検知） |
| 短期の CV 率 | 指名検索・再訪率（刈り取りに寄りすぎて認知が枯れる） |
| 表示速度・実装量 | 表現の法令適合（→ `ad-compliance-jp`）・誤情報の混入 |

**ガードレールは目標にしない。** 目標にした瞬間、それも最適化対象になって同じ問題が起きる。

**OEC とガードレール以外の指標を大量に眺めると、判断にバイアスが入る**（たまたま動いた数字を根拠にしてしまう）。
見る指標は事前に決めておく。

## 5. グッドハートの法則 — 指標を目標にすると、指標は壊れる

> **Goodhart (1975)**: "Any observed statistical regularity will tend to collapse once pressure is placed upon it for control purposes."
> （統制目的で圧力が加えられると、観測された統計的規則性は崩壊する傾向がある）

> **Strathern (1997)**: "When a measure becomes a target, it ceases to be a good measure."
> （指標が目標になると、それは良い指標ではなくなる）

**これは人の悪意の話ではない。** 目標にした時点で構造的にそうなる。起きることは3つ:

1. **行動の歪曲** — 目的ではなく指標の改善に焦点が移る
2. **腐敗圧力** — 数値目標が、操作や見せかけの達成を招く
3. **本質的機能の喪失** — 実態を把握できなくなり、意思決定の信頼性が落ちる

### 対策（このスキルの中核）

- **目標にする指標を最小限にする。** 北極星1つ＋その直下の数個まで。残りは「監視」であって「目標」ではない
- **対の指標を必ず置く**（量の指標には質の指標を、獲得の指標には維持の指標を）
- **比率で持つ**（後述）。絶対値は水増ししやすい
- **質的な観察を併存させる。** 実際の投稿・実際の問い合わせ文面・実際の検索クエリを読む。
  複数の観察に基づく質的データは**操作しにくい**
- **代理指標であることを忘れない。** 読了率は「伝わったこと」そのものではない。
  代理指標を目標にすると、代理指標の改善だけが起きる

## 6. 指名検索とシェア・オブ・サーチ — ゼロ広告費における最重要の先行指標

広告を出さないなら、**認知の伸びを測る手段が限られる**。ここで効くのが**ブランド名での検索**である。

**シェア・オブ・サーチ**（Les Binet / IPA, 2020）:

```
自社ブランドの検索数 ÷ カテゴリ内の全ブランドの検索数
```

- データ源は **Google トレンド**。**無料**で、**2004年以降**、**週次**で取れる
- **有料検索のシェアではなく、オーガニック検索クエリのシェア**である
- **市場シェアの先行指標**として機能する（上がれば市場シェアが上がり、下がれば下がる）。
  **最大1年ほど先行**する。リードタイムはカテゴリによって異なる
- 自動車・エネルギー・携帯端末など複数カテゴリで市場シェアとの相関が報告されている

**なぜ匠CMO の主柱なのか。** 動画・SNS・記事の認知施策は、ラストクリック帰属では永久に評価されない（→ `ga4-jp`）。
シェア・オブ・サーチは**認知の総量を、CV を経由せずに測れる**。包囲網の効果はここに出る。

### Google トレンドを使うときの必須の注意（一次情報で確認済み）

- 値は **0〜100 に正規化された相対値**。各データポイントは対象地域・期間の検索総数で割られ、
  全トピックの総検索数に対する割合でスケールされる。**絶対的な検索回数ではない**
- **サンプルに基づく**（1日数十億件の検索から1サンプル）
- 地域が違えば、同じ「100」でも実際の検索ボリュームは同じとは限らない
- **検索ボリュームの小さいキーワードは「0」と表示される**
- **低ボリュームでは、実際の関心ではなく統計的ノイズを反映していることがある**

したがって:

- **単月の上下で判断しない。** 移動平均・四半期のトレンドで見る
- **必ず競合を含めた比率で見る**（自社単独の 0〜100 は市場全体の季節変動と区別できない）
- **表記ゆれをまとめる**（正式名・カナ・英字・略称）。まとめないと過小評価する
- ブランド名が一般語と衝突する場合は使えない。**この場合は Search Console のブランドクエリで代替する**（→ `search-console-jp`）

## 7. 虚栄の指標を見分ける4つの問い

1. **下がることがあるか。** 累計値（累計PV・累計フォロワー）は下がらない。**下がらない数字は判断に使えない**
2. **母数が変わっても意味が保たれるか。** 保たれないなら比率にする
3. **打ち手と結び付いているか。** 何をすれば動くのかが言えないなら、それは天気予報であって指標ではない
4. **悪い数字が出たときに報告されるか。** 報告されない指標は、機能していない

**インプレッション・PV・フォロワー数は、単独では虚栄の指標。** 分母か対比を伴って初めて指標になる。

---

## 8. 比率で持つ — 絶対値の罠

**絶対値を KPI に置かない。** 理由は3つあり、いずれも構造的なものである。

- **GA4 のセッション数は推定値**（HLL++）。1〜2件の差に意味はない（→ `ga4-jp`）
- **データのしきい値**で行が消えることがある。絶対値だと「減った」と誤読する
- **外部流入は必ず過小評価される。** アプリ内ブラウザ・DM 転送・コピペ共有では referrer が落ちる

比率で持てば、これらの誤差が分子と分母で相殺される方向に働き、**トレンドの判断が壊れにくい**。

| 絶対値（避ける） | 比率（推奨） |
|---|---|
| AI 経由セッション数 | 全流入に占める AI 経由の**構成比** |
| キーイベント数 | **セッションのキーイベント率** |
| ブランド検索数 | **シェア・オブ・サーチ**（カテゴリ内比率） |
| 動画再生数 | **視聴維持率**・保存率 |

**例外**: 実数を報告する場面はある（成果報告の確定数）。
その場合も **outcome-verifier が証跡で確定させた数だけ**を成果として数える。

## 9. 指標定義書 — 1指標1行で書き切る

指標は**定義を書いた時点で初めて存在する**。同じ名前で違う計算をしている状態が、最も高くつく負債になる。

ブランド区画（`knowledge/brands/<slug>/`）に、次の項目をすべて埋めて置く。

| 項目 | 書くこと |
|---|---|
| **名前** | 略称を使わない。「CVR」ではなく「セッションのキーイベント率」 |
| **定義（計算式）** | 分子と分母を明示。「90%スクロール到達イベント ÷ 記事詳細のセッション」 |
| **データ源** | どのツールのどの画面・どのレポートか（GA4 探索 / GSC / Google トレンド） |
| **更新頻度** | 週次・月次。**取りに行く曜日**まで決める |
| **種別** | 先行 / 遅行 / **ガードレール** |
| **目標か監視か** | 目標にするのは最小限。残りは監視 |
| **誰のどの判断を変えるか** | §0 の問いへの答え。空欄なら削除候補 |
| **既知の歪み** | 「referrer 落ちで過小」「しきい値で消えることがある」「Trends は相対値」 |

**「既知の歪み」を書くのがこの表の要である。** 歪みを知らずに見た数字は、知らないまま意思決定を汚染する。

## 10. KPIツリーの組み方

```
根   = 北極星指標（1つだけ・遅行）
枝   = 中間の成果（遅行）
葉   = 先行指標（打ち手に直結）
```

**規律:**

- **葉は必ず、実行できる手順書に紐づく。** どのコマンドの、どの作業が動かすのかを書く。
  紐づかない葉は「願望」であって指標ではない
- **親子には因果の仮説がある。** 「この葉が上がれば、この枝が上がる」と言える理由を1文で持つ。
  データドリブンとは、仮説なしに数字を並べることではない
- **深さは3層まで。** それ以上は運用されない
- **ゼロ広告費の制約は機械強制。** 有料指標（CAC / LTV / ROAS / CPA / CPC / CPM / 広告費 / 出稿 / 入札）は
  `KpiNode` の生成時に `ValueError` で弾かれる
- **ノードの新設は `docs/parts/pre-setup-council.md` の合議を通す。**
  指標の定義は後から変えると過去と比較できなくなる — 戻すのが高くつく典型

### 匠CMO の標準形（出発点。ブランドごとに書き換える）

| 層 | ノード | 種別 |
|---|---|---|
| 根 | 指名検索のシェア（シェア・オブ・サーチ） | 遅行 |
| 枝 | オーガニック流入の構成比 | 遅行 |
| 枝 | 想起の質（再訪率・購読継続率） | 遅行 |
| 葉 | 公開本数 × 読了率（薄い量産のガードレール付き） | 先行 |
| 葉 | モダリティ被覆率（テキスト/画像/動画が揃った施策の割合） | 先行 |
| 葉 | 検索での表示回数と平均掲載順位（→ `search-console-jp`） | 先行 |
| 葉 | セッションのキーイベント率（チャネル別） | 先行 |

## 11. 指標を増やすときのコスト（追加は無料ではない）

- **GA4 のカスタムディメンションには上限がある**（イベントスコープ50・ユーザースコープ25 等）
- **削除しても48時間は同名で作り直せない**
- **カーディナリティを上げると `(other)` に落ちる**
- **登録から24〜48時間はレポートに出ない**
- レビューの時間は有限。**指標が20個あるダッシュボードは、誰も見ていないダッシュボードである**

**1つ足すなら1つ落とす。** これを既定の運用にする。

## 12. 見直しの周期

| 周期 | やること |
|---|---|
| 週次 | 数字を取る。**歪みの兆候**（急な断絶・0 の出現・(other) の増加）を見る |
| 月次 | ガードレールが割れていないかを確認 |
| 四半期 | **指標の棚卸し。** 使われていない指標を落とす。定義のずれを直す |
| 施策の節目 | 親子の因果仮説が今も成り立つかを問い直す |

**指標を変えたら、変えた日を記録する。** 記録がないと、断絶をトレンドの変化と誤読する。

---

## 13. よくある失敗

| 失敗 | 直し方 |
|---|---|
| 取れるデータから KPI を決めた | 目標 → 兆候 → 指標 の順に戻す |
| 北極星が2つある | 1つに絞る。対立したときに決められない |
| 遅行指標しかない | 打ち手に直結する葉を足す |
| 先行指標しかない | 成果につながる枝を足し、因果の仮説を書く |
| 数値目標を置いたら数字だけ良くなった | グッドハート。対の指標を置き、質的な観察を併存させる |
| 累計フォロワー数を KPI にしている | 下がらない数字。比率か増減に変える |
| ダッシュボードに20指標並んでいる | 四半期の棚卸し。1つ足すなら1つ落とす |
| 同じ名前で人によって計算が違う | 指標定義書（§9）を書く。分子と分母を明示 |
| 単月の Trends の上下で施策を止めた | 相対値・サンプル・ノイズ。移動平均と競合比で見る |
| 動画施策の CV がゼロなので打ち切った | ラストクリックの構造。シェア・オブ・サーチと先行指標で見る |
