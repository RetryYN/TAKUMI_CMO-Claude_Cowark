# GA4 設定・分析スキル

GA4 は「**設定した分しか測れない**」。計測されていないものは後から遡って取れない。
だから**設定編を先に済ませ、分析編はそのデータを読む**という順序になる。

## 安全境界

| 操作 | 可否 | 理由 |
|---|---|---|
| レポート・探索の閲覧とデータ取得 | ✅ 自律可 | 読み取り |
| **探索の新規作成** | ✅ 自律可 | 既存の探索を**上書きしない**。名前に `-takumi` を付ける |
| **キーイベントの追加** | ✅ 自律可 | 追加は影響が閉じている。**既存キーイベントの解除は承認必須**（レポートと連携先に波及） |
| **カスタムディメンション/指標の追加** | ⚠️ 上限に注意 | 上限あり・**削除すると48時間は同名で作り直せない**。追加前に既存を棚卸しする |
| **カスタムチャネルグループの作成** | ⚠️ 事前説明 | 過去データに遡って再処理される。レポートの見え方が変わるのでユーザーに先に伝える |
| **データ保持設定の変更** | 🚫 **禁止** | **期限切れで消えたデータは二度と戻らない。** 変更提案は人間へ |
| **データフィルター（内部トラフィック除外等）の有効化** | 🚫 承認必須 | 誤設定で本番の計測が丸ごと欠落する。テストモードで検証してから人間が有効化 |
| プロパティ・データストリームの削除 / ユーザー権限の変更 | 🚫 禁止 | 復旧不能 |
| Google 広告アカウントとのリンク | 🚫 禁止 | 有料出稿の導線（ゼロ広告費に反する） |
| **PII を含むデータの送信** | 🚫 **禁止** | 下記 |

## PII — 送らない、それだけ

Google 契約上の **PII の定義は「それ単体で個人の特定、個人への接触、個人の所在地の特定を可能にするもの」**。

- **含まれる**: メールアドレス / 住所 / 電話番号 / 高精度位置情報（GPS 座標）/ フルネーム / ユーザー名 / リセットできない端末固有 ID
- **含まれない**: 仮名化 Cookie ID / 仮名化広告 ID / **IP アドレス**（※ Google 契約上の定義の話。各国の法令での扱いとは別）

**最頻の混入経路は URL のクエリ文字列**（フォーム送信後・サンクスページの `?email=`）。ページパスとして記録される。
公式は「**URL パスとパラメータのいずれにも**個人情報が含まれていないことを確認」するよう明記している。

対策は3つだけ:

1. **`gtm-jp` のプレビューで送信パラメータを目視**する
2. **データ除去機能**（メールアドレスの削除・指定クエリパラメータの削除）に `email` `mail` `tel` `phone` `name` `uid` `token` を登録する
3. ログインユーザーを追うなら **User-ID に個人を特定できない自前の一意 ID** を渡す（メールアドレスやそのハッシュを ID にしない）

> **未確認**: 「違反するとプロパティのデータが全削除される」は公式2ページのどちらにも措置の記載がない。
> **措置の程度を根拠にしない。** 送ってしまうと取り消せないことが根拠である。

# 設定編

## 1. 拡張計測機能 — まず何が既に取れているかを確認する

管理 → データストリーム → 該当ストリーム → **拡張計測機能**のスイッチ。
個別のオンオフは歯車アイコン。**タグを作る前にここを見る。** 既に自動で取れているものを二重実装する事故が一番多い。

| 計測項目 | イベント名 | 発火条件 | 主なパラメータ |
|---|---|---|---|
| ページビュー | `page_view` | ページが読み込まれるたび、または閲覧履歴のステータスが変更されるたび | `page_location` / `page_referrer` |
| スクロール数 | `scroll` | ページの**最下部（90%）まで初めて**スクロール | `engagement_time_msec` |
| 離脱クリック | `click` | 別ドメインへのリンクをクリック（クロスドメイン測定対象外の場合） | `link_classes` / `link_domain` / `link_id` / `link_url` / `outbound` |
| サイト内検索 | `view_search_results` | URL に検索パラメータ（`q` `s` `search` 等）が含まれる | `search_term` / `unique_search_term` |
| 動画エンゲージメント | `video_start` / `video_progress` / `video_complete` | YouTube 埋め込み動画の再生・進捗・終了 | `video_title` / `video_url` / `video_percent` / `video_duration` / `video_provider` / `visible` |
| ファイルのダウンロード | `file_download` | pdf・docx・xlsx 等の拡張子のリンクをクリック | `file_extension` / `file_name` / `link_text` / `link_url` |
| フォームの操作 | `form_start` / `form_submit` | フォームの初回操作時・送信時 | `form_id` / `form_name` / `form_destination` / `form_submit_text` |

**ページビューの収集はオフにできない。** 他は個別に無効化できる。

**注意**: 拡張計測機能の `scroll` は **90% 到達の1回だけ**。
読了率を段階で測りたい（25/50/75/90）なら **GTM のスクロール距離トリガー**で自前のイベントを作る（→ `gtm-jp`）。

## 2. キーイベント（旧コンバージョン）

**ビジネスの成果にとって特に重要なアクションを測定するイベント。**
イベントにキーイベントとしてマークを付けると、その実行ユーザー数を確認できるようになる。

- 対象のイベントが**一度でも発生していないと一覧に出てこない**。先に GTM 側で発火させ、DebugView で確認してから設定する
- 関連する指標: **キーイベント数**、**セッションのキーイベント率**
- **既存のキーイベントを解除しない。** レポートと連携先に波及する

> **未確認**: キーイベント数の上限・解除後のデータの扱いは公式ヘルプで確認できなかった。実機で確認すること。

## 3. カスタムディメンション / カスタム指標

**イベントパラメータは、ここに登録しないとレポートで使えない。** GTM でパラメータを送っただけでは見えない。

| スコープ | 何を見るか | 標準プロパティ | 360 |
|---|---|---|---|
| ユーザー | カスタムユーザープロパティ | 25 | 100 |
| イベント | カスタムイベントパラメータ | 50 | 125 |
| アイテム | 商品の色・サイズ等（EC） | 10 | 25 |
| カスタム指標 | イベントパラメータの数値 | 50 | 125 |
| 計算指標 | — | 5 | 50 |

**運用上の必須事項:**

- 登録から**24〜48時間後**にレポート・データ探索で使えるようになる。**当日に見えなくても壊れていない**
- 削除すると**48時間経過しないと同じディメンションを追加できない**
- **カーディナリティ（値の種類数）を上げない。** ユーザーごとの一意 ID・セッション ID・タイムスタンプを送ると、
  レポートとデータ探索に悪影響が出て、データが **`(other)` 行に集約される**
- 上限があるので、**KPIツリーのノードに紐づかないパラメータは登録しない**

## 4. チャネルグループ

**既定のチャネルグループは18種**: アフィリエイト / オーディオ / クロスネットワーク / ノーリファラー / ディスプレイ / メール /
モバイルのプッシュ通知 / オーガニック検索 / オーガニック ショッピング / オーガニック ソーシャル / オーガニック動画 /
その他（有料）/ 有料検索 / 有料ショッピング / 有料ソーシャル / 有料動画 / 参照 / SMS。

そのまま使える公式定義:

- **オーガニック ソーシャル**: 参照元がソーシャルサイトの正規表現リストに一致、またはメディアが該当
- **参照（Referral）**: メディアが `referral` / `app` / `link` のいずれか
- **ノーリファラー（Direct 相当）**: 参照元が完全一致で `(direct)` かつメディアが `(not set)` または `(none)`

### AI アシスタント経由の流入を分けるとき

管理 → データの表示 → チャネルグループ → 新規作成。チャネル「AI Referrals」を作る:

- 条件: **参照元（Source）が正規表現に一致** — `chatgpt|openai|perplexity|claude|anthropic|gemini|copilot|edgeservices`
- **ルールの順序を Referral より上に置く。** これが最頻の失敗原因。正規表現が正しくても、Referral に先に当たれば分類されない
- サブドメイン付き（`www.perplexity.ai`）で来るので部分一致にする
- **四半期ごとに見直す**（新ドメイン・新製品が継続的に増える）

> **未確認**: 「AI Assistant チャネルが既定へ追加された」は二次情報が報じているが、
> **公式ヘルプの既定チャネル一覧では確認できなかった**。実機のプロパティに実在するか最初に確認し、
> あればカスタム側の役割を縮小してよい。無い前提で設計しておけばどちらでも壊れない。

## 5. DebugView — 設定した直後に必ず見る

デバッグモードを有効にする方法:

- **GTM のプレビューモード**（Tag Assistant）を使う ← 通常はこれ
- gtag.js: `gtag('config', 'G-XXXXXXX', { 'debug_mode':true });`（特定イベントだけなら `gtag('event', 'xyz', { 'debug_mode':true });`）
- GTM: Google タグまたは GA4 イベントタグで `debug_mode` を `true` に設定

画面の見方:

- **Seconds ストリーム**: 過去60秒のイベント。最新が一番上。**イベントを選ぶとパラメータが見られる**
- **Minutes ストリーム**: 直近30分を1分単位。円内の数字はその時刻に受信したイベント数
- **上位のイベントとユーザープロパティ**: 30分間の上位イベントと現在のデバイスのユーザープロパティ
- 左上の**「デバッグに使用するデバイス」**で対象デバイスを切り替える

**「GTM で発火した」と「GA4 に届いた」は別。** DebugView で届いたことを確認して初めて設定完了。

# 分析編

## レポートと探索の使い分け

| | 用途 |
|---|---|
| **レポート**（左メニュー） | 定型の把握。集客・エンゲージメント・収益化。週次で同じ数字を追うのはここ |
| **探索**（データ探索） | 自由な切り口での分析。ディメンションと指標を自分で組む |

## 探索の7手法

| 手法 | 何を分析するか |
|---|---|
| **自由形式** | 使い慣れたクロス集計表の形式でデータを探索。棒グラフ・円グラフ・折れ線・散布図・地域マップに対応 |
| **目標到達プロセス** | タスクを完了するまでのステップを視覚化。どこで落ちているかを見る |
| **経路** | ユーザーがどのような経緯でアクセスしているかを視覚的に表示 |
| **セグメントの重複** | 異なるユーザーセグメントの関係。複雑な条件を満たす新規セグメントを特定できる |
| **ユーザーエクスプローラ** | セグメントを構成する個々のユーザーの行動を詳細に見る |
| **コホート** | 共通の属性を持つユーザーグループの行動とパフォーマンス |
| **ユーザーのライフタイム** | ライフタイムバリューの評価 |

**画面構成**: 左の**変数**パネルでディメンション・指標・セグメント・期間を選び、**タブの設定**で手法と配置を決める。
ディメンションは「内訳」、指標は「値」に置く。

## 指標の定義（誤読を防ぐ）

- **セッション**: ユーザーがサイトを操作する時間。**既定30分間操作がないとタイムアウト**（ウェブは管理画面で調整可）
- **セッション数は推定値**。ユニークセッション ID の数を **HyperLogLog++（HLL++）** で推定している（2021年10月以降）。
  **小数点以下や1〜2件の差を追いかけない**
- **エンゲージメントのあったセッション数**・**エンゲージメントセッション数（1アクティブユーザーあたり）** も推定値に基づく

## アトリビューション — ここを理解しないと SNS の評価を間違える

GA4 のモデルは3つ:

| モデル | 割り当て方 |
|---|---|
| **データドリブン** | 機械学習で各アカウント・各キーイベントのデータから貢献度を計算。経路の時間経過・デバイス種別・インタラクション数・クリエイティブ種別を考慮し、反事実的手法で実際の結果と起こり得た結果を比較する |
| **有料およびオーガニックのラストクリック** | **最後にクリックしたチャネルに全て割り当てる。** ノーリファラーは除外 |
| **Google 有料チャネル（ラストクリック）** | Google 広告の最後のクリックのみ。無ければ上にフォールバック |

**すべてのモデルで、キーイベント経路がすべてノーリファラーである場合を除き、ノーリファラー訪問はアトリビューション対象外。**

### これが意味すること（設計に直結する）

**ラストクリックでは、認知を担うモダリティは構造上いつまでも評価されない。**
ショート動画で知り、後日検索して購入したなら、CV は「オーガニック検索」に付く。動画の貢献はゼロと表示される。

したがって:

- **動画・SNS の認知施策を、CV 数だけで評価しない。** 打ち切る判断を誤る
- **データドリブンに切り替えて比較する**（複数タッチポイントに配分される）
- **先行指標を KPIツリーの別ノードに置く** — 到達（インプレッション・視聴）／エンゲージメント／指名検索数（→ `search-console-jp`）
- 「ラストクリックで見た数字」と「データドリブンで見た数字」の**両方を並べて報告する**。片方だけ出すと必ず誤った意思決定になる

> 公式ヘルプの記載: ルックバックウィンドウはキーイベントで既定90日（エンゲージメント指標のヘルプ）。
> アトリビューションのヘルプには「コンバージョン発生から最長7日間」の再アトリビューション期間の記載がある。
> **この2つは別の話なので、実機のアトリビューション設定画面で現在値を確認してから設計に入れること。**

## データのしきい値 — 数字が消えることがある

- **ユーザー属性データを含むレポート・データ探索・API 呼び出し**、および検索語句情報でユーザー数が不十分な場合に適用される
- 適用されると**行が除外される**。レポート上部の**データ品質インジケーター**にメッセージが出る
- **しきい値自体は調整できない。** 出る可能性を減らす手段は2つ:
  - **期間を広げる**（ユーザー数・イベント数が増えて表示されることがある）
  - **BigQuery へエクスポート**する（Google シグナル由来のデータは含まれない）

**週次レポートで「先週あった行が今週消えた」ときは、まずしきい値を疑う。** 施策の失敗と誤読しない。

## SNS・マルチメディア別の CV を読む手順

1. **集客 → トラフィック獲得**で「セッション参照元 / メディア」「セッション キャンペーン」ごとのキーイベントを見る
   （UTM の付け方は `gtm-jp`）
2. **探索（自由形式）**でディメンションに「セッション キャンペーン」、指標に「セッション」「キーイベント数」「セッションのキーイベント率」を置く
3. **アトリビューションをラストクリックとデータドリブンで切り替えて両方見る**
4. 認知系モダリティは**先行指標のノード**で別に評価する

# 週次で取るもの（`takumi.db` へ積む）

1. 全セッション / チャネル別セッション（オーガニック検索 / オーガニック ソーシャル / 参照 / ノーリファラー / AI Referrals）
2. チャネル別の**構成比**（絶対値ではなく比率で追う）
3. キーイベント数と**セッションのキーイベント率**（チャネル別）
4. `utm_campaign` 別のセッションとキーイベント（施策単位の評価）
5. ランディングページ別セッション — **どのコンテンツが拾われているか**（`takumi-campaign` のモダリティ設計へ返す）
6. 参照元の内訳 — 新しいドメインが出てきたらチャネル定義の正規表現の更新サイン

**絶対値を KPI にしない。** アプリ内ブラウザ・DM 転送・コピペ共有では referrer が落ちるため、
外部流入は仕組み上必ず過小評価される。**構成比とトレンドで見る。**

# よくある事故と回避

| 事故 | 回避 |
|---|---|
| GTM でパラメータを送ったのにレポートに出ない | **カスタムディメンションに登録**する。登録後**24〜48時間**待つ |
| 登録した直後に見えないので設定をやり直した | 24〜48時間待つ。やり直すと削除後48時間ロックに引っかかる |
| ディメンションの中身が `(other)` ばかり | カーディナリティが高すぎる。一意 ID・タイムスタンプをパラメータに送らない |
| カスタムチャネルを作ったのに AI が Referral のまま | **ルールの順序**を Referral より上に。正規表現より順序を先に疑う |
| 動画施策の CV がゼロなので打ち切った | ラストクリックの構造。**データドリブンと先行指標で見る** |
| 先週あった行が消えた | **データのしきい値**。期間を広げて確認 |
| セッション数が集計と微妙に合わない | HLL++ による推定値。**1〜2件の差を追わない** |
| 拡張計測機能と同じイベントを GTM で二重実装 | 実装前に拡張計測機能の一覧を確認する |
| 数字が去年と比べられない | データ保持設定は触らない |
