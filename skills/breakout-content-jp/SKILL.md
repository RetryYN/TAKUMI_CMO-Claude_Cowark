# 伸びるコンテンツの構造

**「良い記事を書けば読まれる」は嘘。** 読まれるには、**配信され**、**選ばれ**、**最後まで見られ**、
**誰かの行動を引き起こす**必要がある。4つは別の問題で、それぞれ別の作りが要る。

> **ゼロ広告費との関係**: 広告は「配信」を金で買う。買えない以上、**配信の仕組みに選ばれる形**を
> 作るしかない。ここは運ではなく、公開されている仕様に沿った設計の問題。

## 0. 伸びない原因を4つに切り分ける

「伸びなかった」で終わらせない。**どこで落ちたかで打ち手が全く違う。**

| 段階 | 見る数字 | 落ちていたら |
|---|---|---|
| **① 配信されたか** | 表示回数・インプレッション | テーマか形式が、その場に合っていない |
| **② 選ばれたか** | クリック率・保存率 | タイトル／サムネイル／冒頭が弱い |
| **③ 最後まで見られたか** | 読了率・視聴維持率・滞在 | 中身が期待に応えていない |
| **④ 動いたか** | 保存・共有・引用・キーイベント | 持ち帰るものが無い |

**①が出ていないのに②を直すのは無意味。** 必ず上から見る。

## 1. 配信の仕組みに選ばれる（一次情報）

### YouTube（公式ヘルプで確認済み）

- おすすめは「**視聴者が見ている動画／見ていない動画／検索した動画／高評価と低評価／興味なし**」のフィードバックを考慮する
- 「視聴者のエンゲージメントは、**絶対的な総再生時間と相対的な総再生時間**を指標」として判断される
- **クリック率の実測レンジ**: 「**YouTube の全チャンネルと全動画の半数では、インプレッションのクリック率が 2〜10% の範囲です**」
- **CTR が高い＝良いとは限らない**: 「インプレッションと視聴回数が少ない動画のほうが、クリック率と平均視聴時間が高いこともよくあります。これらの数値が高いのは、**動画が少数の熱心な視聴者によって視聴されているため**です」
- 「動画のインプレッション数が多くなると（トップページに表示された場合など）、**クリック率が低くなるのは自然なこと**です」
- **クリックベイト禁止**: 「クリックベイトになるようなサムネイルやタイトルを使用してクリック率を上げようとしないでください」
- 公式が挙げる打ち手: 「**動画の内容を的確に表した、魅力的なタイトルを付けましょう**」／「**視聴者維持率**から、視聴者が動画を楽しんで視聴している時間を把握し、それに応じてコンテンツを調整できます」／**常に新しいトピックや形式を試す**
- 伸びない原因として公式が挙げるもの: 視聴者が他の動画を多く見ている／YouTube 利用時間の減少／**アップロード頻度が通常より少ない**／トピックの人気低下／過去の高パフォーマンス動画の視聴者が戻ってこない

**実務上の読み替え（重要）**:

1. **CTR は 2〜10% が半数のレンジ。** これを外れて低いなら②の問題、極端に高いのに伸びていないなら**露出が狭い**（①の問題）
2. **CTR を上げること自体を目的にしない。** 露出が広がれば下がるのが自然で、**クリックベイトは公式に否定されている**
3. **相対的な総再生時間**が効く＝「他の選択肢と比べてどうか」の勝負。**尺を短くして維持率を上げる**のは正当な打ち手
4. **投稿頻度の低下が伸び悩みの原因**として公式に挙がっている＝**続けること自体が配信要因**

### 検索（→ `skills/seo-jp` が正本）

検索は**時間が経つほど積み上がる**唯一の配信面。一過性の話題より、**長く問われ続ける問い**に答える。

### その他のプラットフォーム

**【未確認】** TikTok / Instagram / X のレコメンド仕様は、公式ヘルプの本文取得に失敗している
（TikTok はサポートページの本文が空、X は HTTP 403）。**媒体別の仕様は `skills/sns-jp` と各媒体手順に従い、
設計前に公式ヘルプで現行仕様を確認すること。** アルゴリズムの噂話を根拠にしない。

## 2. テーマを選ぶ — 「当たる問い」の探し方

**内容の質より、問いの選択が結果を決める。** 良い答えを、誰も気にしていない問いに書いても伸びない。

| 探し方 | 具体 | なぜ効くか |
|---|---|---|
| **顧客が実際に打った言葉** | GSC の検索クエリ・サイト内検索（→ `/匠計測`） | 実在する需要そのもの。**最も安く確実** |
| **繰り返し来る質問** | コメント・問い合わせ（→ `/匠顧客`） | 1人が聞いた＝多数が黙って困っている |
| **例外の分析** | 自社で伸びた上位2割の共通点 | **再現できる当たりの原料** |
| **不在の発見** | 競合が誰も答えていない問い | 空白は、そのまま独占できる |
| **一次情報の公開** | 自社の実測・失敗・現場の判断基準 | **他社が書けない＝非対称**（→ `skills/winning-position-jp`） |
| **常識への異議** | 業界で当然とされていることの再検証 | 意外性が引用を生む。**ただし根拠が要る** |

**「不在」と「一次情報」が最も強い。** 検索ボリュームがある問いは競合も書いており、
そこで勝つには物量が要る。**物量で勝てないなら、誰も書けないものを書く。**

## 3. 選ばれる作り（②の設計）

- **タイトルは内容を的確に表す**（公式の推奨。誇張は短期のクリックと引き換えに信頼を失う）
- **具体を1つ入れる**: 数字・固有名・期間（「3か月」「12本」「失敗した2つ」）
- **読み手の状況を名指す**: 「〜な人向け」ではなく「〜しようとして詰まったとき」
- **冒頭3行で「これは自分の話だ」と分からせる**（動画なら3秒 → `skills/video-script`）
- **サムネイル・アイキャッチは縮小表示で読めるか**を必ず確認（→ `skills/design-evidence-jp`）

**クリックベイトを使わない**のは倫理の話ではなく、**公式に否定されており、③④で必ず崩れる**から。

## 4. 最後まで見られる作り（③の設計）

- **冒頭で結論を出す。** 引っ張らない（引っ張りは離脱を生む）
- **1コンテンツ1メッセージ**（詰め込むと何も残らない）
- **中だるみに具体を置く**（事例・数字・図。抽象が続くと落ちる）
- **視聴維持率・読了率で「どこで落ちたか」を見て、その箇所を直す**（公式が挙げる打ち手）
- **短くできるなら短くする。** 相対的な総再生時間が効く以上、**薄く長いより、濃く短い**

## 5. 動く作り（④の設計）— 保存・引用・共有される理由

**シェアされるのは「良かったから」ではない。** 人が動くのは次のどれかがあるとき:

| 動機 | 作り方 |
|---|---|
| **後で使える**（保存） | 手順・チェックリスト・判断基準の表。**その場で消費して終わらない形** |
| **人に説明したい**（引用） | 1文で言い切った主張・名前をつけた概念・数字 |
| **自分の立場を示せる**（共有） | 読み手が「これ、そうなんだよ」と言える主張 |
| **誰かの役に立てる**（共有） | 特定の困りごとに正面から答えたもの |
| **意外だった**（引用） | 常識と違う事実 + **検証できる根拠** |

**「持ち帰るもの」を必ず1つ入れる。** 読んで「良い記事だった」で終わるものは、④が発生しない。

**名前をつける**のは特に効く。手順・現象・失敗パターンに名前があると、人は引用しやすくなる
（そして**その名前がブランドと結びつく** → `skills/messaging-design-jp` の柱に紐づける）。

## 6. 当たりを再現する — 1本を12本にする

**当たったら分析する。** 偶然で片付けるのが最大の損失。

1. **当たった要因を仮説にする**（→ `skills/hypothesis-design-jp`。テーマか／形式か／タイミングか／届き方か）
2. **1変数だけ変えて再現を試す**（同じテーマで形式を変える／同じ形式で隣のテーマ）
3. **2回再現したら型にする**（`skills/content-design` のパターンへ昇格）
4. **横展開する**: 1本を**モダリティ違い**（記事→動画→画像→投稿）で展開する。
   **新テーマを1本足すより、当たったテーマを4形式に広げるほうが濃い**（→ `/匠戦略` 2b）
5. **時間差で再利用する**（更新・続編・まとめ。積み上がる資産にする）

**上位2割の分析に、下位8割の改善より時間を使う。** 平均を上げる作業は、平均的な結果しか生まない。

## 7. 実験の設計 — 打席を増やすのではなく、学習速度を上げる

公式が「**常に新しいトピックや形式を試す**」を打ち手として挙げている。ただし闇雲に試さない。

- **月に1〜2本を「実験枠」にする**（既存の型で作るものとは別枠）
- **実験は1回1変数**（テーマか形式かタイミングか。同時に変えない）
- **判定基準と期間を先に決める**（→ `skills/hypothesis-design-jp` §4）
- **外れたら3つに切り分ける**（前提／因果／実行）。「効果なし」で終わらせない
- **当たった実験は §6 で型にする**

**「毎回全力で当てにいく」より「安定枠 + 実験枠」のほうが速く強くなる。**

## 8. よくある失敗

- **「伸びなかった」で終わる**（①〜④のどこで落ちたか切り分けていない）
- **CTR を上げること自体を目的にする**（露出が広がれば下がるのが自然。クリックベイトは公式に否定）
- **良い答えを、誰も気にしていない問いに書く**（内容の質より問いの選択）
- **検索ボリュームだけでテーマを選ぶ**（競合も書いており、物量勝負になる → `skills/seo-jp`）
- **当たった1本を分析せず、次の新テーマに行く**（再現できないので毎回ゼロから）
- **持ち帰るものが無い**（④が発生せず、積み上がらない）
- **平均の底上げに時間を使う**（平均的な結果しか出ない）
- **アルゴリズムの噂を根拠にする**（公式ヘルプで確認できることだけを設計の根拠にする）
