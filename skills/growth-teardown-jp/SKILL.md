# 伸びているものの分解

**「伸びてる事例を参考にする」は、やり方を間違えると最も高くつく学習になる。**

理由は3つ。**①生存者バイアス**（同じことをして伸びなかった数百件は見えない）、
**②因果の取り違え**（観測できるのは構造で、なぜ伸びたかは本人にも分からないことが多い）、
**③資源の前提の無視**（専任編集部がある会社の更新頻度を、1人で真似すれば潰れる）。

このスキルは**それでも学べる部分だけを取り出す**手順。学べるのは
**「観測できる構造」と「そこから立てられる仮説」**であって、「成功の秘訣」ではない。

> **ゼロ広告費との関係**: 伸びている大手の多くは**広告も使っている**。
> 数字だけ見て真似すると、**広告で作った結果をオーガニックで再現しようとする**ことになる。
> 分解では必ず「**この結果のうち、どこまでが金で買われたものか**」を分けて記録する。

## 0. 大原則

1. **まとめ記事の数字を根拠にしない。** 「◯◯は月間100万PV」の類は、**運営者自身の発表**に当たるまで使わない
2. **実物を開いて自分で観測する。** 記事タイトル・更新日・連載名・著者表記・導線は、**誰でも確認できる事実**
3. **観測（見えたもの）と推論（そう思った理由）を混ぜて書かない**
4. **「なぜ伸びたか」を断定しない。** 分解の出力は結論ではなく**仮説**（→ `skills/hypothesis-design-jp`）
5. **伸びていないものも見る。** 成功例だけを並べると、成功例だけが持つ特徴を見つけられない
6. **アルゴリズムの噂を根拠にしない**（→ `skills/breakout-content-jp` と同じ原則）

## 1. ベンチマーク先を選ぶ（ここで結果の8割が決まる）

**有名だから選ぶ、をやめる。** 選定基準:

| 基準 | なぜ |
|---|---|
| **自社と資源が近い**（人数・更新頻度） | 専任編集部の型は、片手間では再現できない |
| **自社と客層が近い** | 客層が違えば、効いている理由も違う |
| **観測できる情報が多い**（更新日・著者・連載が見える） | 分解できないものは分解しない |
| **運営者自身が数字を出している** | 二次情報の孫引きを避けられる |
| **1つは「伸びていない同業」も入れる** | 差分を取るため（**これが無いと生存者バイアスに落ちる**） |

**3〜5件。** 増やすほど平均化して、当たり障りのない結論になる。

## 2. 観測する（見えるものだけ書く）

実物を開き、**推測を混ぜずに**次を記録する。

| 観測項目 | 見る場所 | なぜ効くか |
|---|---|---|
| **記事・投稿タイトルを10本そのまま** | 一覧ページ | **型が出る**。要約すると型が消えるので**原文のまま** |
| **連載・カテゴリ・タグの名前** | ナビ | 単発の集合か、**続きものの構造**か |
| **直近5本の公開日** | 一覧 | **更新頻度**（週何本か。ここが資源の実体） |
| **著者表記の有無と書き方** | 記事 | 実名か・肩書きか・社員が主役か・無記名か |
| **自社商品/サービスへの導線の位置** | 本文/ヘッダ/フッタ | **本文で売っているか、売っていないか** |
| **コンセプト文** | About・タイトル下 | 何のメディアだと名乗っているか |
| **商品以外の接点** | フッタ・SNSリンク | アプリ・動画・音声・メール等、**面の広さ** |
| **運営者自身が出している数字** | プレスリリース・IR・決算資料 | **唯一信用できる数字** |

**記録の形**: `knowledge/brands/<slug>/knowledge/teardowns/<date>-<対象>.md`。
**観測**と**推論**を節で分ける。

## 3. 実際に分解した5件（一次観測・2026-07-25 時点）

**以下はすべて実物を開いて観測した事実。** 数字は運営者自身の発表のみを載せている。
**サイトは改装されるので、使う前に再観測すること**（日付を残しているのはそのため）。

### ① サイボウズ式（サイボウズ）

- 名乗り: 「**新しい価値を生み出すチームのメディア**」
- タイトルの型 = **問いと逆説**。「なぜ、一太郎はWordに喰われたのか？」「AIによる『新人不要論』は本当か？」
  「数字は『嘘をつける』──KPIがチームの協力を破壊する構造的な理由」
  「がんばれなくて、ごめん──『働かないおじさん』と思われているシニアの、言えない事情」
- 連載を10本前後持つ（カイシャ・組織／働き方・生き方／家族と仕事／防災とIT／本とはたらく 等）
- **記事一覧に著者名の表示なし**
- **自社製品への導線はヘッダ・フッタのみ。記事本文で製品を売っていない**

### ② SmartHR Mag.（SmartHR）

- 名乗り: 「**働く明日が、もっとよくなる**」
- タイトルの型 = **検索に対応した具体**。「【2026年最新版】令和8年度税制改正で年末調整はどう変わる？178万円の壁を解説」
  「休日出勤とは？違法になるケースや手当・残業代のルールを**社労士が解説**」
- **著者が実名で出る**（社労士など**資格を持つ外部の専門家**）
- 連載・カテゴリを17種
- 導線 = 「お役立ち資料」「メルマガ登録」を上部に、**機能解説とユーザーストーリーは別セクション**に分離
- 更新: 2026.07.23 / 07.22 / 07.09 / 07.08 / 07.01（**週1〜2本**）

### ③ LIGブログ（LIG）

- タイトルの型 = **具体と数量**。「【実例4選】Webディレクターのポートフォリオの作り方と見せ方のコツ」
  「同業アドバイザーが忖度なしで厳選！転職エージェントおすすめ17選」
- **著者名あり**
- 更新: 2026.07.24 / 07.23 / 07.21 / 07.17 / 07.15（**2〜4日に1本**）
- 導線 = ヘッダ・フッタ・サイドバー（Solutions / Recruit）
- 検索狙いの記事と、対談・インタビューが**同じ媒体に同居**している

### ④ mercan（メルカリ・採用広報）

- 名乗り: 「**メルカリの"いま"と"未来"を伝える**」
- タイトルの型 = **社内の出来事の実況**。「新シーズン前の恒例行事！鹿島アントラーズの選手たちがメルカリにやってきた」
  「リスペクトと変革の両立——新CHRO @kimuras が描く、AI-Nativeな組織づくり」
- **社員が主役**（アカウント名で登場）。連載はタグで持つ（「#月刊メルカリ放送室」等）
- 更新: 2026-7-24 / 7-23 / 7-17 / 7-16 / 7-10（**2〜7日に1本**）
- 導線 = 「募集中の求人一覧」「採用サイト」「Join us!!」の**3箇所**。目的が採用に一本化されている

### ⑤ 北欧、暮らしの道具店（クラシコム）

- 名乗り: 「北欧雑貨や北欧食器を中心にご紹介する**通販サイト**です」（**メディアと名乗っていない**）
- **商品ページと読みものが同一サイトに同居**。「記事」「特集」が商品カテゴリと並ぶ
- 接点の広さ: 自社アプリ／Instagram／YouTube／LINE／X／**Spotify（ポッドキャスト）**／読みもの内の4コマ漫画

**運営者自身が発表している数字**（2025年9月9日 プレスリリース）:

- アプリ「**500万ダウンロードを突破**」（2025年8月達成）
- 「**EC売上の約8割**」がアプリ経由
- Instagram「**170万**」／YouTube登録者「**100万を超える**」
- エンゲージメントアカウント総数「**1,000万を突破**」（2025年8月末時点）
- 成長の説明: 「**SNSで認知を向上することにより、高い費用対効果で新規ユーザーの獲得を可能に**」
  「**アプリのプッシュ通知によるリマインドだけではなく、SNSからの継続的な導線によって高いアプリ起動率を維持**」
- 戦略の名乗り: 「多様なジャンルの商品と多様なチャネルから集まる顧客を、**一貫した世界観でつなぐ**『マルチチャネル・マルチカテゴリ』戦略」

同社担当者のインタビュー（自社メディア掲載）では、指標について
「ひとつのKPIを追いかけているわけではありませんが、新しいユーザーが翌日も使っているか、その後も継続して使っているか**『継続率』は重視しています**」。

> **重要な注意**: 「高い費用対効果で新規ユーザーの獲得」という表現は、**費用を投じていること**を示す。
> **この事例をゼロ広告費の成功例として扱わないこと。** 転用できるのは
> 「SNS → アプリ → 継続率」という**構造**と「一貫した世界観」であって、到達した数字ではない。

## 4. 5件を並べて分かったこと（横断の観測）

**ここが分解の本体。1件ずつ見ても型は出ない。並べて初めて出る。**

### (1) 単一の「正解のタイトル型」は存在しない

- サイボウズ式・mercan = **問い / 逆説 / 出来事**（検索を狙っていない）
- SmartHR Mag.・LIGブログ = **具体 / 数量 / 法改正**（検索を狙っている）

**同じく伸びている媒体で、タイトルの型が正反対。**
つまり**目的が違えば正解が違う**。「バズるタイトルの型」を探すのは筋が悪い。
**先に決めるのは型ではなく、検索から来てほしいのか、読者に覚えてほしいのか。**

### (2) 全社が「連載・カテゴリ」を持っている（例外なし）

サイボウズ式10前後、SmartHR Mag. 17、mercan はタグ、北欧は特集。
**単発記事の集合ではなく、続きものの構造**になっている。
5件の中で唯一の例外がなかった項目がこれ。**最も転用しやすい観測**。

### (3) 更新頻度は「毎日」ではない

観測できた3件はいずれも **2〜7日に1本**（LIG 2〜4日、SmartHR 週1〜2、mercan 2〜7日）。
**毎日出すことが条件ではない**。ただし**止まってはいない**。

### (4) 著者の出し方は目的で割れる

- 検索を狙う媒体（SmartHR）は**資格を持つ外部の専門家を実名で**出す（＝**その分野で信じてよい理由**）
- 採用が目的の媒体（mercan）は**社員が主役**
- ブランド論を語る媒体（サイボウズ式）は**一覧に著者を出さない**

**著者表記は飾りではなく、何で信じてもらうかの設計。**

### (5) 本文で売っていない

サイボウズ式は導線がヘッダ・フッタのみ。SmartHR Mag. は資料請求と機能解説を**別セクションに分離**。
mercan は導線が採用に一本化。**記事の中で商品を売り込む形になっていない。**

### (6) 伸びているところほど、面が広い

北欧はアプリ・YouTube・Instagram・LINE・X・**ポッドキャスト**・4コマ漫画まで持ち、
**EC売上の約8割がアプリ経由**（運営者発表）。
**1つの媒体で完結していない**（→ `docs/parts/index.md` のモダリティ横断・`/キャンペーン` 2b）。

## 5. 観測を仮説に変える（ここをやらないと分解は無駄になる）

**観測をそのまま真似しない。** 必ずこの形に落とす（→ `skills/hypothesis-design-jp`）。

```
観測: 〈どこで・何が見えたか。原文のまま〉
差分: 〈自社と何が違うか〉
推論: 〈なぜそれが効いていると考えるか。**推論だと明記する**〉
資源: 〈自社の工数で再現できるか（→ docs/parts/capacity-plan.md）〉
仮説: 〈誰が・どんな状況で・だからこうすれば・こう変わるはず〉
外れたと分かる条件: 〈これが起きたら間違い〉
```

**「連載を持つ」のような構造の転用は、資源の確認が要る。**
連載は**続けられなければ逆効果**（放置された連載は、更新が止まった媒体に見える）。

## 6. やってはいけないこと

- **文章・構成・デザインをそのまま複製する**（著作権侵害。**型を学ぶことと複製は別**）
- **競合の記事を書き換えて自社記事にする**（→ `skills/seo-jp` の一次情報の原則に反する）
- **数字を出典なしで引用する**（「業界大手は月間◯◯PV」は、運営者発表に当たれないなら書かない）
- **相手の非公開情報を推測して事実のように書く**（売上・人数・費用）
- **「伸びている」の根拠を示さずベンチマークにする**

## 7. よくある失敗

- **有名だからという理由で選ぶ**（資源も客層も違えば、学べるものが無い）
- **まとめ記事の数字を根拠にする**（原典に当たれないものは使わない）
- **成功例だけを並べる**（生存者バイアス。**伸びていない同業を1件入れる**）
- **観測と推論を混ぜて書く**（後から検証できなくなる）
- **「なぜ伸びたか」を断定する**（本人にも分からないことが多い。出力は仮説）
- **広告を使っている結果をオーガニックで再現しようとする**（§3⑤の注意）
- **更新頻度だけ真似して潰れる**（資源の前提を無視している）
- **タイトルの型を目的抜きで真似る**（§4(1)。目的が違えば正解が正反対）
- **分解して満足する**（仮説と検証に落ちなければ、ただの読書）
