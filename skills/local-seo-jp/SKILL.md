# ローカル検索（日本市場）

**掲載順位は買えない。** Google はローカル検索について
「掲載順位の向上を要求したり、料金を支払うことはできません」と明記している。

これは、ゼロ広告費の事業にとって**唯一に近い「金で条件が並ぶ面」**である。
検索広告では予算の大きい側が上に出るが、地図の枠にはその仕組みが無い。
**広告費で負けている相手と、同じ条件で並べる場所が地図にはある。**

同時に、ここは**面ごと失える場所**でもある。Google はガイドライン違反に対して
「ビジネス プロフィールへのアクセスを停止する権利を留保する」としている。
記事は書き直せるが、停止されたプロフィールは書き直せない。
**攻めの効きが大きく、事故が不可逆** — このスキルはその両方のために存在する。

## 0. まず適用判定 — 該当しないなら丸ごと飛ばす

ローカル検索が効くのは、**顧客の現在地が結果に影響する事業**だけである。

| 該当する | 該当しない |
|---|---|
| 実店舗（飲食・美容・物販・教室・クリニック） | 全国配送のみの EC |
| 訪問型（工務店・修理・出張サービス） | オンライン完結のサービス |
| 来訪型の士業・相談業（事務所に来てもらう） | 商圏の概念が無い BtoB SaaS |
| 商圏が決まっている BtoB（地域の取引先） | — |

**該当しないブランドにこのスキルを適用しない。**
プロフィールを作ること自体が目的化すると、更新されない放置プロフィールが残り、
**古い営業時間で顧客を無駄足にする**（不正確な情報は、無いより悪い）。

## 1. 順位の3要素 — 動かせるのは2つだけ

Google はローカル検索の掲載順位が主に3つの要素で決まるとしている（一次情報）。

| 要素 | 内容 | 動かせるか |
|---|---|---|
| **関連性**（Relevance） | プロフィールが検索内容にどの程度マッチしているか | **動かせる** |
| **距離**（Distance） | 顧客の現在地からビジネスまでの距離 | **動かせない** |
| **視認性の高さ**（Prominence） | どの程度よく知られているか（サイトへのリンク数・口コミ数など） | **動かせる**（遅い） |

**距離が動かせない、という事実が戦略のすべてを決める。**

商圏の外の人にはどう頑張っても出ない。だから**商圏を広げようとするのではなく、
商圏の中で1位を取る**。これは `skills/scale-strategy-jp` の局所優勢とまったく同じ形であり、
ローカル検索は**その考え方が物理的に強制される数少ない面**である。

- 「地域名 + 業種」で全域1位を狙うのではなく、**店舗から半径◯km で確実に出る**を先に取る
- 商圏が重ならない限り、**複数店舗は互いに競合しない**（それぞれの近くの人に出る）
- 商圏内に競合が1つしか無い業種なら、**そこは事実上の指名戦**になる。最優先で取る

## 2. 掲載情報 — 「正確さ」がそのまま関連性になる

Google は「ビジネス情報を最新かつ正確に保つ」ことを掲載順位向上の対策として挙げている。
**関連性を上げる作業は、盛る作業ではなく、埋めて合わせる作業。**

| 項目 | ルール（一次情報に基づく） |
|---|---|
| **ビジネス名** | 店頭で一貫して使っている**実際の名称のみ**。キーワード・所在地・キャッチコピーを含めない |
| **プロフィール数** | **1事業につき1プロフィール**。重複させない |
| **住所 / 提供地域** | 正確な住所または提供地域。**私書箱は不可**。実際の営業拠点のみ |
| **営業時間** | 通常の顧客対応時間を掲載する。**祝日・臨時休業を先に入れる** |
| **カテゴリ** | **できるだけ少なく**。ビジネス自体を説明するものを選ぶ |
| 写真・動画 | 追加する（Google が対策として明示） |

### 名称にキーワードを足さない — 最も誘惑が強く、最も高くつく違反

「いちょう歯科」を「【渋谷駅徒歩3分】いちょう歯科 インプラント」にすると、**短期的には効いてしまう。**
だから多くの事業者がやる。だが Google のガイドラインは実際の名称のみを認め、
違反はプロフィールの停止につながる。**効いている間に依存が育ち、止まったときに面ごと失う。**

文章の注意書きでは破られるので、**機械で確かめる**:

```python
from takumi.domain.local_profile import ProfileName
ProfileName(storefront_name="いちょう歯科", listed_name="【渋谷駅徒歩3分】いちょう歯科").assert_matches_storefront()
# ValueError: 看板に無い語がプロフィール名に足されている: 【渋谷駅徒歩3分】
```

**地域名や取扱商品を出したいなら、名称ではない場所で出す** —
カテゴリ、説明、投稿、そして自社サイト側のページ（→ `skills/seo-jp`）。

## 3. 口コミ — 法規で許されても、プラットフォームで禁止されている

ここが**このスキルで最も間違えやすい点**である。

- **日本のステマ規制**は「事業者の関与を表示すれば可」というルール
- **Google のポリシー**は、**対価と引き換えの口コミそのものを認めない**

つまり**「#PR を付ければよい」では解決しない。**
Google は、無料または割引の商品・サービスなどのインセンティブを、口コミの投稿・変更・
否定的な口コミの削除と引き換えに提供することを「偽りおよび誤解を招くコンテンツ」として
**厳格に禁止**している。

さらに**利害の対立**（conflict of interest）— 現在・過去の雇用関係、契約・顧問関係にある者による
口コミは削除の対象。**社内に頼んで数を作る**のは、既存ルール（役員・管理職に好意的投稿を依頼しない）と
同じ理由でここでも禁じられる。競合先に評判を落とす投稿をするのも同様に禁止。

```python
from takumi.domain.local_profile import ReviewSolicitation, SolicitationTarget
ReviewSolicitation(target=SolicitationTarget.CUSTOMER, incentive=False).assert_allowed()  # 通る
ReviewSolicitation(target=SolicitationTarget.CUSTOMER, incentive=True).assert_allowed()   # ValueError
ReviewSolicitation(target=SolicitationTarget.EMPLOYEE, incentive=False).assert_allowed()  # ValueError
```

**対価の有無は人間が宣言する**（未申告は「問題なし」ではなく判定不能として止まる）。

### では何をしてよいか

**依頼そのものは認められている。** Google は、顧客に口コミの投稿を依頼するためのリンクや
コードを使うことを案内している。禁じられているのは**対価**であって**依頼**ではない。

1. **頼むタイミングは、満足している瞬間**（→ `skills/referral-advocacy-jp` §4 の設計に従う）
2. **定型文やハッシュタグを配らない** — 同じ文が並んだ時点で口コミとしての価値が消える
3. **断りにくい状況で頼まない**（不具合対応の直後・支払い交渉中）
4. **返信する。** Google は口コミへの返信を対策として挙げている。
   返信は書いた本人より、**それを読む第三者**に効く（→ `skills/engagement-reply-jp` が正本）
   - Google の推奨: プロフェッショナルで丁寧に／短く簡潔に／宣伝ではなく会話として
     （**返信で割引やキャンペーンを持ち出さない** — 相手はもう顧客である）
5. **低評価を消そうとしない。** 削除は制度（ポリシー違反の報告）であって交渉ではない。
   事実に反する記載の訂正依頼は可、内容を自社に都合よく改めさせる依頼は不可（既存ルール）

## 4. 視認性 — 遅いが、他の施策の副産物として積み上がる

視認性はサイトへのリンク数・口コミ数などに基づくとされる。**単独で狙う施策ではない。**

- `/広報`（Earned）で地域メディア・地域団体に載る → リンクと言及が増える
- `/オウンドメディア` の記事が読まれる → サイト自体の知名度が上がる
- 口コミが自然に増える → 視認性に効く

**「視認性のための施策」を新設しない。** 他の面をやれば付いてくる部分であり、
ここを直接狙うとリンクの購入・口コミの水増しという禁止領域に足が向く。

## 5. 測る — 直接流入に溶かさない

**プロフィールからサイトへの流入に UTM を付けないと、`(direct)` に混ざって消える。**
「マップから来た人がどれだけ問い合わせたか」が永久に分からなくなる。

1. プロフィールのウェブサイトリンクに UTM を付ける（→ `/計測`・`skills/ga4-jp`）
2. プロフィール側の指標（表示回数・経路検索・電話）と、サイト側のキーイベントを**別々に**持つ
3. **指標は1〜2個に絞り、KPIツリーのノードに紐づける**（→ `skills/channel-planning-jp`）
   - 「見つかる」の役割を担う面なので、**認知系の先行指標**として置くのが自然
4. 順位そのものを指標にしない。**距離で人によって違う**ため、1つの値として存在しない

**電話が主な問い合わせ経路の事業では、Web の数字だけ見ても実態が分からない。**
電話本数を人間が記録する枠を先に作る（→ `skills/kpi-design-jp` の「測れないものを測れるふりをしない」）。

## 6. 安全境界 — AI が何をしてよいか

| してよい | してはいけない |
|---|---|
| 掲載内容の**下書き**を作る（説明文・カテゴリ案・写真の選定案） | **プロフィールの編集・公開を AI が実行する** |
| 口コミへの**返信案**を作る | **返信を投稿する**（既存ルール: 投稿は人間） |
| 名称・住所の整合を機械で検査する | **可否の最終判断**（掲載停止のリスク評価は人間） |
| 依頼文の下書きを作る | **対価つきの依頼を設計する**（ポリシー違反） |
| ポリシー違反の口コミを**列挙**する | **削除申請を出す**・削除の可否を判断する |

- **営業時間・住所・提供地域に、確認していない値を書かない。** 誤った営業時間は顧客を無駄足にする
- **プロフィールの削除・統合は不可逆。** 重複プロフィールを見つけても、AI は報告までにとどめる
- **医療・美容医療は別法体系**（→ `skills/ad-compliance-jp` §7）。
  掲載文にも医療広告規制がかかる可能性があり、**AI はここで止めて人間・専門家に回す**

## 7. よくある失敗

- **作って放置**。営業時間が古いまま、写真が開店時のまま。**無いより悪い**
- **名称にキーワード**。効いている間に依存が育ち、停止で面ごと失う
- **口コミを「集める」施策にする**。数を目標にした瞬間、対価と社内動員に足が向く
- **全域1位を狙う**。距離は動かせないので、商圏外の順位を追っても意味が無い
- **UTM を付け忘れる**。流入が `(direct)` に溶けて、効果が永久に測れない
- **低評価に反射で反論する**。返信は第三者に読まれている（→ `skills/engagement-reply-jp`）
