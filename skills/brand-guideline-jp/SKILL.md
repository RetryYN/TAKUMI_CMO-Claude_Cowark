# ブランドの構築とレギュレーション

**ガイドラインは、作った時点では機能しない。守られて初めて機能する。**

多くのブランドガイドは「立派な PDF」で終わる。読まれず、参照されず、
**発信のたびに少しずつズレて**、1年後には別のブランドになっている。

このスキルは3つを扱う。**①決める（identity）→ ②書く（regulation）→ ③守らせる（運用）**。
**③が無いガイドラインは作らない。**

> **`skills/messaging-design-jp` との違い**: あちらは「**何を言い続けるか**」（主張）。
> ここは「**誰として、どう言うか**」（人格・見た目・言い方）と、**それを保つ仕組み**。
> **順番は messaging → brand-guideline。** 言うことが決まる前に、言い方は決められない。

> **匠CMO 固有の事情**: 発信の多くを **AI が下書きする**。
> 人間だけで運用するブランドより、**明文化されていないルールは確実に守られない**。
> **「察してほしい」が一切通用しない前提**でレギュレーションを書く（→ §4）。

## 0. 作る前に決める3つ

| 問い | 決めないと |
|---|---|
| **誰が最終判断するか** | 揺れたときに決着がつかず、都度議論になる |
| **どこまで縛るか**（厳格 / 幅を持たせる） | 縛りすぎて何も出せない／緩すぎて意味が無い |
| **どこに置き、いつ参照するか** | 読まれない（→ §4） |

**「どこまで縛るか」は、人数と媒体数で決まる。**
一人で1媒体なら軽く、複数人・複数媒体・AI併用なら厳格に。
**縛りの強さは正しさではなく、運用の現実に合わせる。**

## 1. 決める — ブランドアイデンティティ

**見た目から入らない。** ロゴや色から始めると、**何を表しているのか説明できない見た目**になる。

```markdown
## ブランドアイデンティティ（<ブランド名>）

**存在理由**: 〈なぜこのブランドが世の中にあるのか。無くなったら誰が困るか〉
**提供価値**: 〈顧客の状況がどう変わるか。機能ではなく結果〉
**人格**: 〈人だとしたら、どういう人か。3語 + それぞれ1文〉
**約束**: 〈顧客に必ず守ること。守れないことは書かない〉
**らしくないこと**: 〈このブランドが絶対にやらないこと〉
```

**「らしくないこと」が最も効く。** 何をするかより、**何をしないか**のほうが
判断の場面で使える（→ `skills/winning-position-jp` §5・`skills/messaging-design-jp` §2）。

**人格を形容詞3語で終わらせない。** 「誠実・親しみやすい・先進的」は誰でも書ける。
**それぞれに「だから、こういうときはこうする」を1文つける。**

- ✗ 「親しみやすい」
- ○ 「親しみやすい — **だから、専門用語を使うときは必ず言い換えを添える**」

## 2. 書く — レギュレーション（判断できる粒度で）

**ガイドラインの良し悪しは「迷ったときに答えが出るか」で決まる。**

### 言葉のレギュレーション

| 項目 | 決めること | 例 |
|---|---|---|
| **一人称・二人称** | 自社／読み手の呼び方 | 「当社」か「私たち」か。「お客様」か「ユーザー」か |
| **文体** | 敬体／常体、断定の強さ | 「です・ます」で統一。「〜かもしれません」を多用しない |
| **用語の統一** | 表記ゆれを潰す | 「Web / ウェブ」「お問い合わせ / お問合せ」「ユーザー / ユーザ」 |
| **数字・単位** | 半角/全角、桁区切り | 「3日」「3,000円」 |
| **記号** | 感嘆符・三点リーダ・波ダッシュの可否 | 「！は1投稿1回まで」 |
| **NG表現** | 使わない言葉 | 誇張・煽り・断定・差別的表現 |
| **絵文字** | 媒体別の可否と量 | 「LINEは可、note本文は不可」 |

**用語統一表は「対」で書く**（✗ と ○ を並べる）。**説明文だけでは守られない。**

### 表記の土台は「自分で発明しない」

漢字・仮名・句読点の一般的な基準は、**既にある公的な整理を土台にして、自社の差分だけを書く**。
ゼロから決めると、決めきれずに揺れる。

日本語の公的な整理としては、文化審議会の建議「**公用文作成の考え方**」（令和4年1月7日）がある。
**常用漢字表に基づく漢字使用**や、**横書きでは読点に「、」を用いる**（「，」ではない）
といった扱いが示されている。

> **注意**: 本スキルは**この建議の本文（PDF）を取得できていない**。
> 上記は所在と概要の確認にとどまる。**自社の表記ルールの土台に採用するなら、原典を人間が読むこと。**
> また**公用文の基準がブランドの文体に常に適合するとは限らない**
> （公用文は硬い。カジュアルなブランドならそのまま採らない判断もある）。
> **土台として何を採用したかを、レギュレーションに1行書いておく**（後任が迷わない）。

### 見た目のレギュレーション

| 項目 | 決めること | 正本 |
|---|---|---|
| ロゴ | 最小サイズ・余白・背景・**やってはいけない加工** | このスキル |
| 配色 | 主要色・補助色・**使用比率** | 具体値は `skills/design-evidence-jp` |
| タイポ | 書体・サイズ・行間・行長 | 同上 |
| 写真・図版 | 被写体・加工・明るさの方向性 | このスキル |
| 余白 | 密度の方針（高密度／低密度） | `skills/psych-ux-jp`（客層×価格帯で判断） |

**数値の正本は `skills/design-evidence-jp`。** ここで独自の数値を作らない
（本文16px以上・コントラスト比などの実証基準は既にある）。
**ブランド側が決めるのは「どの選択肢を取るか」であって、可読性の下限ではない。**

### 禁止事項は理由とセットで書く

**理由の無い禁止は、必ず破られる**（「なぜダメか分からないが、今回は特別」が起きる）。

- 「**最上級表現（No.1・最高）は根拠が無い限り使わない** — 景表法の優良誤認に当たりうるため
  （→ `skills/ad-compliance-jp` が正本）」
- 「**煽り・不安の増幅は使わない** — 心理は不安の解消に使う（session-rules (3)）」
- 「**実績数値は母数と期間を併記する** — 併記の無い数字は検証できない」

## 3. ブランド名・タグラインを決めるとき

**名前は後から変えられない。** 決める前に確認する。

| 確認 | どこで |
|---|---|
| **商標** | **J-PlatPat**（特許情報プラットフォーム。無料）で同一・類似を調べる。**必要なら弁理士へ** |
| ドメイン・各SNSのID | 実際に取得できるか |
| 既存の意味・読み | 検索して、望まない意味と結びついていないか |
| 読み間違い | 声に出して伝わるか（電話で言えるか） |
| 表記のゆれ | 英字/カナ/漢字のどれを正とするか**先に決める** |

**「先に使っていたから大丈夫」とは限らない。** 特許庁は次のように説明している:

> 「わが国では、同一又は類似の商標の出願があった場合、**その商標を先に使用していたか否かにかかわらず、
> 先に出願した者に登録を認める先願主義**という考え方を採用しています」

**つまり、名前を決めて使い始める前に調べる。** 調査は
**J-PlatPat**（工業所有権情報・研修館が提供する無料の検索・照会サイト）で行える。
特に**「称呼（類似検索）」**を使うと、**読みが類似する可能性のある商標を広く検索できる**。

**AI が商標の可否を判断しない** — 調査の結果を示し、**判断は人間（必要なら弁理士）**。
類似の判断は評価を含み、検索結果だけでは決まらない。

## 4. 守らせる — ここが本体

**「ガイドラインを読んでください」は仕組みではない。**

### (1) 参照される場所に置く

- **正本は1つ**: `knowledge/brands/<slug>/brand.yaml`（トーン・NG・配色）と
  `knowledge/brands/<slug>/strategy/brand-guideline.md`
- **制作の手順書から必ず参照させる**（`/匠発信 ▸ takumi-content`（制作物）・`takumi-website`（サイト・LP）・`takumi-ownedmedia`（記事））
- **AI に渡すときは要約でなく該当箇所の原文を渡す**（要約すると縛りが消える）

### (2) チェックできる形に落とす

**文章のガイドラインは守られない。チェックリストは守られる。**

```markdown
## 公開前チェック（<ブランド名>）
- [ ] 一人称は「〈決めた語〉」になっているか
- [ ] 用語統一表の ✗ 側が残っていないか
- [ ] 最上級・保証・断定の表現が無いか（→ ad-compliance-jp）
- [ ] 数値に母数と期間が併記されているか
- [ ] 主張が messaging.md の柱のどれかに紐づくか
- [ ] 「らしくないこと」に触れていないか
```

**このリストを、送出前の監査（`pre-send-verifier`）と公開前チェックに載せる。**

### (3) 逸脱を検出する

- **主張のドリフト**（何を言っているかのズレ）→ `docs/parts/messaging-audit.md`
- **表記・トーンのズレ** → 用語統一表で機械的に検索できる形にしておく
  （✗ 側の語を grep できるようにする）
- **周期**: 四半期に1回、直近の発信からサンプルを取って点検する

### (4) 更新の手順を決めておく

| 項目 | 周期 | 変えてよい条件 |
|---|---|---|
| 存在理由・提供価値・約束 | 年1回見直し | **事業の実態が変わったときだけ** |
| 人格・トーン | 年1回 | 顧客の受け取られ方とズレていたとき |
| 用語・表記 | 随時 | 迷いが2回発生した語は、その場で追記する |
| 見た目 | 年1回 | — |

**朝令暮改しない。** ブランドは**反復で記憶に残る**もので、
変えるたびに蓄積がゼロに戻る（→ `skills/messaging-design-jp` §5）。

**ただし用語だけは随時更新する。** 「迷いが2回出た語」を放置すると、
**ガイドラインが現場より遅れている状態**になり、参照されなくなる。

## 5. AI が下書きする前提での追加ルール

**匠CMO では発信の多くを AI が下書きする。** 人間だけの運用より縛りを具体にする。

1. **明文化されていないルールは守られない**（「察して」は通用しない）
2. **AI に渡すのは原文**（要約すると縛りが消える）
3. **人が確認していない生成物を公開しない**（→ `skills/content-ops-jp` §5）
4. **自動化の関与をどう開示するかを、ガイドラインに1項目として持つ**
   （Google は自己評価の問いに「AI による生成などの自動化を使用していることを、
   開示などの方法でユーザーに対して明確にしていますか」を挙げている → `skills/content-ops-jp`）
5. **「独自の情報」を必ず1つ入れる**をガイドラインの条件に入れる
   （AI が生成できるのは既存情報の再構成）

## 6. よくある失敗

- **見た目から作る**（何を表しているか説明できないロゴと色になる）
- **人格を形容詞3語で終える**（「だから、こうする」が無いと判断に使えない）
- **「らしくないこと」を書かない**（最も判断に効く部分が欠ける）
- **理由の無い禁止事項**（必ず破られる）
- **可読性の数値をブランド側で独自に決める**（正本は `design-evidence-jp`）
- **文章だけで終える**（チェックリストにしないと守られない）
- **正本が複数ある**（どれが最新か分からなくなる）
- **AI に要約して渡す**（縛りが消える）
- **守らせる仕組みを作らない**（§4 が無いガイドラインは、作らないほうがまし）
- **朝令暮改する**（反復で効くものを反復の前に変えている）
- **用語だけ更新しない**（現場より遅れ、参照されなくなる）
- **名前を決めてから商標を調べる**（後から変えられない）
- **AI が商標や法規の可否を断定する**（調査までが AI。判断は人間・専門家）
