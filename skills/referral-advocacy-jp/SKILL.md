# 紹介と推奨の設計

**ゼロ広告費で、唯一「複利で増える」獲得経路がこれ。**

コンテンツも検索も積み上がるが、伸び方は**線形**に近い。紹介だけは、
**顧客が増えるほど紹介の母数も増える**。ここを設計しないのは、
**一番強い武器を偶然に任せている**ことになる。

> **「良いものを作れば口コミは起きる」は嘘。** 満足していても、人は黙っている。
> 起きるのは、**語る理由と、語る機会と、語る言葉**が揃ったときだけ。
> このスキルはその3つを作る。

## 0. 大原則（ここを外すと全部が逆効果になる）

1. **満足していない顧客に紹介を頼まない。** 不満を増幅させる。**先に `/顧客の声` で確かめる**
2. **紹介は「お願い」ではなく「してあげやすくする」こと。** 頼む前に、**紹介する側が損をしない形**を作る
3. **対価を渡した推奨は「広告」になる。** 表示が要る（ステマ規制 → §4）
4. **特典には法定の上限がある。** 景品規制は計算できる（→ §5。`takumi/domain/premium.py` で機械検査）
5. **AI は依頼文・仕組みの下書きまで。送信・投稿は人間**（不可逆送出）
6. **紹介数を KPI の主目標に置かない。** 主目標にすると無理な依頼が始まり、関係を焼く。
   **ガードレール（依頼を断られた率・関係の悪化）とセットで持つ**

## 1. まず「語る理由」があるか確かめる

**紹介施策の失敗の大半は、施策の出来ではなく、語る理由が無いこと。**

| 確かめること | 見る場所 | 無かったら |
|---|---|---|
| **推奨したいほど満足しているか** | `/顧客の声`・継続率・再購入率 | 紹介ではなく**商品と体験を直す**。ここを飛ばさない |
| **人に説明できる言葉があるか** | 顧客が実際に使っている表現 | **顧客の語彙を拾って渡す**（→ §3） |
| **紹介先に心当たりがあるか** | 顧客の周囲に同じ状況の人がいるか | 紹介ではなく**別経路**（→ `/広報`） |
| **紹介して恥をかかないか** | 品質のばらつき・サポート | **紹介した人が損をする設計は必ず崩れる** |

**「紹介したくなるほどの体験があったか」を先に聞く。**
無いまま仕組みだけ作ると、反応が無いか、来た紹介が続かない。

## 2. 推奨されているかを測る（オーガニック指標で）

**LTV・CAC は KPIツリーに置けない**（有料指標として `KpiNode` が拒否する）。
紹介はオーガニックな指標で組む。

| 指標 | 種別 | 定義の注意 |
|---|---|---|
| **紹介経由の新規比率** | 遅行 | 参照元が落ちるため**比率で持つ**。自己申告（「どこで知ったか」）と併用 |
| **紹介してくれた顧客の割合** | 遅行 | 分母は「紹介を依頼できる状態の顧客」。**全顧客ではない** |
| **推奨の言及数**（レビュー・SNS） | 遅行 | 件数と**中身の質**を分けて見る（→ `/エンゲージメント`） |
| **顧客の声の提供に応じた割合** | **先行** | 依頼への応諾率。**最も打ち手に近い** |
| **依頼を断られた率・関係悪化** | **ガードレール** | 上がったら**依頼をやめる**。数字ではなく閾値で見る |

**紹介経由は、たいてい実際より小さく見える**（参照元が落ちる・口頭で伝わる）。
**「どこで知ったか」を申込時に1問だけ聞く**のが最も安く確実（→ `skills/cro-jp` と摩擦を相談する）。

## 3. 語る言葉を渡す — 最も安く、最も効く

**顧客は「良かった」としか言えない。** 具体的に語れないのは、語る言葉が無いからで、
満足していないからではない。

- **顧客自身の言葉を拾って返す**（`/顧客の声` で得た表現をそのまま使う。こちらの宣伝文にしない）
- **名前のついた概念を渡す**（「◯◯という考え方」。名前があると引用しやすい → `skills/breakout-content-jp`）
- **数字を渡す**（自社の実測。相手が説明に使える形にする）
- **共有しやすい単位で作る**（1枚の図・1本の記事・1つのチェックリスト）

**押し付けのハッシュタグや定型文を配らない。** 同じ文が並んだ瞬間、
読む側には「作られたもの」と分かり、**推奨としての価値が消える**。

## 4. 対価が絡んだ瞬間、それは「広告」になる（ステマ規制）

**金銭・物品・便宜のいずれかを渡して投稿・レビューを依頼したら、
それは事業者の表示であり、その旨の明示が要る。** 適法性の正本は `skills/ad-compliance-jp`。

### 絶対にやらないこと（例外なし）

- **対価を伏せた好意的コメント・レビューの依頼／投稿**
- **役員・従業員・関係者に、個人アカウントでの好意的投稿を依頼する**
  （事業者の表示に当たり、明示が必要になる）
- **口コミを「自社に都合の良い内容に改めるよう」依頼する**
  （**事実に反する箇所の訂正を求めるのは可**。評価そのものを変えさせるのは不可）
- **低評価だけを選んで消す／見えなくする**
- **紹介者に、紹介先へ嘘を言わせる**（「無料と言ってくれれば」等）

### やってよいこと

- **対価があることを明示したうえで**依頼する（表記の作法は `skills/ad-compliance-jp`）。
  **ただし、これは「日本の表示規制の話」でしかない** — **出す先の規約が対価つき投稿自体を禁じていることがある。**
  たとえば Google は、無料・割引の商品やサービス等のインセンティブを口コミと引き換えに提供することを
  「偽りおよび誤解を招くコンテンツ」として厳格に禁止しており、**明示しても許されない**
  （→ `skills/local-seo-jp` §3。可否は `takumi/domain/local_profile.py` の `ReviewSolicitation` で機械検査）。
  **「#PR を付ければどこでも出せる」と考えない。法規と規約は別に効く。**
- **対価なしで感想を募る**（謝礼を出さないなら表示義務の話にはならない。
  ただし**謝礼が無いことを条件に投稿内容を指定しない**）
- **事実誤認の訂正を、根拠を示して依頼する**

**迷ったら「対価を渡したか」で切る。** 渡していれば明示。渡していなければ、内容に口を出さない。

## 5. 特典の上限は計算できる（景品規制）

紹介特典は、景品表示法の**景品規制**の対象になりうる。**上限は計算できるので、機械で確かめる。**

### 限度額（消費者庁）

| 種別 | どういうものか | 最高額 | 総額 |
|---|---|---|---|
| **総付景品** | 懸賞によらず**もれなく**提供する（紹介特典の大半） | 取引価額 1,000円未満 → **200円** / 1,000円以上 → **取引価額の10分の2** | 定めなし |
| **一般懸賞** | くじ・抽選・優劣で提供先を決める | 取引価額 5,000円未満 → **取引価額の20倍** / 5,000円以上 → **10万円** | 懸賞に係る**売上予定総額の2%** |
| **共同懸賞** | 商店街・複数事業者の共同企画 | 取引価額にかかわらず **30万円** | 懸賞に係る**売上予定総額の3%** |

### 景品類に当たらないもの（消費者庁が規制対象外として挙げる例）

- **値引き**（自社の商品・役務の対価そのものを減額するもの）
- **自他店共通の同額割引券**
- 商品の販売・使用または役務の提供のために必要な物品・サービス（**配送料など**）
- 見本その他宣伝用の物品・サービス
- 開店披露・創業記念等の行事に際して提供する物品・サービス

**実務上、最も効く読み替え**: 紹介特典を **「ギフト券」にするか「次回割引」にするか**で、
規制の当たり方が変わりうる（**値引きは景品類に当たらない**）。

**ただし、AI が自動で分類しない。** `takumi/domain/premium.py` は
**種別を呼び出し側に宣言させる設計**にしてある（自動分類は過剰検知と過小検知の両方を生み、
どちらも法的判断を誤らせる）。**分類は人間が決め、金額の当否だけを機械が見る。**

### 確かめ方

```python
from takumi.domain.premium import PremiumKind, PremiumOffer

# 例: 5,000円の商品で、紹介者にもれなく1,500円分のギフト券を渡す案
PremiumOffer(PremiumKind.TOTSUKE, transaction_value_yen=5000, premium_value_yen=1500).assert_lawful()
# → ValueError: 総付景品の最高額を超えている: 1,500円 > 上限 1,000円
```

**懸賞で売上予定総額を申告していない場合は「判定不能」を返す。**
**判定不能を「問題なし」と読まない**（→ `skills/hypothesis-design-jp` と同じ原則）。

**これは法的助言ではない。** 「取引の価額」の認定や、そもそも景品類に当たるかの判断は
事案ごとの評価を含む。**上限を超えていたら止める**用途に使い、
**超えていないことを適法の保証に使わない。**

### そもそも特典を出すべきか

**ゼロ広告費は「ゼロ支出」ではないが、特典は金が出る。**
**まず §3（語る言葉を渡す）と §6（頼み方）を尽くす。**
金銭的インセンティブは、それでも足りないときの手段で、**予算判断は人間が行う**。

**特典で釣った紹介は、特典が終わると止まる**（積み上がらない → `skills/winning-position-jp` §4）。

## 6. 頼み方 — タイミングと粒度

**紹介依頼の成否は、文面よりタイミングで決まる。**

| 頼むとき | 見分け方 |
|---|---|
| **成果が出た直後** | 目標の達成・課題の解決を確認できた時点 |
| **感謝を伝えられた直後** | 問い合わせ・アンケート・返信での好意的な言及 |
| **定着の節目を越えた直後** | `/リテンション` ②で定義した「ここを超えると残る」行動の到達時 |

**頼んではいけないとき**: 不具合対応の直後／問い合わせが未解決／
契約更新の交渉中（**断りにくい状況で頼まない**）。

### 依頼の作法

1. **相手が何をすればよいかを1つに絞る**（「紹介してください」ではなく「この1枚を渡してください」）
2. **断りやすさを残す**（→ `skills/business-writing`）
3. **紹介先に何が起きるかを書く**（紹介した人が説明できるようにする）
4. **一斉送信にしない**（テンプレ臭は関係を消費する → `skills/psych-target-jp`）
5. **1人に何度も頼まない**（回数の上限を決めて記録する）

## 7. 顧客の声・導入事例を作る（推奨を資産にする）

**1件の推奨を、1回で消費しない。** 記事・事例・引用として**積み上がる形**にする。

- **許諾を先に取る**（掲載範囲・実名/匿名・期間・取り下げ方法を書面で）
- **相手の負担を減らす**（こちらが下書きを作り、相手は確認だけにする）
- **事実に反する加筆をしない**（読みやすく整えるのと、内容を変えるのは別）
- **数字は相手の実測のみ**（母数と期間を併記。こちらで丸めない）
- **取り下げに即応する**（掲載を続けられるのは信頼があるうちだけ）
- **個人情報の扱いは `privacy-auditor` の監査を通す**

**掲載後、相手に結果を返す**（どれだけ読まれたか）。**返す人は、次も応じてくれる。**

## 8. よくある失敗

- **満足を確かめずに紹介を頼む**（不満を増幅させ、関係を焼く）
- **仕組みだけ作って語る言葉を渡さない**（顧客は「良かった」としか言えない）
- **定型文・ハッシュタグを配る**（同じ文が並んだ時点で推奨の価値が消える）
- **対価を渡して明示しない**（ステマ規制違反）
- **従業員・役員の個人アカウントで褒めさせる**（事業者の表示。明示が要る）
- **特典の金額を確かめない**（景品規制の上限を超える。§5 で計算する）
- **特典で釣る**（特典が終われば止まる。積み上がらない）
- **紹介数を主目標に置く**（無理な依頼が始まる。ガードレールとセットで持つ）
- **断りにくいタイミングで頼む**（更新交渉中・不具合対応直後）
- **推奨を1回で消費する**（事例・記事にして積み上げる）
- **掲載結果を相手に返さない**（次が無くなる）
