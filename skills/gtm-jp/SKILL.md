# GTM 設定スキル

GTM は Web UI なので Claude in Chrome で操作できる。**指標を読むだけでなく、指標を定義する側に回れる**のがこのスキルの価値。

**GTM の設定は難しい作業ではない。** 構成要素は4つしかなく、間違えてもバージョンで元に戻せる。
このスキルは「正しく設定するために必要な事実」を並べたものである。

## 4つの構成要素

| 要素 | 役割 |
|---|---|
| **タグ** | 実際に何かをするコード（GA4 へイベントを送る等） |
| **トリガー** | タグを配信するタイミング（クリック、フォーム送信、ページ読み込み等のイベントを待ち受ける） |
| **変数** | 変動する値が入る名前付きのプレースホルダ。トリガーの条件にも、タグに渡す値にも使う |
| **データレイヤー** | サイト側から GTM へ値とイベントを渡すための JavaScript オブジェクト |

**タグ単体では何も起きない。** 必ず1つ以上の配信トリガーが要る。

## 設定の基本手順

1. **変更前にコンテナを JSON エクスポート**（管理 → コンテナをエクスポート）— 戻す先の証跡
2. 必要な**組み込み変数を有効化**（変数 → 設定）。使う予定のカテゴリだけ入れる
3. **トリガーを作る**（トリガー → 新規 → タイプを選ぶ → 条件を絞る）
4. **タグを作る**（タグ → 新規 → タイプを選ぶ → 配信トリガーを紐づける）
5. **プレビュー**で発火とパラメータの中身を目視確認（後述）
6. **公開**（送信 → バージョン名と説明 → 公開）

# トリガー

## 条件の書き方（全トリガー共通）

条件は **変数 / 演算子 / 値** の3つ組。例: `Page URL` `含む` `/products/`。
演算子には「等しい」「含む」「小さい」「正規表現に一致」などがある。

**配信トリガーと除外トリガー**

- **配信トリガー**: タグを配信するタイミング。**複数設定した場合は OR 評価** — いずれか1つの条件が成立すれば配信される
- **除外トリガー**: 特定条件下で配信をブロックする。**除外が優先される**
  （配信＝「すべてのページ」／除外＝「thankyou.html」なら、thankyou.html では配信されない）

## ページ読み込み系（発火順序が決まっている）

**この順序は仕様である。** 値が入る前にタグが動く事故は、ここの選択ミスで起きる。

| 順 | トリガータイプ | 発火するタイミング |
|---|---|---|
| 1 | **同意の初期化** | 同意に関する設定を、確実に他のすべてのトリガーの配信よりも前に適用するためのタイプ |
| 2 | **初期化** | 「同意の初期化」を除いて最も早く配信するタグ用 |
| 3 | **ページビュー** | ブラウザがページの読み込みを開始するとすぐ。ページのインプレッションだけが必要ならこれ |
| 4 | **DOM Ready** | HTML の読み込みが完全に終わり DOM が解析できる状態になった後。**DOM 値を使うタグはこれ** |
| 5 | **ウィンドウの読み込み** | 画像やスクリプトを含めページが完全に読み込まれた後 |

## クリック

- **すべての要素**: リンク・画像・ボタンなどページ上のすべての要素のクリック
- **リンクのみ**: `<a>` 要素に限定

オプション:

- **タグの配信を待つ**: すべてのタグの配信が完了するか、指定タイムアウトが経過するまで遷移を待つ
- **妥当性をチェック**: リンクのクリックが妥当なアクションとみなされた場合のみ配信。**未選択だと毎回配信される**

クリック時、クリックベースの組み込み変数（`Click Element` / `Click Classes` / `Click ID` / `Click Target` / `Click URL` / `Click Text`）に値が自動で入る。

## フォーム送信

オプションはクリックと同名で意味も同じ（タグの配信を待つ／妥当性をチェック）。
**妥当性をチェックをオフにすると、送信の試行時点で発動する**（バリデーションで弾かれた送信も数える）。

自動で入る組み込み変数: `Form Element` / `Form Classes` / `Form ID` / `Form Target` / `Form URL` / `Form Text`。

## スクロール距離

- **縦方向・横方向**を選ぶ（同一トリガー内で両方の組み合わせも可）
- しきい値は**パーセンテージまたはピクセル**。**正の整数のみ**
- **複数のしきい値はカンマ区切り**。`10, 50, 90` なら、ページの高さの 10% / 50% / 90% の地点でそれぞれ発動する
- 有効化タイミングの既定は**ウィンドウの読み込み（`gtm.load`）** — ページサイズの計算に完全読み込みを待つ必要があるため

組み込み変数: `Scroll Depth Threshold`（しきい値）/ `Scroll Depth Units`（% かピクセル）/ `Scroll Direction`（縦か横）。

## 要素の表示（視認性）

選択方法は **ID**（`id` 属性で単一要素）または **CSS セレクタ**（1つ以上の要素）。

起動タイミングは3択:

1. **1ページにつき1度** — 複数該当してもいずれか1つが視認可能になった時点で1回
2. **1要素につき1度** — 指定した要素ごとに1回
3. **各要素が画面に表示されるたび** — 視認可能になるたびに毎回

詳細設定:

- **視認の最小割合**: 既定 **50%**。要素の半分以上が画面内に表れないとイベントは呼ばれない
- **最小表示時間**（ミリ秒）: この時間だけ視認可能であり続ける必要がある
- **DOM 変更の監視**: オンにすると、DOM 変更で表示状態が変わる要素も監視対象になる

組み込み変数: `Percent Visible`（1〜100）/ `On-Screen Duration`（ミリ秒）。

## タイマー

| 項目 | 内容 |
|---|---|
| イベント名 | 既定は `gtm.timer`。通常は変更不要だが、カスタムイベントトリガーを作るときに使える |
| 間隔 | **ミリ秒単位**（例: 5000） |
| 制限 | 起動する最大回数。**空白にするとページを離れるまで送り続ける** |
| 条件 | 変数・演算子・値。必要なページに絞ると全体のパフォーマンスが上がる |

## カスタムイベント

サイト側の `dataLayer.push({'event': '名前'})` を受ける。**サイト側で発火点を制御できるので最も確実**。

## トリガー設定の推奨（公式）

1. **フォームやリンクのトリガーは、公開する前にプレビューでテストする**（別の JavaScript が干渉することがある）
2. 古いブラウザでの動作確認が必要な場合は入念にテストする
3. **フィルタで対象範囲を制限する** — 全ページでテストする手間が減り、特定ページに限定した慎重な実装ができる

# 変数

## 組み込み変数（変数 → 設定 で有効化）

| カテゴリ | 変数 |
|---|---|
| **ページ** | `Page URL`（完全な URL）/ `Page Hostname` / `Page Path` / `Referrer`（完全な参照元 URL） |
| **クリック** | `Click Element`（DOM 参照）/ `Click Classes` / `Click ID` / `Click Target` / `Click URL` / `Click Text` |
| **フォーム** | `Form Element` / `Form Classes` / `Form ID` / `Form Target` / `Form URL` / `Form Text` |
| **スクロール** | `Scroll Depth Threshold` / `Scroll Depth Units` / `Scroll Direction` |
| **視認性** | `Percent Visible` / `On-Screen Duration` |
| **動画** | `Video Current Time` / `Video Duration` / `Video Percent` / `Video Provider` / `Video Status` / `Video Title` / `Video URL` / `Video Visible` |
| **履歴** | `History Source` / `New History Fragment` / `Old History Fragment` / `New History State` / `Old History State` |
| **エラー** | `Error Message` / `Error URL` / `Error Line` / `Debug Mode` |
| **ユーティリティ** | `Container ID` / `Container Version` / `Environment Name` / `Event`（現在の dataLayer イベント名）/ `Random Number` / `HTML ID` / `Analytics Client ID` / `Analytics Session ID` / `Analytics Session Number` |

## ユーザー定義変数タイプ

**ナビゲーション**

- **HTTP 参照**: 直前にアクセスしていたページの URL
- **URL**: URL を分解する。Full URL / Protocol / Hostname / Port / Path / Filename Extension / **Query** / Fragment から選ぶ。
  **URL ソースに別の変数を指定できる**（後述の UTM 取得はこれを使う）

**ページ変数**

- **ファーストパーティ Cookie**: 同名 Cookie が複数あるときは**最初の値**を返す
- **データレイヤー**: `dataLayer.push()` でプッシュされた値。
  **バージョン1 = キー名のドットをそのまま解釈／バージョン2 = ドットをネストとして解釈**（既定は2。既存コンテナを触るときは要確認）
- **JavaScript 変数**: グローバル JavaScript 変数から取得
- **カスタム JavaScript**: 値を返す匿名関数（→ 後述の制限あり）

**ページ要素**

- **自動イベント変数**: イベント発生元の情報（Element / Element Type / Element Attribute / Element Classes / Element ID / Element Target / Element Text / Element URL / History 系）
- **DOM 要素**: DOM 要素のテキスト、または指定した属性の値
- **要素の視認性**: True/False かパーセント（0〜100）

**ユーティリティ**

- **ルックアップ テーブル**: 別の変数の値に応じて値を差し替える。「変数を選択」＋「この変数の設定」の2列
- **正規表現の表**: ルックアップの正規表現版。**パターンは上から順に評価され、最初の一致が返る**。
  大文字小文字の区別・完全一致の切り替え、**キャプチャグループと置換**も使える
- **定数** / **乱数**（0〜2147483647）/ **カスタム イベント**（プッシュされたイベント名）/ **環境名**
- **アナリティクス ストレージ**: クライアント ID / セッション ID / セッション番号。測定 ID・Cookie 接頭辞でフィルタできる
- **Google タグ: 設定** / **Google タグ: イベントの設定**: パラメータをまとめて複数タグで再利用する

**コンテナデータ**: コンテナ ID / コンテナのバージョン番号 / デバッグモード。

# データレイヤー

## 設置

```javascript
window.dataLayer = window.dataLayer || [];
```

- **コンテナスニペットより前**、ソースコードのできるだけ上に置く。この書き方なら既存の値を壊さない
- **`dataLayer` は大文字小文字を区別する**（`datalayer` では動かない）
- **1ページに1つだけ。** 複数あるとタグが誤発火し、デバッグが困難になる

## push の書き方

```javascript
// イベント
dataLayer.push({'event': 'login'});

// 変数
dataLayer.push({'color': 'red'});

// まとめて
dataLayer.push({
  'color': 'red',
  'conversionValue': 50,
  'event': 'customize'
});
```

- **メッセージがイベントなら、条件を満たしたトリガーのタグが配信されてから次のメッセージへ進む**
- **変数名は必ず引用符で囲む**
- 値は**現在のページの間だけ保持される**。ページをまたいで使うなら各ページの読み込み時に、コンテナコードより前でプッシュする
- **`window.dataLayer = []` で上書きしない。** GTM 読み込み後は必ず `.push()`
- ページ間で**同じ変数名を使う**（名前がぶれるとタグが発火しない）

## カスタムメソッド

`set`（値の保存）/ `get`（取得）/ `reset`（クリア）を dataLayer に直接プッシュできる。

# GA4 イベントタグの設定

1. タグ → 新規 → **「Google アナリティクス: GA4 イベント」** を選ぶ
2. タグに分かる名前を付ける（例: `GA4 イベント - ニュースレター登録`）
3. **イベント名**を入れる。ここに入れた名前が **GA4 レポートにそのまま表示される**。
   推奨イベントを実装するなら**定義済みのイベント名を使う**
4. 必要ならイベントパラメータを追加する
5. トリガーを紐づける（例: `Click Text` `含む` `ニュースレター配信登録`）

**Google タグ（設定タグ）側**では、タグ ID（測定 ID）を指定し、
「共有イベントの設定」で `currency` などイベントごとに送る追加パラメータを指定できる。
カスタムユーザープロパティを測るには **Google タグのイベント設定変数**を作って Google タグに割り当てる。

**イベント設計の原則**

- **イベント名は GA4 の推奨イベント名に寄せる**（自動収集・推奨と衝突しない範囲で）。独自名は snake_case
- **1指標 = 1イベント。** パラメータで切る。イベント名を増やしすぎると GA4 側の上限とレポートの見通しを損なう
- 作った指標は**必ず KPIツリーのノードに紐づける**。紐づかない指標は作らない（測るだけで使わないデータは負債）
- **パラメータは GA4 側でカスタムディメンションに登録しないとレポートに出ない**（→ `ga4-jp`）

# SNS・マルチメディアからの CV を計測する

**これがこのスキルの本題。** やることは2つだけで、GTM 側は驚くほど単純である。

## 1. 流入側 — URL に UTM を付ける（GTM の作業ではない）

SNS・動画説明欄・プロフィールリンクなど、**外部から自社サイトへ送るリンクすべてに UTM を付ける。**

```
https://example.com/lp?utm_source=x&utm_medium=social&utm_campaign=2026q3_launch&utm_content=video_short
```

- `utm_source` = 参照元（`x` / `youtube` / `tiktok` / `note`）
- `utm_medium` = メディア（`social` / `video` / `email`）
- `utm_campaign` = キャンペーン（施策名。**モダリティ横断で同じ値**にする）
- `utm_content` = クリエイティブの区別（**モダリティ・素材違いをここで切る**）

**命名規則はブランド区画に固定して置く**（`knowledge/brands/<slug>/` の計測規約）。表記ゆれは分析を殺す。

## 2. CV 側 — GA4 イベントを1つ発火させる（GTM の作業）

CV 地点（フォーム送信完了・サンクスページ到達・予約ボタンクリック）で **GA4 イベントを1つ**発火させる。
トリガーは上記のどれか（フォーム送信 / ページビューで `Page Path` `等しい` `/thanks` / クリック）。

**モダリティ情報を CV イベントに載せる必要はない。**
GA4 はセッションに参照元・メディア・キャンペーンを保持しており、
**トラフィック獲得レポートで「セッション参照元 / メディア」「セッション キャンペーン」ごとにキーイベントを分解できる**。
GTM 側でランディングページの `utm_content` を CV まで運ぶ配線は要らない。

> **未確認**: `utm_content` に対応するセッションスコープのディメンション名は公式ヘルプで確認できていない。
> 実機の GA4 で「セッションの手動広告コンテンツ」等が探索のディメンション一覧にあるかを確認してから、
> モダリティ別（`utm_content` 別）の分解を設計に入れること。**なければ `utm_campaign` の粒度を細かくして代替する。**

## 3. 認知系モダリティは CV だけで測らない

動画・SNS の役割は多くの場合「最後の1クリック」ではない。
**ラストクリック帰属では認知を担うモダリティは構造的に評価されない**（→ `ga4-jp` のアトリビューション節）。
CV 計測と併せて、**先行指標（到達・エンゲージメント）を KPIツリーの別ノードに置く**こと。

# プレビューとデバッグ

**公開前に必ず通す。** プレビューは自分のブラウザにだけ適用され、本番には影響しない。

1. ワークスペース右上の**「プレビュー」**をクリック → Google Tag Assistant が新しいタブで開く
2. サイトの URL を入力し、必要に応じて「URL にデバッグシグナルを含める」を調整
3. **「接続」**をクリック → サイトが新しいウィンドウで開き、「接続済み」と表示される
4. サイトを操作すると、**タグの配信情報がリアルタイムで更新される**
5. 各イベントを選び、**配信されたタグ / 配信されなかったタグ**と**変数の実際の値**を確認する

**見るべきもの**: 狙ったタグが発火しているか、余計なタグが発火していないか、送信パラメータの中身が意図どおりか。

終了: デバッグインターフェース左上の **× → Tag Assistant の「デバッグを停止」**。
**プレビューをつけっぱなしにしない。**

制限: モバイルアプリ用コンテナと AMP 用コンテナではデバッグインターフェースを使えない。

# バージョンと公開・ロールバック

バージョンは**特定の時点のコンテナ設定のスナップショット**。ミスがあっても戻せる。

## 公開せずにバージョンだけ作る

送信 → **「バージョンの作成」** → 名前と説明 → 作成。

**名前と説明は内容が分かるように書く。** 公式の例:

- 名前: `GA ページビュー タグ - 初回リリース`
- 説明: `example.com で Google アナリティクスのページビュー タグを公開`

「v47」のような番号だけの名前にしない。**戻すときに探せない。**

## 公開

送信 → 名前と説明 → 公開。保存済みバージョンを後から公開する場合は
**バージョン → 対象を選択 → アクション → 公開**。

## ロールバック（元に戻す）

**バージョン → 対象バージョンのアクション → 「最新バージョンに設定」。**
現在のドラフトコンテナが、選択したバージョンの内容に置き換わる。

**この手順があるので GTM の公開は不可逆ではない。** 壊れたら戻せる。
戻せないのは削除（タグ・コンテナ・アカウント）と権限操作。

## 確認できること

- ワークスペースの変更画面 → その他の操作 で**バージョン間の相違点と変更内容**
- バージョン画面の「公開済み」列で**公開日時と公開したユーザー**

# 安全境界（守るのはここだけ）

| 操作 | 可否 | 理由 |
|---|---|---|
| 閲覧・棚卸し・JSON エクスポート | ✅ 自律可 | 読み取り。**編集前に必ずエクスポートを取る** |
| ワークスペース内でのタグ/トリガー/変数の追加・編集 | ✅ 自律可 | 公開しなければ本番に出ない |
| プレビュー（Tag Assistant）での検証 | ✅ 自律可 | 自分のブラウザだけ |
| **公開（バージョンの公開）** | ⚠️ **人間の承認** | 全訪問者に即時反映される。ただし**ロールバック可**。プレビュー通過を前提に承認を取る |
| **カスタムHTMLタグ / カスタムJavaScript変数**の作成・編集 | 🚫 **AI 自律禁止** | 任意の JS を全訪問者に注入できる。Magecart 型のカード情報窃取が実際にこの経路で起きている。**下書きの提示までにとどめ、作成・保存は人間が行う** |
| タグ・トリガー・変数の**削除** | ⚠️ 承認必須 | 削除ではなく**一時停止（Pause）**を提案する。停止なら即戻せる |
| コンテナ・アカウントの削除 / ユーザー権限の変更・招待 | 🚫 禁止 | 復旧不能・セキュリティ事案 |
| サーバーサイドコンテナの作成・課金設定 | 🚫 禁止 | 課金が発生する（ゼロ課金ゲート対象） |

**送信するパラメータに個人情報を入れない。** メールアドレス・氏名・電話番号を GA4 へ送るのは Google 契約上の違反であり、
送ってしまうと取り消せない。**プレビューの手順5でパラメータの中身を目視する**のがこの防止策の実体（→ `ga4-jp` の PII 節）。

## カスタムHTMLを構造的に止める（任意・推奨）

コンテナに `gtm.blocklist` を設定すると、**UI から追加されてもタグが実行されなくなる**。

```javascript
dataLayer.push({'gtm.blocklist': ['customScripts']});
```

一次情報で確認済みの仕様:

- **`customScripts` クラスの対象は2つだけ** — カスタムHTMLタグ（ID: `html`）とカスタムJavaScript変数（ID: `jsm`）。
  **DOM 要素変数は対象外**（`google` クラスに分類される）
- **`blocklist` は `allowlist` に優先する**
- `nonGooglePixels` をブロックすると `nonGoogleScripts` も自動的にブロックされる
- **罠**: カスタムテンプレートを使っている状態で任意のタグクラスを blocklist に入れると、
  **`sandboxedScripts` を明示的に allowlist へ追加しないとテンプレートが動かなくなる**

導入するなら**プレビューで既存タグが全て動くことを確認してから**公開する。

---

# よくある事故と回避

| 事故 | 回避 |
|---|---|
| プレビューで確認せず公開 → 全ページで誤発火 | プレビューを飛ばさない。**「テストせずに公開しない」が GTM の第一原則** |
| DOM の値が空で送られる | トリガーを**ページビュー → DOM Ready** に変える。発火順序の問題 |
| タグを削除して戻せなくなった | 削除ではなく**一時停止**。公開後の事故なら**バージョンのロールバック** |
| ロールバック先が分からない | バージョン名を内容で書く。「v47」にしない |
| データレイヤー変数が取れない | バージョン1/2 の解釈違い、`dataLayer` の綴り、push がコンテナより後になっていないかを順に疑う |
| スクロールトリガーが発火しない | 有効化タイミングが**ウィンドウの読み込み**であることを確認。遅延読み込みページでは高さが変わる |
| フォーム送信が取れない | JavaScript でハンドリングしているフォームは検出されないことがある。**サイト側から `dataLayer.push` してカスタムイベントで受ける** |
| プレビューをつけっぱなし | 検証後に「デバッグを停止」 |
| 除外トリガーを配信トリガーだと思っていた | 配信は OR、**除外が優先**。この2つを取り違えると全ページに出る |
