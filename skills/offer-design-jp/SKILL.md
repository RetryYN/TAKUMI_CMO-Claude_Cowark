# オファーの設計

**同じ集客量で成果が変わる、最大のレバーがここにある。**

流入を2倍にするのは広告費があっても難しい。だがオファーを変えれば、
**今の流入のまま**転換率が変わる。**ゼロ広告費では、ここが最も費用対効果の高い打ち手**になる。

にもかかわらず、多くの現場は「もっと集客を」に時間を使う。
**集客の前に、来ている人に何を差し出しているかを見る。**

> **オファーとは何か**: 商品そのものではなく、**差し出し方の全体**。
> 「何が手に入るか × どんな束か × いくらか × どんな条件か × 断ったときどうなるか」。
> 商品を変えずにオファーだけ変えられる余地は、たいてい思っているより大きい。

## 0. 手をつける順番（この順を守る）

1. **今のオファーを書き出す**（§1）— 言語化されていないことが多い
2. **摩擦を数える**（§2）— **足す前に減らす。ここが最も安く効く**
3. **束を組み直す**（§3）— 値下げの前に、価値の側を動かす
4. **入口を設計する**（§4）— 最初の一歩を軽くする
5. **リスクを引き取る**（§5）— 保証・返金・お試し
6. **値付けを見直す**（§6）— **最後**。ここから始めると値下げ競争に落ちる
7. **表示の適法性を通す**（§7）— → `skills/ad-compliance-jp` が正本

**値付けから始めない。** 値下げは誰でも真似できる（＝非対称ではない → `skills/winning-position-jp`）。
真似されない順に手をつける。

## 1. 今のオファーを1枚に書き出す

```markdown
## オファー（<商品・サービス名>）

**得られる結果**: 〈顧客の状況がどう変わるか。機能ではなく結果〉
**含まれるもの**: 〈中身の一覧〉
**価格と支払い方**: 〈金額・期間・回数・支払方法〉
**必要な条件**: 〈対象・前提・準備してもらうもの〉
**申込の手間**: 〈項目数・所要時間・その場で完結するか〉
**やめるときどうなるか**: 〈解約・返金・違約〉
**断る理由になっているもの**: 〈想定される躊躇。→ /顧客の声 で実際に聞く〉
```

保存先: `knowledge/brands/<slug>/strategy/offer.md`。

**最後の1行が最も重要で、最も埋まらない。** 埋まらないなら推測で埋めず、
`/顧客の声`（`skills/voc-research-jp`）で**買わなかった人**に聞く。

## 2. 摩擦を減らす — 足す前に、減らす

**特典を足すより、障害を取り除くほうが安く、速く、確実に効く。**

| 摩擦 | 見つけ方 | 減らし方 |
|---|---|---|
| **入力項目が多い** | フォームの項目数を数える | **必須項目を減らす**（後から聞けるものは後から） |
| **決めることが多い** | 選択肢の数を数える | 既定の1案を用意する（→ `skills/psych-nudge-jp`） |
| **その場で完結しない** | 折り返し・資料待ちの有無 | その場で結果が出る形にする |
| **次に何が起きるか不明** | 申込後の説明の有無 | **申込後の流れを事前に書く**（不安は情報不足から出る） |
| **価格が分からない** | 料金ページの有無 | 幅でよいので出す（→ §6） |
| **やめ方が分からない** | 解約手順の記載 | **先に書く。書くほど申し込まれる** |

**「やめ方を先に書くと申込が減る」は逆。** 書かれていないほうが不安が残る。
やめ方の明記は、日本の通信販売では**表示義務**でもある（→ §7）。

**フォーム・導線そのものの改善は `skills/cro-jp` が正本。**
このスキルは「何を差し出すか」を扱い、cro-jp は「どう差し出すか」を扱う。

## 3. 束を組み直す — 値下げの前に価値を動かす

**同じ原価でも、束ね方で受け取られる価値は変わる。**

| 手 | 何をするか | 効く場面 |
|---|---|---|
| **足す** | 提供済みで原価が増えないものを明示する | **既にやっているのに書いていない**ことが多い（サポート・記録・その後の相談） |
| **分ける** | 大きい1本を、入口と本体に割る | 単価が高く検討が長いとき（→ §4） |
| **絞る** | 対象と用途を狭める | 「誰にでも」が刺さらないとき（→ `skills/sales-writing`） |
| **名付ける** | 束に名前をつける | 比較されにくくなる。**引用されやすくなる**（→ `skills/breakout-content-jp`） |
| **束ねる** | 別々に買われていたものを1つに | 併用率が高いとき |

**「足す」を最初に確かめる。** 既に提供しているのに書いていないものは、
**原価ゼロで価値が上がる**。オファーの棚卸しで最も多く見つかるのがこれ。

**やってはいけない**: 中身を増やさずに「特典」と称して見せかけを膨らませること。
実質の伴わない特典表示は優良誤認・有利誤認になりうる（→ `skills/ad-compliance-jp`）。

## 4. 入口を設計する — 最初の一歩を軽くする

**検討期間が長い領域ほど、いきなり本体は売れない**（→ `skills/winning-position-jp` §1）。
最初の一歩を、**相手が失うものがほぼゼロ**の形にする。

| 入口の型 | 向く場面 | 設計の要点 |
|---|---|---|
| **資料・テンプレの提供** | 情報収集の段階 | **その場で使える形**にする（読んで終わりにしない） |
| **診断・チェックリスト** | 課題が言語化できていない | 結果が**その人固有**になること |
| **無料相談・体験** | 人が判断材料の領域 | 時間と範囲を先に決める（無制限にしない） |
| **少額の入口商品** | 無料だと本気度が測れない | 本体への道筋を最初に示す |

**入口を作るときの必須条件**:

1. **入口だけで完結した価値がある**（本体を買わなくても役に立つ。ここを守らないと信用を失う）
2. **本体への道筋が示されている**（入口で終わる設計は、ただのコスト）
3. **入口の成果を測るノードが KPIツリーにある**（→ `skills/kpi-design-jp`。無いなら作る）

**「無料」は最強ではない。** 無料は本気度の低い相手も呼ぶ。
**人手で対応する入口ほど、少額でも対価を取るほうが総量として効率が良いことがある。**
どちらが効くかは仮説として検証する（→ `skills/hypothesis-design-jp`）。

## 5. リスクを引き取る — 保証・返金・お試し

**買わない理由の多くは「欲しくない」ではなく「外したくない」。**
その不安を売り手が引き取ると、判断が軽くなる。

- **何を保証するか**を具体で書く（「満足いただけなければ」は基準が無く、揉める）
- **条件・期間・手続きを先に書く**（後出しは信用を壊す）
- **引き取れない範囲も書く**（全部引き取るふりをしない）
- **実行できる範囲でだけ約束する**（履行できない保証は最悪の選択）

**日本の通信販売では、返品の可否・条件・送料負担の表示が求められる**（→ §7）。
**保証は「あると強い」ではなく「書き方を間違えると違反になる」領域**だと理解して設計する。

## 6. 値付け — 最後に触る

### 値付けの前に確かめること

- **値下げで勝てる相手か**（資本のある相手には価格で勝てない → `skills/winning-position-jp`）
- **今の価格で断られているのか**（`/顧客の声` で確かめる。**推測で値下げしない**）
- **下げた価格を戻せるか**（戻せないなら、下げるのは片道切符）

### 出し方

| 論点 | 判断 |
|---|---|
| **価格を公開するか** | **原則は公開**（幅でもよい）。非公開は問い合わせの手前で離脱を生む |
| **プランを何本にするか** | 増やすほど決められなくなる。**3本を超えたら理由を言えること** |
| **どの単位で課金するか** | 顧客の成果に近い単位ほど納得されやすい |
| **値上げするとき** | **既存顧客への予告と据置期間**を先に決める（→ `/リテンション`） |

### 「安く見せる」表示の落とし穴（→ §7 が正本）

**二重価格表示（「通常◯円 → 今だけ◯円」）は、比較対照価格に実績が要る。**
消費者庁は「同一の商品について『**最近相当期間にわたって販売されていた価格**』を比較対照価格とする場合には、不当表示に該当するおそれはありません」とし、
そうでない価格を用いる場合は「**当該価格がいつの時点でどの程度の期間販売されていた価格であるかなどその内容を正確に表示しない限り、不当表示に該当するおそれがあります**」としている。

「最近相当期間」の一般的な目安として、消費者庁の Q&A は
「**二重価格表示を行う時点からさかのぼった8週間において、当該価格で販売されていた期間が、当該商品が販売されていた期間の過半を占め、当該価格での販売期間が通算で2週間以上であり、当該価格で販売された最後の日から2週間経過していなければ**」と示している。

**実務上の読み替え**:

1. **「通常価格」を名乗るには、実際にその価格で売っていた期間が要る**。セール用に作った建前の価格は使えない
2. **「期間限定」の常態化は不可**（ずっと限定なら限定ではない）
3. **将来価格との比較**は、「表示された将来の販売価格が十分な根拠のあるものでないとき（実際の販売することのない価格であったり、ごく短期間のみ当該価格で販売するにすぎないなど）には、不当表示に該当するおそれがあります」
4. **迷ったら二重価格表示を使わない。** ゼロ広告費の勝ち筋は値引きではない

## 7. 表示と契約のルール（設計段階で通す）

**適法性チェックの正本は `skills/ad-compliance-jp`。** ここでは**オファー設計に直結する項目**だけ挙げる。

### 通信販売（オンラインで申し込ませるすべて）

- **返品**: 「商品の引渡し（特定権利の移転）を受けた日から数えて８日以内であれば、消費者は事業者に対して、契約申込みの撤回や解除ができ、消費者の送料負担で返品ができます」。
  ただし「**事業者が広告であらかじめ、この契約申込みの撤回や解除につき、特約を表示していた場合は、特約によります**」
  → **返品特約を書くかどうかが、そのまま条件を決める**。書かないと上記の原則が適用される
- **最終確認画面**: 注文確定の直前に契約事項を確認できるよう表示する義務がある。
  「返品に関する事項（返品の可否・返品の期間等条件、返品の送料負担の有無）」は**省略できない**
- **定期購入**: 各回の分量に加え、**引渡しの回数や総量**の表示が要る。
  **消費者が自分で変更しない限り定期購入になる初期設定**は問題になりうる

**「初回◯円」の設計は、ここで事故が起きる。** 総額・回数・解約条件を、
**申込の直前に、打ち消し表示ではなく本文で**示す。

### 特典を配るとき（紹介・キャンペーン）

**景品規制の上限は計算できる。** → `skills/referral-advocacy-jp` と
`takumi/domain/premium.py`（`PremiumOffer.assert_lawful()`）で機械的に確かめる。

## 8. オファーを変えたら測る

**オファーの変更は仮説である**（→ `skills/hypothesis-design-jp`）。

- **1回で1つだけ変える**（束と価格を同時に変えたら、どちらが効いたか分からない）
- **転換率だけを見ない**。転換率が上がっても、**後段（継続・満足）が落ちていたら失敗**
  （→ `/リテンション`・`/顧客の声`）
- **ガードレール指標を決める**（解約率・返品率・問い合わせの手戻り）
- 結果は `knowledge/brands/<slug>/hypotheses/` に、**母数と期間つき**で残す

**「申込が増えたから成功」で終えない。** 入口を軽くすると必ず数は増える。
**軽くしすぎた入口は、後段で落ちる。**

## 9. よくある失敗

- **集客を増やす話から始める**（今の流入で何を差し出しているかを見ていない）
- **値付けから手をつける**（真似されやすく、戻しにくい。最後に触る）
- **特典を足して摩擦を放置する**（減らすほうが安く速く効く）
- **既に提供しているものを書いていない**（原価ゼロの価値を捨てている）
- **やめ方・解約条件を隠す**（申込は増えず、不信と表示義務違反が残る）
- **履行できない保証を書く**（一度でも守れなければ、そこで終わる）
- **「通常価格」を実績なしで名乗る**（二重価格表示。→ §6）
- **「期間限定」を常態化する**（有利誤認）
- **打ち消し表示に条件を逃がす**（本文で言えないなら、その条件は無理がある）
- **転換率だけで成否を判定する**（後段の劣化を見ていない）
