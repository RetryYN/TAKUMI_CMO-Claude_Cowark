# ビジネスモデルとキャッシュフロー

**マーケティングの失敗の多くは、マーケティングの外で決まっている。**

構造的に儲からないモデルに集客を足しても、**赤字が速く増えるだけ**。
現金が回らないモデルで成長を狙えば、**黒字のまま止まる**。

**だから集客の話の前に、「儲かるのか」「現金が回るのか」を見る。**

> **ゼロ広告費との関係**: 広告費を使わないことは、コストがゼロという意味ではない。
> **時間が原価**である。時間を計上しないと、
> 「効率が良い施策」と「ただ自分の時間で埋めているだけの施策」が区別できない（→ §4）。

## 0. 最初に埋める1枚

```markdown
## ビジネスモデル（<ブランド名>）

**誰が金を払うか**: 〈使う人と払う人が違うなら、両方書く〉
**何に対して払うか**: 〈モノ／時間／成果／利用権／場所〉
**いつ現金が入るか**: 〈前払い／即時／掛け（何日後）〉
**いつ現金が出るか**: 〈仕入・外注・人件費のタイミング〉
**変動費**: 〈売上に比例して増えるもの〉
**固定費**: 〈売れなくても出るもの〉
**収益の型**: 〈都度／継続／従量／手数料／組合せ〉
**繰り返し買われるか**: 〈1回きりか、続くか〉
```

**「いつ現金が入るか」を必ず埋める。** 損益計算書には出ないが、**事業が死ぬのはここ**。

## 1. 収益の型で、打ち手がまるごと変わる

| 型 | 例 | 効く打ち手 | 危険 |
|---|---|---|---|
| **都度** | 単発の物販・受託 | 新規獲得・単価・再購入の設計 | 毎月ゼロから積み直す |
| **継続（サブスク）** | 会員・保守 | **継続率**（→ `/匠顧客`） | 解約が全てを溶かす |
| **従量** | 使った分だけ | 利用の深さを増やす | 使われないと売上ゼロ |
| **手数料・仲介** | マッチング | **両側**を集める必要 | 片側だけ集めても回らない |
| **前受け** | 予約・回数券・年払い | **現金が先に入る**（→ §3） | 提供義務が残る |

**継続モデルなら、獲得より継続。** 継続率が悪いモデルに集客を足すのは
**穴の空いた桶に水を注ぐ**行為（→ `procedures/takumi-retention.md`）。

**「繰り返し買われるか」は最重要の分岐。** 1回きりの商品は、**獲得コストを1回の粗利で回収し切る**
必要がある（§4）。回収できないなら、続ければ続けるほど損をする。

## 2. 損益分岐点 — 売っても赤字が増える構造を先に見つける

**限界利益率 = 1 − 変動費率。** 固定費をこれで割ると損益分岐点売上高が出る。

```python
from takumi.domain.unit_economics import BreakEven

be = BreakEven(fixed_cost_yen=1_000_000, variable_cost_ratio=0.4)
be.break_even_sales_yen()        # 1,666,667 円
be.required_sales_yen(500_000)   # 目標利益50万を出すのに必要な売上
be.margin_of_safety_ratio(2_500_000)  # 安全余裕率（負なら赤字）
```

**変動費率が1以上なら `ValueError` になる。**
これは実装の都合ではなく、**損益分岐点が存在しない**（売るほど赤字が増える）ため。
このときにやることは集客ではなく、**原価・提供方法・価格のどれかを変えること**。

### 読み方

- **安全余裕率が小さい**＝売上が少し落ちただけで赤字。**攻めの前に、まず余裕を作る**
- **固定費が大きい構造**は、売れれば一気に利益が出るが、落ちると一気に赤字になる
- **変動費率が高い構造**は安定するが、**規模を追っても利益が伸びにくい**
- **どちらを選ぶかは戦略**。「固定費を下げるのが常に正しい」ではない

## 3. キャッシュフロー — 黒字でも現金が尽きれば終わる

**利益と現金は別物。** 売れた瞬間に現金が入るとは限らない。

### CCC（キャッシュコンバージョンサイクル）

```python
from takumi.domain.unit_economics import CashCycle

cycle = CashCycle(inventory_days=30, receivable_days=45, payable_days=60)
cycle.ccc_days()                                  # 15 日
cycle.working_capital_need_yen(daily_sales_yen=100_000)  # 1,500,000 円
cycle.is_cash_generating()                        # False
```

**CCC = 棚卸資産回転日数 + 売上債権回転日数 − 仕入債務回転日数。**

| CCC | 意味 | 成長するとどうなるか |
|---|---|---|
| **正** | 現金が出てから戻るまでに間がある | **売上が伸びるほど現金が減る**（要運転資金） |
| **ゼロ近辺** | ほぼ同時 | 現金の観点では中立 |
| **負** | 先に現金が入る（前受け・即時決済） | **売れるほど手元現金が増える** |

**ここがマーケティングの計画に直結する。**
CCC が正の事業で「来月から売上2倍」の計画を立てるなら、
**日商 × CCC の運転資金を用意できるか**を先に確認する。用意できないなら、
**その計画は成功したときに資金が尽きる**。

### CCC を縮めるのはマーケティングの仕事でもある

- **前払い・年払いに割引をつける**（→ `skills/offer-design-jp` の束の組み直し）
- **回数券・予約制にする**（前受け化）
- **在庫を持たない形に変える**（受注生産・デジタル）

**ただし、前受けは「もらった時点では他人の金」。** 提供義務が残る。
**前受けで回している事業が成長を止めると、資金繰りが最初に壊れる。**

## 4. オーガニックな獲得コスト — 「無料でやっている」は錯覚

**広告費を使わなくても、時間が出ていく。**

```python
from takumi.domain.unit_economics import OrganicAcquisitionCost

cost = OrganicAcquisitionCost(hours_spent=40, hourly_rate_yen=5_000, customers_acquired=8)
cost.cost_per_customer_yen()                       # 25,000 円/件
cost.verdict(gross_profit_per_customer_yen=30_000) # 「回収できている」
```

### 設計上の要点2つ

**(1) 時間単価を0円にしない。** `hourly_rate_yen=0` は `ValueError`。
自分の時間を0円にすると、**あらゆる施策が「効率的」に見えてしまう**。

**(2) 獲得0件は「判定不能」であって「コスト0円」でも「効率が良い」でもない。**
`cost_per_customer_yen()` は `None` を返し、`verdict()` は「判定不能」と書く。
**期間が短すぎるのか、施策が効いていないのかを切り分ける**
（→ `skills/hypothesis-design-jp` §5 の3分類）。

### 使い道

| 判定 | やること |
|---|---|
| **回収できている** | その施策に時間を寄せる（→ `docs/parts/capacity-plan.md`） |
| **回収できていない** | 時間の投下先を変えるか、**粗利・単価の側を動かす**（→ `skills/offer-design-jp`） |
| **判定不能** | 期間・母数を確かめる。**「効果あり」と書かない** |

**継続モデルなら、1回の粗利ではなく「回収までの期間」で見る。**
何ヶ月で回収できるかを出し、**その期間、現金が持つか**を §3 と突き合わせる。

## 5. KPIツリーには載せない（意図的な分離）

**ここで扱う指標は `knowledge/brands/<slug>/strategy/kpi-tree.yaml` に置かない。**

- **KPIツリー**は「**動かすため**」の指標。葉が実行できる手順書に紐づく（→ `skills/kpi-design-jp`）
- **ユニットエコノミクス**は「**続けるか・やめるか**」を決めるための指標

混ぜると事故る。**「獲得単価を下げる」を施策目標にすると、獲得を減らせば達成できてしまう。**

また、**CAC / LTV / ROAS / 広告費 は KPIノードとして機械的に拒否される**
（`KpiNode` が `ValueError`）。この禁止は、ユニットエコノミクスを扱えるようにしても**緩まない**
（`tests/test_unit_economics.py::TestNotAKpiNode` で固定）。

## 6. 施策を決める前に確かめる3問

1. **この施策で増える売上は、変動費を引いても固定費の回収に回るか**（§2）
2. **売上が増えたとき、現金は足りるか**（§3。CCC が正なら特に）
3. **投じる時間は、1件あたりの粗利で回収できるか**（§4）

**3つのどれかが「いいえ」なら、集客ではなく構造を直す。**

## 7. よくある失敗

- **儲かるかを確かめずに集客を足す**（赤字が速く増えるだけ）
- **利益と現金を同じものとして扱う**（黒字倒産はここで起きる）
- **成長計画に運転資金を織り込まない**（**成功したときに資金が尽きる**）
- **自分の時間を0円で計上する**（すべての施策が「効率的」に見える）
- **獲得0件を「コスト0円」と読む**（判定不能を有利な数字に化けさせる）
- **1回きりの商品で、回収を「そのうち」に先送りする**
- **継続モデルで獲得ばかり追う**（解約が全てを溶かす）
- **前受けで回っているのに、成長が止まるリスクを見ない**
- **ユニットエコノミクスを KPIツリーに入れる**（獲得を減らせば達成できる目標になる）
- **固定費削減を常に正解だと思う**（構造の選択であって、善悪ではない）
