# 顧客データの分析

**「顧客を分析する」で最も多い失敗は、平均を見ることである。**

平均客単価・平均滞在時間・平均継続月数。**平均は、実在しない中央の人物を作り出す。**
売上の大半を作っている少数と、一度きりで去った多数が混ざって、**どちらの姿も見えなくなる。**

**分析の第一歩は、分けること。**

> **前提**: 個人データを扱う。分析の前に **PII を持ち込まない**設計にする
> （→ `privacy-auditor` の監査。GA4 に個人を特定できる値を送らない → `skills/ga4-jp`）。
> **分析に不要な個人情報は、取得の時点で落とす。**

## 0. 手法の選び方（何を決めたいかで決まる）

| 決めたいこと | 手法 |
|---|---|
| **誰に力を入れるか** | RFM／デシル／ABC（§1） |
| **時期による違いがあるか** | コホート分析（§2） |
| **どこで落ちているか** | ファネル分析（§3） |
| **何がきっかけで動くか** | カスタマージャーニー（§4） |
| **なぜ買われたのか** | JTBD＝用事の分析（§5） |
| **どの接点が効いたか** | アトリビューション（§6） |

**手法から入らない。** 「RFM をやりましょう」ではなく「**誰に力を入れるかを決めたい**」から入る。

## 1. 分ける — RFM・デシル・ABC

### RFM

顧客を3軸で分ける: **R**（最終購入からの日数）／**F**（購入回数）／**M**（購入金額）。

| 組合せ | 状態 | 打ち手 |
|---|---|---|
| R高 F高 M高 | 優良 | **紹介・事例を依頼する最有力**（→ `skills/referral-advocacy-jp`） |
| R低 F高 M高 | **離反しかけの優良** | **最優先。ここが最も取り戻しやすい** |
| R高 F低 | 新規・お試し | 定着の節目まで運ぶ（→ `/リテンション`） |
| R低 F低 | 休眠 | 理由を聞く（→ `/顧客の声`）。無理に掘り起こさない |

**R（最終購入からの日数）が最も打ち手に近い。** 金額の大きい顧客より、
**離れかけている優良顧客**のほうが、戻ってもらえる確率が高い。

**BtoB や高単価・低頻度の商材では F がほぼ全員1になる。** そのときは RFM を使わない
（**手法が合わないことに気づかず F=1 の山を眺めるのが典型的な失敗**）。

### デシル・ABC

- **デシル**: 売上順に10等分。**上位2割が売上の何割か**を出す
- **ABC**: 累積構成比で A/B/C に分ける。商品にも顧客にも使える

**目的は「集中先を決めること」。** 出した後に必ず「**だから何に時間を使うか**」を書く。

**上位に集中すると決めたなら、下位を切ることも同時に決める**（→ `docs/parts/capacity-plan.md`）。

## 2. コホート分析 — 「今月の継続率」は読めない

**入ってきた時期ごとに分けて、経過期間で並べる。**

そうしないと、**新規が増えた月に継続率が下がったように見える**（分母が変わっただけ）。

| 見るもの | 読み方 |
|---|---|
| **横に読む**（同じコホートの推移） | 何ヶ月目で落ちるか＝**定着の節目**がどこか |
| **縦に読む**（同じ経過月数を時期で比較） | 施策や商品改善が効いたか。**新しいコホートほど良ければ改善している** |
| **落ちるタイミングが一定** | 構造的な理由がある（利用の壁・契約更新月） |

**必ず母数を併記する。** 「継続率80%」は、母数5人なら4人のこと。

**縦読みが、施策の効果を見る唯一の実用的な方法**であることが多い
（A/Bテストの母数が足りない領域では特に → `skills/cro-jp`）。

## 3. ファネル分析 — どこで落ちているか

**認知 → 流入 → 検討 → 転換 → 定着 → 継続 → 推奨**。段階ごとに人数と通過率を出す。

- **絶対数と通過率の両方を見る**（通過率が良くても母数が小さければ効かない）
- **最も落ちている段階ではなく、「改善しやすさ × 影響」で選ぶ**
- **段階の定義を先に固定する**（後から変えると過去と比較できない → `docs/parts/pre-setup-council.md`）
- **落ちた人の理由はデータに出ない。** 数字で場所を特定し、**理由は `/顧客の声` で聞く**

**「ボトルネックを直す」だけを繰り返すと、天井が来る。**
全段階が平均的に良くなった後は、**流入の質**（誰を連れてきているか → `skills/stp-jp`）を疑う。

## 4. カスタマージャーニー — 推測で作らない

**多くのジャーニーマップは、作った人の想像である。** それでは使えない。

| 列 | 埋め方 | 出典 |
|---|---|---|
| 段階 | 認知〜推奨 | ファネル（§3） |
| **行動** | 実際にやったこと | GA4・GSC・購買データ |
| **接点** | どこで触れたか | 参照元・「どこで知ったか」の設問 |
| **思っていたこと** | **顧客の言葉のまま** | `/顧客の声`（→ `skills/voc-research-jp`） |
| **不安・つまずき** | 具体的に | 問い合わせ・レビュー・離脱ページ |
| 自社の打ち手 | 誰が何をするか | 各パック |

**「思っていたこと」を推測で埋めない。** ここが推測なら、
**マップ全体が推測**になる。埋まらないなら `/顧客の声` を先に回す。

**BtoB では「決裁の関門」を必ず入れる**（使う人と決める人が違う。上司の説得材料が要る
→ `skills/sales-writing`）。

## 5. JTBD（用事）— 「なぜ買われたのか」を構造で捉える

**顧客は商品を買っているのではなく、片付けたい用事のために雇っている。**

```
〈状況〉のとき、〈したいこと〉したい。
なぜなら〈理由〉だから。
そのために今は〈今使っている代替手段〉を使っている。
```

**最後の1行が最も重要。** 競合は同業他社ではなく、
**顧客が今その用事に使っている手段**（Excel・人手・我慢・何もしない）であることが多い。

**「何もしない」が最大の競合であることは非常に多い。**
そのときの打ち手は比較優位の主張ではなく、**動く理由を作ること**。

**聞き方は `/顧客の声`**（過去と行動を聞く。「あったら使いますか」は聞かない）。

## 6. アトリビューション — 「どの接点が効いたか」は簡単には分からない

| モデル | 何を見るか | 注意 |
|---|---|---|
| ラストクリック | 最後の接点 | **指名検索が全部の手柄を取る**。オーガニックでは特に歪む |
| ファーストクリック | 最初の接点 | 検討が長いと最初が古すぎる |
| 線形・時間減衰 | 全接点に配分 | 配分の根拠は仮定 |

**どのモデルも「仮定」である。** モデルを変えれば結論が変わる。

**オーガニック運用での現実的な扱い**:

- **参照元は落ちる**（ダークソーシャル・アプリ内ブラウザ・メール）。**絶対値を信じない**
- **申込時に「どこで知ったか」を1問だけ聞く**のが最も安く確実（→ `skills/cro-jp` と摩擦を相談）
- **接点ごとの貢献を厳密に配分しようとしない。**
  代わりに「**この施策を止めたら何が落ちるか**」で考える（→ `skills/hypothesis-design-jp`）

## 7. 分析結果を「打ち手」に変える

**どの手法でも、出力の最後は同じ形にする。**

```
分かったこと: 〈数字。**母数と期間を併記**〉
それはなぜか: 〈推論だと明記。データは「何が起きたか」しか語らない〉
確かめること: 〈/顧客の声 で聞く・別の切り口で見る〉
だから何をするか: 〈誰が・いつ・何を〉
外れたと分かる条件: 〈→ skills/hypothesis-design-jp〉
```

**「分析しました」で終わる報告を出さない。**

## 8. よくある失敗

- **平均を見る**（実在しない中央の人物を作る）
- **手法から入る**（何を決めたいかを先に言う）
- **母数を書かない**（「継続率80%」が5人中4人のことがある）
- **今月の継続率を単体で読む**（コホートに分けないと分母の変化と区別できない）
- **BtoB・低頻度商材に RFM を当てる**（F がほぼ全員1になる）
- **ファネルの定義を途中で変える**（過去と比較できなくなる）
- **ジャーニーの「思っていたこと」を推測で埋める**（マップ全体が推測になる）
- **競合を同業他社の中だけで探す**（用事の水準で見ると「何もしない」が最大の競合）
- **アトリビューションのモデルを真実だと思う**（どれも仮定）
- **参照元の絶対値を信じる**（オーガニックでは必ず落ちる）
- **分析して終わる**（打ち手と反証条件まで書いて完了）
- **個人情報を分析用に持ち込む**（取得の時点で落とす）

## 出典

**【一次情報・入手先】**

- **自社の行動・購買データ**: GA4／Search Console（→ `skills/ga4-jp`・`skills/search-console-jp`）。
  **GA4 の数値は推定値でありしきい値で行が消える**ため、**絶対値ではなく比率と推移で読む**
- **顧客の言葉・状況・代替手段**: `/顧客の声`（→ `skills/voc-research-jp`）
- **個人データの扱い**: `privacy-auditor`（PII を GA4 に送らない・分析に不要な個人情報は取得時に落とす）

**【未確認】**

- **RFM・デシル・ABC・コホート・ファネル・JTBD・アトリビューションは、実務で広く使われる分析手法**である。
  本スキルは**特定の書籍・論文の記述を引用しておらず**、ゼロ広告費のオーガニック運用で使う形に再構成している
- **§1 の RFM の打ち手の対応（「離反しかけの優良が最も取り戻しやすい」等）は実務上の整理**であり、
  実証された効果量ではない。**自社のコホートで確かめること**（§2 の縦読みがその手順）
- **「何もしない が最大の競合であることが多い」は経験則**。自社の `/顧客の声` で確かめること
